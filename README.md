# Рядом

**Найди компанию для спорта рядом с домом.**

«Рядом» помогает людям встречаться и заниматься спортом вместе: выйти на
пробежку, сыграть в футбол или шахматы, присоединиться к зарядке в парке.
Можно найти встречу по интересам или организовать свою — от личного профиля
или сообщества.

Сервис рассчитан на людей с разным опытом, в том числе на тех, кто только
начинает заниматься спортом. Особое внимание — понятному первому шагу и людям
старшего поколения: где встретиться, что взять с собой и к кому обратиться.

## Что можно делать

- **Находить встречи** по виду спорта, городу, датам и способу записи.
  В карточке указаны место, организатор, условия и время с часовой зоной.
- **Присоединяться сразу или по заявке.** При свободной записи участие
  подтверждается сразу; заявку рассматривает организатор. Ближайшие
  подтверждённые встречи доступны на персональной главной и в «Моих встречах».
- **Задавать вопросы** и получать ответы в обсуждении встречи до записи.
- **Создавать свои встречи.** Помощник первой встречи помогает описать темп,
  подготовку, инвентарь и знакомство с организатором.
- **Организовывать занятия от сообщества.** После допуска администратором
  организация получает публичную страницу и может публиковать встречи.
- **Приглашать людей офлайн.** Печатное приглашение содержит условия, место,
  время и QR-код со ссылкой на встречу. Оно не заменяет запись на сайте.
- **Оформлять профиль и встречи.** Доступны семь готовых аватаров, собственный
  SVG-аватар с модерацией и SVG-фон встречи. Максимальный размер файла — 128 КиБ.

Администратор рассматривает организации и новые спортивные направления,
обрабатывает жалобы на встречи и сообщения, скрывает и восстанавливает сообщения,
снимает встречи с публикации с указанием причины и блокирует аккаунты.
Снятая встреча недоступна для новой записи; существующие записи сохраняются.

## Попробовать демонстрацию

После запуска откройте главную страницу приложения, затем **«Демоаккаунты»**
внизу страницы или адрес `/demo`. Там есть описания профилей и скачиваемый
список доступов `/demo/accounts.txt`. В форме входа можно подставить данные
нужного профиля, после чего нажать «Войти».

| Профиль | Email | Пароль | Что попробовать |
| --- | --- | --- | --- |
| Алексей | `alex@example.test` | `Ryadom-Alex-2026!` | Поиск, запись, вопросы и личные планы |
| Анна | `anna@example.test` | `Ryadom-Anna-2026!` | Создание встреч и работа с организациями |
| Марина | `marina@example.test` | `Ryadom-Marina-2026!` | Допуск организаций и модерация |

Все демонстрационные аккаунты и данные вымышлены. Вход проверяет пароль на
сервере, а действия сохраняются в базе данных. Для одновременного просмотра
разных ролей используйте отдельные профили браузера или приватное окно.

Удобный маршрут знакомства: войти Алексеем, открыть ближайшую встречу и
записаться; затем войти Анной в другом окне и посмотреть состав участников.
Для встречи по заявке организатор может принять или отклонить запись.

В деморежиме Марина может восстановить исходный набор данных из своего профиля.
Это действие требует подтверждения, удаляет изменения пользователей и завершает
все сессии. Обычный перезапуск приложения данные не сбрасывает.

## Запуск

Для сборки и запуска нужны **Docker и Docker Compose**. Go, Node.js и PostgreSQL
на машине отдельно устанавливать не требуется.

**Для выделенного сервера:** [пошаговая инструкция Ubuntu 24.04.5 LTS](docs/deployment/ubuntu-24.04.md).
Она описывает доступ по IP на порту 80, настройки, первый запуск, обновления
и резервное копирование.

**Для локального просмотра:** из корня репозитория скопируйте настройки:

```bash
cp .env.example .env
```

В `.env` заполните `POSTGRES_PASSWORD` случайной hex-строкой из 32 байт,
`AUTH_JWT_SECRET` — другим случайным ключом из 32 байт в base64. Например,
их можно получить командами `openssl rand -hex 32` и `openssl rand -base64 32`.
Сохраните исходное выражение `DATABASE_URL`: Compose подставит пароль сам.
Для страницы демоаккаунтов установите `WEB_DEMO_ACCESS=true` перед сборкой.
Остальные локальные настройки оставьте из примера.

```bash
docker compose config --quiet
docker compose build migrate api seed web
docker compose up -d --wait web
# Только для первоначального наполнения новой БД:
docker compose run --rm --no-deps seed
```

Приложение откроется по адресу **[http://127.0.0.1:8080](http://127.0.0.1:8080)**.
Миграции применяются до запуска API; демонстрационные данные загружаются
отдельной командой. Для обычных обновлений не удаляйте том PostgreSQL,
сохраняйте `.env` и не запускайте сброс.

Доступ по сетевому IP через HTTP включается явно для демостенда по серверной
инструкции. В этом режиме пароли и сессии передаются без шифрования;
для настоящих пользовательских данных нужен HTTPS.

## Технологии

| Часть | Решение |
| --- | --- |
| Веб-интерфейс | React, TypeScript, Vite, React Router, TanStack Query |
| Сервер | Go, chi, pgx, sqlc |
| База данных | PostgreSQL, миграции goose |
| Вход | Email и пароль, Argon2id, JWT в HttpOnly-cookie, серверный отзыв сессий |
| Поставка | Docker Compose, Nginx, постоянный том PostgreSQL |
| Документация API | Единый OpenAPI для Go и TypeScript, локальный Swagger UI |

Аватары и фоны хранятся в PostgreSQL после серверной проверки SVG; внешнее
хранилище не требуется. QR-коды создаются локально, без стороннего сервиса.
Для работы основных сценариев не нужны внешние API или платные ключи.
Первоначальная сборка скачивает образы и зависимости из интернета.

На том же адресе, что и приложение, доступны **`/api/docs`** — Swagger UI
в режиме просмотра и **`/api/openapi.yaml`** — схема API.

## Формат и ограничения

Это адаптивный веб-прототип, подготовленный по кейсу Столото. Он работает
в браузере на компьютере и телефоне; отдельного мобильного приложения нет.
Подтверждение почты, восстановление пароля, платежи, бронирование площадок
и подтверждение фактического посещения в текущую версию не входят.

Ядро прошло проверку пользовательских и административных сценариев. Для
финальной сборки выполнены сборки контейнеров и адресные проверки новых функций;
полный повтор всех тестов не проводился. Доступность с внешнего компьютера
проверяется после развёртывания на сервере.
