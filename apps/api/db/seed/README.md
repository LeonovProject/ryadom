Реализовано 20 октября 2026 после проверенных DB-01/AUTH-01, в отдельном worktree
бэкенда `codex/be-01-foundation` от `ab6b105`. Область этой карточки — только
`apps/api/db/seed/**`. Миграции, общие зависимости, OpenAPI 0.13.0 и фронтенд
не менялись. Версия набора: **2026-10-20.1**.

## Что поставляется

- [Набор данных](dataset.go) и [вставка](insert.go): новые случайные UUID,
  свежие Argon2id-хеши через AUTH-01, относительные даты Asia/Krasnoyarsk.
- [Транзакционное наполнение](seed.go): один набор для обычного явного seed
  и последующего переиспользования BE-12, без удаления/сброса в этом пакете.
- [Явная CLI-команда](cmd/seed/main.go): читает DATABASE_URL и общий manifest
  аватаров, проверяет готовность схемы 2026102001 и подтверждает результат после commit.
- [Проверки PostgreSQL](seed_integration_test.go) с настоящими миграциями,
  [проверки набора](dataset_test.go), CLI и [изолированная среда](testdata/compose.yaml).

Обычный запуск API seed не вызывает. Пакет не запускает миграции, не создаёт
JWT/сессии и не меняет demo_state, включая generation и последнюю квитанцию.
SVG-фоны/личные CUSTOM SVG отсутствуют: их добавление требует MEDIA-00/01B.
PRESET берётся из уже существующего общего manifest, без вымышленных ID/картинок.

## Назначение контрольных встреч

- «Пробежка для знакомства» — OPEN, «Футбол во дворе» — APPROVAL от допущенной
  организации. Алексей ещё не записан ни на одну: эксперт может пройти обе
  ветки самостоятельно. У футбола уже есть две разные PENDING-заявки Ивана и Дарьи.
- «Шахматы в парке» — опубликованная встреча Анны для обсуждения/модерации:
  отдельная прямая OPEN-жалоба и OPEN-жалоба на сообщение, свежая цель для новой
  жалобы, скрытое и восстановленное сообщения с версиями/датами.
- «Зарядка у фонтана» — опубликована от заблокированного Бориса, содержание
  и участие другого человека сохранены. Блокировка автора не становится снятием.
- У Алексея четыре будущих CONFIRMED/PUBLISHED: ближняя встреча имеет старую
  запись, дальняя — новую. Ещё две встречи начинаются в один момент для проверки
  порядка startsAt/event.id. Нельзя подменять его порядком создания участия.
- Отдельно сохранены начавшаяся сегодня в 00:00 **по зоне встречи** и вчерашняя,
  ожидающая и отклонённая заявки, снятая встреча с CONFIRMED. Только сегодняшняя
  входит в STARTED_TODAY; PENDING/REJECTED/UNPUBLISHED не входят в будущие планы.
- Пользовательские PENDING/REJECTED направления уже используются опубликованными
  встречами. Подготовлены две независимые PENDING-цели для обеих веток справочника.
- У снятой встречи обязательная причина, сохранённое участие и закрытая прямая
  жалоба. Отказ организации имеет причину, отказ участнику отдельной причины не требует.

Базовая дата определяется после ожидания транзакционного барьера, по текущему
времени Asia/Krasnoyarsk. Основные встречи лежат в будущих днях; даты статусов
и сообщений согласованы. У новых полных наполнений UUID/соли новые, demo_key,
email и демонстрационные пароли стабильны.

## Явный первоначальный запуск

После применения DB-01 и настройки DATABASE_URL, из корня репозитория:

```bash
go -C apps/api run ./db/seed/cmd/seed -presets ../../packages/contracts/avatar-presets.json
```

Нужен закреплённый Go 1.27.2. Путь относится к рабочему каталогу apps/api после
`go -C`. В продуктовой поставке OPS-01 подключает отдельную явную seed-команду
и этот же manifest; запуск API самостоятельно ничего не наполняет.

Команда не применяет миграции. Пустая/неполная схема сначала должна пройти
goose up, ожидаемая версия — 2026102001. Неверная конфигурация/каталог/ошибка
БД не выдаёт сообщение об успешной загрузке. Секрет соединения и PHC не печатаются.

При непустой БД и наличии всех шести пар demo_key/email команда делает no-op:
сохраняет текущие статусы, решения, даты, сессии и новые пользовательские строки.
Эти маркеры означают лишь отказ от перезаписи, не проверку полноты/версии
существующего набора. Частичная либо чужая непустая БД без маркеров отклоняется
без дополнения или исправления данных. Автоматических повторов/DELETE нет.

CLI выбирает готовый ID из того же manifest для **подготовленных** демоаккаунтов.
При пустом manifest они создаются с NONE/EMPTY: их известный пароль остаётся
пригодным для будущего входа. Это не обход обязательного presetId новой регистрации.
CLI не реализует второй runtime-каталог API; его общий читатель принадлежит BE-02.
Проверка реальных SVG/доставка веб-ресурсов остаются за MEDIA-00/01F.

## Переиспользование BE-12

`Initialize(ctx, db, Options)` начинает READ COMMITTED и делает один commit.
`Apply(ctx, tx, Options)` использует **переданную** pgx.Tx и не делает commit,
rollback, удалений или изменений квитанции. При ошибке вызывающий обязан откатить tx.

Первый предметный запрос Apply — demo_state FOR SHARE. После него advisory
transaction lock сериализует два обычных initial seed одного schema; дальнейшие
чтения READ COMMITTED видят результат первого. Параллельный reset удерживает
свой эксклюзивный demo_state, поэтому seed ждёт его до выбора даты/чтения данных.

BE-12 в своей транзакции сначала получает FOR UPDATE-барьер, проверяет
DEMO_MODE/Origin/ADMIN/generation/версию/подтверждение, сам удаляет предметные
строки в согласованном FK-порядке, затем вызывает этот Apply на пустых таблицах.
Повторный FOR SHARE не снимает уже удерживаемый эксклюзивный замок. После
наполнения BE-12 сам сохраняет новую generation/квитанцию и выполняет commit.
Это интерфейс для будущего reset, а не уже работающий административный сброс.

## Проверка

Из корня worktree, отдельный проект `ryadom-db02` с временной PostgreSQL,
без опубликованных портов и без постоянного тома:

```bash
docker build --network=host -f apps/api/db/seed/testdata/Dockerfile -t ryadom-db02-go-check .
docker compose -p ryadom-db02 -f compose.foundation.yaml -f apps/api/db/migrations/testdata/compose.yaml -f apps/api/db/seed/testdata/compose.yaml up -d --wait db
docker compose -p ryadom-db02 -f compose.foundation.yaml -f apps/api/db/migrations/testdata/compose.yaml -f apps/api/db/seed/testdata/compose.yaml run --rm --no-deps go-check go test -race -count=1 ./...
docker compose -p ryadom-db02 -f compose.foundation.yaml -f apps/api/db/migrations/testdata/compose.yaml -f apps/api/db/seed/testdata/compose.yaml down
```

Сеть хоста используется только при сборке из-за DNS стандартной сети сборки
этой среды; тестовые контейнеры работают в выделенной Compose-сети.
Новые зависимости не добавлялись; Go/PostgreSQL/goose закреплены прежней основой.

Весь контейнерный Go-набор с race detector прошёл, включая DB-01/AUTH-01/BE-01.
DB-02 выполнена без SKIP: реальные goose-миграции в случайных схемах, состав/
связи набора, хеши доступов, относительные даты/локальная полночь, SQL-окна личных
планов, оба режима/состояния. Проверены явная CLI-команда и её повтор, сохранение
изменений/новой регистрации/сессии/квитанции, отказ на чужой непустой БД,
откат после принудительной ошибки при вставке reports, два одновременных seed,
ожидание общего барьера, пустой каталог и повторное использование общей tx.
В тестовой случайной схеме внешняя транзакция удаляла только свои фикстуры,
наполнялась заново и откатывалась/фиксировалась; исходный набор/сессия возвращались
после rollback, новый набор имел свежие UUID и ноль sessions после commit.

Нужна RYADOM_SEED_TEST_DATABASE_URL для живых SQL-проверок; overlay задаёт её.
Без переменной локальный go test явно пропускает SQL-группу. Реального сброса
общей БД или обращения к пользовательскому серверу не было.

Также прошли локальные go test -race, go vet, check_repository.py,
check_handoff.py, git diff --check и проверка новых файлов.

## Передача

Координатору переданы seed.Version, Initialize/Apply и отдельная CLI-команда.
OPS-01 ещё должен связать API/миграции/веб/proxy и проверить постоянный том.
BE-02 после закрытия зависимостей подключает login/register/logout/getMe и guard;
готовые записи в PostgreSQL не объявляются работающими пользовательскими сценариями.
MEDIA-00/01F и итоговая продуктовая приёмка также остаются впереди.

Общие статусы очереди/CONTEXT/manifest обновляет координатор по этому отчёту.
Коммит, push и развёртывание не выполнялись.
