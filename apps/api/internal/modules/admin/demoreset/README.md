# BE-12 и передача BE-P3

База пакета — интеграционный c7c04b1, ветка codex/be-03-event-reads.
BE-10 сохранена ff18678, BE-11 — 56c3f81, BE-12 — коммит с этим отчётом.
Выполнены последовательно, без reset и промежуточного объединения.

## Реализация

BE-10: четыре административные операции направлений, единая с публикацией
нормализация NFC/пробелов/регистра, expectedName, атомарное исправление с
одобрением, причины отказа, безопасные повторы, UNIQUE-коллизии и счётчики встреч.

BE-11: подача жалоб на обе цели, квитанции и закрытые повторы, ADMIN-чтение
оригинала сообщения, восстановление и разбор двух независимых групп жалоб.
Скрытие/снятие переиспользуют BE-08/09; версии защищают новые жалобы и решения.
Восстановление сохраняет историю/текст/ID/порядок, не восстанавливает публикацию.

BE-12: adminGetDemoState/adminResetDemoData. DEMO_MODE по умолчанию false;
выключенные маршруты возвращают 404 до проверки тела/сессии, без обращения к БД.
Включённый режим требует ADMIN/Origin/точного слова СБРОСИТЬ, свежих generation
и seedVersion, нового resetId. Runner берёт общий FOR UPDATE с ожиданием до 5 s,
затем заново проверяет сессию/ADMIN. Удаление десяти таблиц идёт фиксированным
порядком FK обычными DELETE; единый seed.Apply вставляет свежие UUID и соли.
Схема, миграции, manifest и demo_state сохраняются. Все сессии удаляются.
Новая generation и квитанция сохраняются тем же commit; ошибка откатывает всё.
Очистка cookie и успешный ответ уходят только после COMMIT. Ответ квитанции
читается из сохранённой строки PostgreSQL, включая точность даты/времени,
и совпадает с lastReset после нового входа. Повтор не сбрасывает новую базу.

Пользователь отдельно разрешил единственную общую правку:
`DEMO_MODE: ${DEMO_MODE:-false}` в окружении api в compose.yaml. Ни включение
режима в общей среде, ни реальный сброс общей БД не выполнялись. Для включения
в собственной поставке задаётся DEMO_MODE=true и пересоздаётся api. Это само
по себе не запускает reset или обычный seed.

## Интегратору

Принять три последовательных коммита. Основные изменения: модули
activitytypes/review, reports, discussion/restore, admin/demoreset, SQL/sqlc,
main.go, обработка выключенных операций HTTP, DEMO_MODE в config/Compose.
Очередь, manifest и корневые отчёты остаются у координатора и здесь не менялись.
Проверить затронутые подключения и совместный фронтенд. Общий go test ./...,
контрактный валидатор/Go/TS-генерация, совместные FE-P3/FE-14 и QA/DELIVERY
оставлены интегратору. Новые интерфейсы этим серверным пакетом не объявляются
готовыми. BE-13 и MEDIA находятся вне назначенного BE-P3.

Воспроизведение: собрать api/web с тегами ryadom-bep3-api/ryadom-bep3-web,
предоставить совместимые ryadom-bep3-migrate/ryadom-bep3-seed, затем:

```bash
python3 apps/api/internal/modules/admin/demoreset/testdata/http_accept.py --source "$PWD"
```

SQL-тесты в прежней изолированной Compose-среде из отчёта organizations:
`go test -race -count=1 -run '^TestP3' ./internal/modules/events`.
Нужен RYADOM_EVENTS_TEST_DATABASE_URL; без него тесты пропускаются.
Скрипты не используют общий preview. Push, внешний сервер и сообщения другим
чатам не выполнялись; временные тестовые проекты/тома удаляются их скриптами.
