# BE-08 — обсуждение и скрытие сообщения

Продолжение от BE-07 `c81b00b` (общая интеграционная база `a976427`) в
`codex/be-03-event-reads`. Подключены `listMessages`, `createMessage`,
`adminListMessages`, `adminHideMessage` в штатном API.

Обсуждение открыто у PUBLISHED независимо от участия и начала встречи. Авторство
и принадлежность организатору определяет сервер. Снятая встреча закрывает
публичное чтение; добавление после ожидания блокировки повторно проверяет статус.
Текст обычный, до 4000 символов; свободные края нормализуются, пустой текст/NUL
и подстановка служебных полей отвергаются. Автоматического повтора POST нет.

HIDDEN возвращается публично без body даже автору/ADMIN; SQL публичного списка
также не выбирает оригинал скрытого текста. ADMIN отдельно получает оригинал,
реальные счётчики OPEN и обе версии. Пагинация: публичный default OLDEST_FIRST
(ASC), NEWEST_FIRST (DESC), административный список ASC. Подписанный курсор
связан с маршрутом, встречей, направлением, hasOpenReports и аккаунтом ADMIN;
фильтр применяется до LIMIT.

Скрытие использует event → message, проверяет expectedRevision и увеличивает
moderationRevision. Уже HIDDEN — безопасный повтор без переписывания дат.
В той же транзакции закрываются только OPEN-жалобы данного сообщения и при
непустом закрытии увеличивается reportsRevision; история восстановления
сохраняется. Ответ отправляется только после успешного COMMIT.
`ResolveOpenMessageReports` в queries/messages.sql — общая операция закрытия
для дальнейшей BE-11; второй версии правил модерации нет.

## Интегратору

Общий `go test ./...`, контрактный валидатор/генерация Go/TS и совместный
браузерный проход оставлены интегратору. Проверки HTTP описывают серверный
S5/A3, не готовность интерфейса FE-10. Восстановление/подача жалоб и
adminGetMessage относятся к BE-11 и здесь не регистрируются. BE-09 не закрыта.
Общий preview/БД и пользовательский сервер не затрагивались; push не выполнялся.

Для воспроизведения собрать API target корневого Dockerfile с тегом
`ryadom-be08-api`; предоставить совместимые web/migrate/seed с тем же префиксом:

```bash
python3 apps/api/internal/modules/discussion/testdata/http_accept.py --source "$PWD"
```

SQL-тесты используют существующие overlays из отчёта
`../organizations/README.md`, переменную `RYADOM_EVENTS_TEST_DATABASE_URL` и
адресную команду выше. Без переменной тесты пропускаются, что не доказывает
предметную приёмку. Каждая проверка создаёт и удаляет отдельную схему БД.
