# BE-07 — запись и решения по участию

Продолжение от интеграционного `a9764275479f04cf4e40716c197bb5776178728c`
в `codex/be-03-event-reads`; существующая работа сохранена без reset.
Реализована отдельная BE-07. BE-08/09 этим результатом не закрыты.

Подключены `joinEvent`, `decideParticipation`, `listMyParticipations` и
`listEventParticipations` в штатном `cmd/api/main.go`.
OPEN создаёт CONFIRMED, APPROVAL — PENDING. Повтор возвращает прежнюю запись,
включая REJECTED. Решения доступны ответственному автору; ADMIN без авторства
не получает эти права. Одинаковое решение сохраняет прежние даты, противоположное
даёт конфликт. Состояние публикации и актуальное время проверяются после
предметных блокировок, до успешных повторов; ответ публикуется после COMMIT.

Личные списки поддерживают три временных окна, общий referenceTime и подписанные
курсоры, связанные с актёром/фильтрами/направлением. Фильтрация и сортировка
выполняются в SQL до LIMIT. STARTED_TODAY использует зону встречи; снятая встреча
в полном списке ограничена тремя полями. Наносекундная точность referenceTime
сохраняется в ответе/курсоре, сравнение с PostgreSQL учитывает микросекунды.

Изменения вне нового модуля: запросы/sqlc участия, проверка event-owner по
participationId и текущему владельцу организации, повторное использование
канонического EventSummary, регистрация обработчиков. OpenAPI 0.13.0, общие DTO,
миграции, зависимости, Compose и фронтенд не менялись.

## Воспроизведение

После сборки образов из проверяемой ветки:

```bash
python3 apps/api/internal/modules/participation/testdata/http_accept.py --source "$PWD"
```

Нужны локальные Docker Compose/OpenSSL. Образы API/migrate/seed собираются
соответствующими target корневого Dockerfile; web — `infra/web/Dockerfile`,
с именами `ryadom-be07-api`, `ryadom-be07-migrate`, `ryadom-be07-seed`,
`ryadom-be07-web`. Скрипт не собирает их автоматически.

Для SQL-тестов применяется существующая среда из отчёта BE-P1
(`organizations/README.md`), с командой адресного набора выше. Переменная
`RYADOM_EVENTS_TEST_DATABASE_URL` задаёт отдельную тестовую БД; каждый тест
создаёт свою схему и удаляет её после завершения. Без переменной SQL-тесты
пропускаются, что не считается успешной предметной приёмкой.
