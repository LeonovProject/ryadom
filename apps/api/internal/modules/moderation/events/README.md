# BE-09 — поиск и снятие встреч

Продолжение от BE-08 `1a00a81` в `codex/be-03-event-reads`, общая база `a976427`.
Подключены `adminListEvents`, `adminGetEvent`, `adminUnpublishEvent`.
Модерационная обвязка вызывает единственные операции доменного модуля events.

ADMIN получает полные сведения, автора создания и актуального организатора,
реальные счётчики OPEN на встречу/сообщения и eventReportsRevision. Само наличие
роли ADMIN не даёт управления чужими участниками. Поиск: нормализованная
подстрока названия/описания/направления без wildcard, publicationStatus,
organizationId, activityTypeId любого статуса справочника, hasOpenReports по
обеим группам жалоб. Фильтры применяются до LIMIT; порядок createdAt/id DESC.
Подписанный курсор связан с аккаунтом, всеми фильтрами и маршрутом.

Unpublish берёт тот же FOR UPDATE события, что запись/решение/сообщение.
Обязательная причина нормализуется по краям. Первый переход атомарно снимает
публикацию и закрывает только прямые OPEN-жалобы как RESOLVED; при непустом
закрытии reportsRevision увеличивается на один. Сообщения, их жалобы, участия,
фон и организация не меняются. Та же причина — безопасный повтор без новых
дат; другая — DECISION_CONFLICT. Успешный ответ отправляется только после COMMIT.
SQL `ResolveOpenEventReports` предназначен для повторного использования BE-11.

После снятия каталог/публичное обсуждение недоступны. Чужая прямая ссылка — 404;
автор, ADMIN и сохранённый участник читают ограниченную карточку. Причина видна
автору/ADMIN; полный список участия сохраняет запись с тремя полями встречи.
Новая запись, сообщение и решение закрыты актуальным состоянием под блокировкой.
Автор сохраняет чтение состава; PENDING автоматически не меняется.

## Передача интегратору

В этой ветке последовательно сохранены BE-07 `c81b00b`, BE-08 `1a00a81` и
данный коммит BE-09. Переносить без reset. Общие статусы/manifest/CONTEXT здесь
не редактировались, push и сообщения в другие чаты не выполнялись.

Интегратору остаются общий go test ./..., контрактный валидатор/Go/TS-генерация,
совместные интерфейсные S3–S6/A2/A3 и DELIVERY. Серверный HTTPS-проход не
объявляет готовыми новые экраны фронтенда. Изменение фона пока не реализовано
(MEDIA-01): его запрет после снятия требует проверки при подключении MEDIA,
с тем же замком события и проверкой PUBLISHED после ожидания. Восстановление
публикации не добавлено; дальнейшие операции жалоб — BE-11.

Для воспроизведения собрать API target корневого Dockerfile с тегом
`ryadom-be09-api`, предоставить совместимые web/migrate/seed с тем же префиксом:

```bash
python3 apps/api/internal/modules/moderation/events/testdata/http_accept.py --source "$PWD"
```

SQL-проверки используют существующую Compose-среду из
`../../organizations/README.md` и RYADOM_EVENTS_TEST_DATABASE_URL; команда:
`go test -race -count=1 -run 'TestAdminEvent|TestUnpublish' ./internal/modules/events ./internal/modules/moderation/events`.
Каждый тест создаёт отдельную схему; без переменной он пропускается.
