# BE-05 — профили организаций и подача

Пакет BE-P1, база BE-04 c74dfcd. Реализованы createOrganization,
listMyOrganizations, getMyOrganization, getOrganization, submitOrganization.
Модуль самостоятельно подключён в cmd/api/main.go.

Профиль создаётся частным, владелец — из сессии, application=null и
NOT_SUBMITTED. Публично только APPROVED; до допуска — 404 даже владельцу.
Приватный кабинет и подача только владельцу, ADMIN без владения — 404.
Повтор подачи возвращает ту же заявку 200, включая REJECTED/APPROVED, без
перезаписи дат/решения. Первая подача 201. Замок организации сериализует подачу.
PrivateOrganization содержит полный договорённый DTO, application nullable;
публичный ответ только шесть допустимых полей и текущий ownerIsBlocked.
Блокировка владельца не скрывает APPROVED, но guard запрещает его мутации.
Личный список: createdAt/id DESC, подписанный курсор аккаунта/маршрута,
последняя полная страница без ложного продолжения, limit можно менять.

Файлы: organizations/**, SQL organizations.sql/organization_applications.sql,
соответствующая sqlc-генерация и cmd/api/main.go. Общие DTO/OpenAPI 0.13.0,
миграции, зависимости, контейнеры и фронтенд не менялись.

Проверки перед коммитом: отдельный Compose с PostgreSQL/goose и реальными
JWT/guard, `go test -race -count=1 -v ./internal/modules/organizations` — PASS
(6.987s). Создание/trim, приватность всех состояний, публичность APPROVED,
сохранённый отказ и canPublish, отсутствие ADMIN-владения, BLOCKED,
курсор/сортировка/пустота, две одновременные подачи (201/200, один ID),
откат отложенного сбоя COMMIT, свежая сессия после ожидания барьера.
Канонические OpenAPI-схемы проверяют ответы. PASS: go vet ./...,
check_repository.py, check_handoff.py (48 карточек/3 пакета), git diff --check.
