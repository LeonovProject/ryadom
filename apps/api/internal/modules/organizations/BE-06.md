# BE-06 — допуск организаций и административный поиск

Пакет BE-P1, предыдущая карточка BE-05 7754d7d. Реализованы и подключены
adminListOrganizations, adminGetOrganization, adminDecideOrganization.
Маршруты предоставляет moderation/organizations, единственная операция решения
и DTO принадлежат organizations; независимой копии правил допуска нет.

Список включает NOT_SUBMITTED, PENDING, APPROVED, REJECTED. q ищет буквальную
подстроку названия/деятельности/интересов после нормализации пробелов/регистра,
без wildcard-семантики. Фильтры до LIMIT, createdAt/id ASC. Подписанный курсор
привязан к маршруту/аккаунту/нормализованным фильтрам, limit может меняться.
ADMIN видит частные данные, но canSubmit/canPublish не получает без владения.

APPROVE не принимает reason, REJECT требует непустую причину до 2000 символов.
Организация блокируется перед заявкой, как в подаче/публикации. После ожидания
читается текущее решение: одинаковый повтор возвращает прежние дату/reviewer,
другое решение/причина даёт DECISION_CONFLICT. Новый результат меняет одну заявку
в общей транзакции; сообщение об успехе выдаётся после commit. Отказ не сбрасывается
повторной подачей. Допуск сразу разрешает публикацию по BE-04 без согласования
каждой встречи. ADMIN без сессии/роли не может читать или менять контур.

Файлы: organizations/moderation.go и moderation/organizations/organizations.go,
SQL организаций/заявок и sqlc, cmd/api/main.go, PostgreSQL/HTTPS/браузерные тесты.
Схема/миграции, зависимости, OpenAPI/DTO, фронтенд и Compose не менялись.

Проверки: полный контейнерный `go test -race -count=1 ./...` — PASS, включая
BE-04/05, auth, миграции/seed/SVG/transport. Events 21.950s, organizations 14.684s.
Новые тесты проверяют обе ветки/причину, одинаковое и противоположное решения,
параллельные решения (200/200 либо 200/409), ADMIN-права и контекстные capabilities,
поиск/статусы/курсоры/порядок до LIMIT, отсутствие частичного решения при ошибке
COMMIT, SESSION_EXPIRED после ожидания барьера, полный API S2 с публикацией.

Настоящие S1/S2 по HTTPS и через существующие веб-формы с тремя независимыми
сессиями прошли; after down/up данные и сессии сохранились. Все операции
зарегистрированы в производственном main.go. Итог и воспроизведение —
[в отчёте всего BE-P1](README.md). Следующий пакет самовольно не начинается.
