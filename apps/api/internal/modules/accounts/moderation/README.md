# BE-13 — поиск и блокировка аккаунтов

Продолжение от BE-P3 `41ca357` в `codex/be-03-event-reads` (общая интеграционная
база c7c04b1). Подключены adminListAccounts/adminGetAccount/adminSetAccountStatus
в штатном main.go. Код не меняет auth/общий guard, роли и предметные состояния.

Поиск по нормализованному имени/email либо точному UUID, ACTIVE/BLOCKED до LIMIT,
createdAt/id DESC; подписанный курсор связан с ADMIN, q и status. Административный
DTO содержит приватные поля, публичный по-прежнему только четыре поля.
PublicFromRow в accounts переиспользует каноническую проекцию аватара из той же
SQL-строки: status/isBlocked/blockedAt читаются согласованно.

Порядок блокировки: общий барьер → действующий ADMIN FOR SHARE (существующий
guard) → предварительное чтение роли цели → только USER FOR UPDATE → проверка
expectedRevision → изменение статуса и отзыв sessions → COMMIT. Цель ADMIN,
включая себя, отклоняется до эксклюзивного замка. Устаревшая revision даёт
ACCOUNT_REVISION_CONFLICT даже при совпавшем статусе. Повтор с текущей версией
и тем же статусом ничего не переписывает. Изменение увеличивает revision;
BLOCKED заполняет дату/ADMIN и удаляет все сессии. ACTIVE очищает blocked-поля,
разрешает новый вход и не возвращает старые токены. Ответ только после COMMIT.

Публикации, сообщения, жалобы, допуск организаций, участия и аватары сохраняются.
Публичные признаки isBlocked/ownerIsBlocked используют уже действующие модули;
прочие пользователи сохраняют доступ и запись на опубликованную встречу.

интегратору.

- `go test -race -count=1 -run '^TestAccountModeration' ./internal/modules/events ./cmd/api`

## Передача интегратору

Изменения: accounts/moderation, SQL accounts_moderation.sql и отзыв сессий,
их sqlc, main.go, выделенная каноническая проекция PublicFromRow и адресные
тесты на существующей общей fixture в events. Принимать поверх BE-P3 без reset.
Статусы/manifest/корневые документы остаются у координатора. Общий go test ./...,
контрактный валидатор/генерация Go/TS и совместный SCR-22 с FE-15 — интегратору.
BE-13 не реализует фронтенд FE-15 или MEDIA-01A/B. Push не выполнялся.

Воспроизведение: собрать api target корневого Dockerfile с тегом ryadom-be13-api;
предоставить совместимые ryadom-be13-web/migrate/seed, затем:

```bash
python3 apps/api/internal/modules/accounts/moderation/testdata/http_accept.py --source "$PWD"
```

Адресные SQL-тесты используют существующие overlays из отчёта organizations
и переменную RYADOM_EVENTS_TEST_DATABASE_URL. Каждая проверка создаёт свою схему
и удаляет её после завершения; отсутствие переменной пропускает тесты и не
является успешной предметной приёмкой. HTTPS-скрипт удаляет только свой проект/том.
