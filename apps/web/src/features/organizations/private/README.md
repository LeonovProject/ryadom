# FE-06 — кабинеты организаций

Продолжение по поручению «Продолжи реализацию» и последующим «Продолжи»,
20 октября 2026. Исходная основа — `ab6b1054ddceeed6c4ec16df9e075b5601c454ce`,
ветка `codex/fe-01-shell`, незакоммиченные FE-01–05 сохранены.
Выполнена фронтенд-часть одной следующей карточки FRONTEND.

**Используется общий клиент API 0.13.0. Проверки бизнес-состояний выполняются
на HTTP-фикстурах. Реальный S2 с BE-05/06, администратором и PostgreSQL через
продуктовый Compose пока не принят.**

## Результат

- `/me/organizations`: собственные профили, четыре состояния допуска,
  причина отказа, переходы в кабинет/создание, публикация встречи только для
  APPROVED + canPublish. Загрузка, ошибка и пустота различимы; страницы
  догружаются без перестановки серверного порядка/дублей. Ошибка следующей
  страницы сохраняет уже загруженное; INVALID_CURSOR предлагает начать заново.
- `/organizations/new`: название, деятельность и спортивные интересы,
  клиентские ограничения и ошибки по JSON pointers. Один POST сохраняет частный
  профиль; только после 201 открывается кабинет с перечитыванием. Заявка не
  отправляется автоматически; создание не называется публикацией организации.
- Таймаут, обрыв, 5xx или неподтверждённый ответ создания сохраняют неизвестный
  результат и блокируют повтор. Есть переход к своим организациям; совпадение
  названия не выдаётся за квитанцию. При уходе — диалог; перезагрузка удаляет
  заполнение. Ввод хранится только в памяти вкладки. Истечение сессии скрывает
  форму; вход в тот же аккаунт восстанавливает её, другой аккаунт/выход/блокировка
  очищают. Неизвестный результат сохраняется до отправки POST, включая потерю
  сессии во время запроса. Чужое заполнение не переносится.
- `/me/organizations/:organizationId`: закрытые сведения, допуск, даты заявки
  и решения с явным UTC, причина отказа обычным текстом. Гость/сбой getMe не
  запускают частное чтение. UUID, соответствие ID и владельца, связь заявки с
  организацией проверяются перед показом. ADMIN не получает чужой кабинет.
  При 404/ошибке перечитывания прежние сведения убираются; зависимые встречи
  не загружаются без успешного чтения кабинета.
- NOT_SUBMITTED + canSubmit: отдельная отправка на проверку без тела, двойной
  запрос блокируется. Только ответ 201/200 даёт подтверждение, затем читается
  актуальный кабинет. Повтор 200 с REJECTED сохраняет отказ и не называется
  новой заявкой. После неизвестного результата — GET без автоматического POST;
  наличие заявки показывает текущее состояние, без утверждения об авторстве
  потерянного запроса. При отсутствии заявки явному идемпотентному повтору
  предшествует явная проверка чтением.
- PENDING: ожидание без публикации. REJECTED: причина без редактирования или
  обещания повторной подачи. APPROVED: публичная страница и создание встречи
  с `?organization=...` только при canPublish. Изменившийся допуск перечитывается
  при возврате во вкладку; отличающиеся ссылки/canPublish в getMe обновляются
  отдельным чтением без циклических запросов.
- В кабинете — `listMyEvents?organizationId=...`, все даты и снятые публикации
  по серверному createdAt/id DESC. Это необходимая часть SCR-14, реализованная
  внутри FE-06; личный список FE-08 не менялся. Публикация, допуск и участие не
  смешиваются. UNPUBLISHED показывает только ограниченную сводку, даже если
  тестовый ответ содержит лишние поля; причина снятия доступна на странице
  встречи для ответственного. Ссылка управления остаётся заглушкой FE-09.

## Файлы и интеграция

- `private/**`: доступ, список, кабинет, чтение, подача, встречи организации,
  стили, фикстуры и тесты. DTO/статусы только из общего API-клиента.
- `../create/**`: создание, валидация, память формы и её сессионная граница.
- `../../../shared/ui/FormLeavePrompt.tsx`: общий доступный диалог ухода.
  `../../events/create/LeavePrompt.tsx` теперь задаёт ему прежний текст про
  встречу; поведение FE-05 проверяется общей регрессией.
- `../../../app/App.tsx`: три маршрута и граница памяти формы.
  Страницы организаций загружаются по переходу: новый раздел не включается
  целиком в начальный JS. `app/tests/shell.spec.ts` исключает готовые маршруты
  из проверки заглушек; `app/README.md` ссылается на этот результат.

Публичная организация FE-04, контракты/генерация/версии/зависимости, брендбук,
контейнерные конфигурации, сервер и старый HTML-макет не менялись.
README/CONTEXT/очередь/manifest в корне принадлежат координатору и не
редактировались; сведения из этого отчёта передаются ему для интеграции.

## Проверки

Из корня с установленными зависимостями BASE-01:

```bash
pnpm typecheck
pnpm build
pnpm exec vitest run apps/web/src/shared apps/web/src/features --exclude '**/*.spec.ts'
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/google-chrome pnpm exec playwright test --config apps/web/src/app/tests/playwright.config.ts --trace retain-on-failure
python3 scripts/check_repository.py
python3 scripts/check_handoff.py
git diff --check
docker compose -f compose.foundation.yaml build web-check
```

Браузерный сервер — порт 4175; зона устройства America/Los_Angeles.
Фикстуры — именованные примеры `packages/contracts/examples/http-cases.json`
и тестовые варианты границ/сбоев. Они не входят в приложение и не реализуют БД.
Снимки списка/создания/кабинета на 320/390/768/1280 — `.artifacts/fe-06/`
(игнорируются Git). Начальный целевой браузерный прогон прошёл 30/30; затем
добавлены проверки связи заявки с организацией, canSubmit, пагинации встреч
и фактической очистки приватного кеша при блокировке.

Предыдущая попытка запуска браузерной проверки была отклонена автоматической
проверкой разрешения из-за лимита использования, без выполнения команды и без
оценки её небезопасности. После продолжения пользователем проверка разрешения
успешна; блокировка не обходилась.

## Ограничения и передача

Нужны BE-05/06 и продуктовый Compose: реальное сохранение/подача, рассмотрение
другим администратором (FE-07), причина отказа/обе ветки решения, публичная
видимость только после допуска, публикация встречи и просмотр вторым человеком,
отзыв сессий/права и сохранение после пересоздания контейнеров с тем же томом.
HTTP-фикстуры и сборка web-check не доказывают эту интеграцию.

Личная лента и общий список своих встреч — FE-08; состав — FE-09; административные
организации — FE-07. Редактирование и повторное рассмотрение не добавлялись в
обход контракта. Физические устройства, экранная клавиатура и диктор не проверялись.
Коммит, push, публикация и развёртывание не выполнялись.
