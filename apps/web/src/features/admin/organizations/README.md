## Результат

- `/admin/organizations`: поиск по названию/деятельности/спортивным интересам,
  все четыре состояния, включая NOT_SUBMITTED, фильтр допуска. Применённые
  фильтры находятся в URL, работают возврат из карточки и история браузера.
  Смена фильтров начинает выдачу без старого курсора. Запрос ограничен 200
  Unicode-символами; неправильный фильтр не запускает запрос к API.
- Загрузка, ошибка и пустота различимы. Страницы сохраняют серверный порядок
  createdAt/id ASC; совпавший ID между страницами заменяет сведения целиком без
  дубля. Повтор одного ID внутри страницы отклоняет ответ. Ошибка следующей
  страницы сохраняет загруженное, INVALID_CURSOR позволяет начать заново.
  Ошибка перечитывания и отказ в доступе, включая следующую страницу, скрывают
  прежние административные сведения.
- `/admin/organizations/:organizationId`: профиль, спортивные интересы,
  ответственный со ссылкой, даты с явным GMT+0, сведения заявки/решения и причина
  отказа обычным текстом. Есть ссылка на `/admin/events?organizationId=...`
  (сам список — будущая FE-11) и публичную организацию после APPROVED.
  Блокировка ответственного не меняет отображаемое состояние допуска.
- ADMIN проверяется по getMe до административного чтения. Гость получает вход
  с допустимым returnTo; USER видит отсутствие доступа без запроса admin API.
  Сбой проверки сессии не запускает чтение. Серверные 401/403/404 не выдаются
  за пустую организацию или успешное решение. Сессионная граница очищает кеш
  и скрывает введённую причину; запоздалый ответ прежней сессии игнорируется.
- Только PENDING с заявкой имеет действия. APPROVE отправляет только decision;
  REJECT открывает Radix-диалог с обязательной причиной, trim и лимитом 2000
  Unicode-символов. Клиентские и серверные ошибки связаны с полем, ввод
  сохраняется. Диалог удерживает фокус, закрывается Escape и возвращает фокус;
  во время отправки закрытие и повторное нажатие заблокированы. Если при
  обновлении обнаружено решение другого администратора, открытый диалог
  закрывается и новое решение из него отправить нельзя.
- Только проверенный ответ 200 с ID просмотренной заявки/организации и тем же
  решением даёт подтверждение, затем перечитывается канонический профиль.
  Ответ одинакового повторного решения не называется изменением уже принятого.
  Прежние списки организаций помечаются для обновления.
- 409 DECISION_CONFLICT перечитывает профиль и сообщает, что решение с другими
  данными уже принято; нового POST и обещания повторного рассмотрения нет.
  Таймаут, обрыв, 5xx или неверная квитанция означают неизвестный результат:
  выполняется GET, без автоматического POST и без приписывания текущего
  состояния потерянному запросу. Если заявка остаётся PENDING, явный повтор
  возможен только после успешной отдельной проверки и с исходным решением/
  причиной. Сбой проверки не разрешает повтор. Во время явного повтора виден
  индикатор отправки; последующий FORBIDDEN показывает отказ и убирает повтор.
- NOT_SUBMITTED не позволяет решить за представителя; APPROVED/REJECTED
  показывают итог без кнопок нового рассмотрения. Допуск, публикация и
  блокировка ответственного не смешиваются. ADMIN не получает возможности
  публикации только из-за своей роли или допуска чужой организации.

## Ограничения и передача

Нужны BE-05/06 и продуктовый Compose для S2 с представителем, администратором
и вторым человеком: реальная подача, поиск, обе ветки решения и сохранение
причины, публичная видимость только после допуска, публикация встречи,
серверные конфликты/Origin/отзыв сессий и сохранение после пересоздания
контейнеров с тем же томом. HTTP-фикстуры и сборка web-check не доказывают
эту интеграцию и не закрывают всю карточку S2.

Административные встречи/модерация сообщений, личные участия и состав относятся
к следующим карточкам. Физические устройства, экранная клавиатура и диктор
не проверялись. Коммит, push, публикация и развёртывание не выполнялись.
