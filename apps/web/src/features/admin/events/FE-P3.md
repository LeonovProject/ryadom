## Подключения и ограничения

Области: features/admin/events/**, admin/activitytypes/**, reports/**,
точки интеграции events/detail/EventPage.tsx и discussion/Discussion.tsx,
app/App.tsx, shared/api/admin-action.ts и ожидания заглушек в shell.spec.ts.
Административные ссылки уже есть в личном кабинете, новые маршруты подключены.
Действующие login/Me, /demo и пользовательские экраны сохранены.
Контракты 0.13.0, Go/TS DTO, сервер/SQL, зависимости/lock, Compose и бренд не менялись.

Общий механизм действий проверяет HTTP/квитанцию, блокирует параллельное
нажатие, не повторяет POST, сохраняет ввод при конфликте и требует явного
успешного перечитывания перед новым действием. Потерянный ответ не превращается
в успех по совпадению состояния. Новые версии сами не подставляются в повтор.
Персональные квитанции ограничены текущим session epoch; административные
данные/запросы недоступны USER. Прямые жалобы и жалобы сообщений независимы.
Восстановление сообщения не возвращает публикацию встречи.

BE-08 предоставляет административный оригинал в списке. До BE-11 прямой
adminGetMessage может возвращать 404: после скрытия FE-11 перечитывает доступный
список как fallback. Если строка исчезла из фильтра и чтение по ID недоступно,
дальнейшее действие остаётся заблокированным. С BE-11 выбранное сообщение
перечитывается по ID и не теряется из-за нового значения счётчика/статуса.
Поле id редактора направления не добавляет нового маршрута.

## Реальный контейнерный проход FE-11

Собственный Compose ryadom-fe-p3, 127.0.0.1:4191, новый отдельный том и обычный
seed. Web собран из текущей ветки, API/migrate/seed — принятые ryadom-p2-*:latest.
Общий preview/его том, ключи и данные не менялись. Сборка web использовала
host network для зависимостей; runtime использует штатные изолированные сети.

`admin/events/tests/runtime.cjs` требует явные FE_P3_BASE_URL и
FE_P3_DISPOSABLE=true, поскольку делает ровно два бизнес-POST через формы:
скрытие одного сообщения и снятие встречи с причиной. Независимый гость получает
HIDDEN без body, затем 404 снятой встречи. Административная причина/оригинал,
ширины 1280/390, отсутствие переполнения/JS-ошибок и отсутствие лишних POST — PASS.
Проверка направлений на этом API показывает честную ошибку отсутствующего BE-10.
Снимки .artifacts/fe-p3/runtime/ просмотрены.

После финальной синхронизации поискового поля с URL/history web пересобран;
API/web пересозданы с прежним томом. Read-only режим FE_P3_VERIFY_ONLY=true
проверяет поиск/назад и сохранённое снятие через UI/API, без новых бизнес-POST.
Это адресная проверка пакета, не весь QA или новый полный прогон P2.
