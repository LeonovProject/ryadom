# FE-02 — вход, регистрация и текущий аккаунт

Продолжение по поручению пользователя от 20 октября 2026. Исходная основа —
`ab6b1054ddceeed6c4ec16df9e075b5601c454ce` и незакоммиченный результат FE-01
в текущей рабочей копии `codex/fe-01-shell`. Изменения FE-01 сохранены.

**Фронтенд подготовлен и проверен по HTTP-фикстурам. Общая интеграция ожидает
OPS-01/BE-02/MEDIA-01F; карточка не закрывает настоящий вход и хранение аккаунтов.**
Продуктовой Compose-среды и серверных операций авторизации при старте не было.
Общие конфигурации, контракты и бэкенд исполнитель не менял.

## Подключённые экраны

- `/login`: email/пароль, показ/скрытие, менеджер паролей, 401/403/429,
  Retry-After без автоматического повтора, ошибка/неопределённый ответ.
- `/register`: имя/email/пароль/подтверждение на одной странице, обязательный
  явный выбор готового аватара и предпросмотр. Нет роли, пропуска, личной
  SVG-загрузки или второго запроса выбора аватара после регистрации.
- `/me`: имя/аватар, приватный email, публичный профиль, свои встречи/организации,
  создание, состояния собственных организаций, выход. Ссылки на модерацию
  доступны только при systemRole=ADMIN. Целевые экраны других карточек пока заглушки.
- Шапка: текущий аккаунт с аватаром и прямым переходом к профилю; загрузка
  входа не выдаётся за гостевую сессию. Отдельное сообщение о блокировке/истечении.

## Поведение и границы

Единый клиент использует cookie same-origin; JWT не читается и не хранится в JS.
Все DTO импортируются из API 0.13.0. Пароль не trim/normalize, длина проверяется
по Unicode code points. Он хранится только в памяти формы/выполняемого запроса,
не попадает в URL, localStorage, sessionStorage или Query/Mutation cache и
очищается при уходе с формы. Подтверждение пароля не уходит API.

Успех требует 200 для login либо 201 для register с Me. До ответа нет перехода
или сообщения об успехе. При потере ответа POST не повторяется автоматически.
Регистрация предлагает явный login; проверка getMe показывает лишь текущий вход
и не доказывает создание аккаунта. После успешного входа — безопасный внутренний
returnTo, иначе `/`; участие/вопрос/жалоба автоматически не отправляются.

Каталог аватаров читается из API, первый вариант не выбирается автоматически.
Загрузка/ошибка/пустота блокируют только регистрацию. Неизвестный выбранный ID
и 422 не подменяют выбор; после обновления требуется явный выбор. Сбой картинки
показан, недоступная картинка блокирует выбор; каталог можно перечитать, сохранив
имя/email. Исходный SVG в тестах берётся из общего набора DEC-22, без inline SVG.
**Статический URL PRESET в реальном веб-образе по-прежнему подключает MEDIA-01F.**

SessionProvider проверяет getMe при загрузке, возврате во вкладку и истечении
указанного сервером срока. При смене аккаунта/выходе/401/ACCOUNT_BLOCKED очищается
кеш и личный интерфейс. Старый ответ с другой версией сессии не отзывает новый
аккаунт. Повторная гостевая проверка не стирает заполняемую форму. Отказ нового
login/register сохраняет прежнюю сессию и кеш; logout очищает их только после
204. Одновременно повторять logout через разные страницы нельзя.
Если getMe недоступен, показывается ошибка проверки; форму можно открыть явно
с объяснением, что успешный вход заменит текущую сессию браузера.

## Файлы

- `features/auth/**`: формы, транспорт авторизации, SessionProvider,
  безопасный returnTo, валидация, каталог/выбор, выход, сообщение об отзыве и тесты.
- `accounts/private/**`: базовый SCR-08 и его адаптивная вёрстка.
- `shared/api/client.ts`, `session-boundary.ts` и тест: обработка отзыва сессии
  для защищённых/optional-session ответов, кроме неудачного нового входа.

- `app/App.tsx`, `AppShell.tsx`, `app.module.css`: подключение провайдера,
  трёх страниц, текущего аккаунта, сообщения и исправление скрытого skip-link.
- `app/tests/**`, `app/README.md`: актуализация проверки оболочки и запуска тестов.

Контракт, генерация, зависимости, брендбук и HTML-макет не менялись.

## Проверки и воспроизведение

Из корня при установленных зависимостях BASE-01:

```bash
pnpm typecheck
pnpm build
pnpm exec vitest run apps/web/src/shared apps/web/src/features/auth --exclude '**/*.spec.ts'
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/google-chrome pnpm exec playwright test --config apps/web/src/app/tests/playwright.config.ts
python3 scripts/check_repository.py
python3 scripts/check_handoff.py
git diff --check
docker compose -f compose.foundation.yaml build web-check
```

Путь Chrome нужен только при использовании системного браузера; без переменной
Playwright использует свой установленный Chromium. Тесты запускают локальный
сервер на 4175 и подменяют только HTTP-ответы внутри браузерного контекста теста.
Именованные фикстуры читаются из `packages/contracts/examples/http-cases.json`;
в приложение они не включаются, фиктивная cookie из примеров не устанавливается.

Результат: TypeScript/сборка и Docker web-check успешны; 24 модульные проверки,
25 браузерных проверок успешны. Проверены успех/ожидание, точный DTO/пароль,
единственная отправка, returnTo, 401/403/409/422/429, неопределённая регистрация,
каталог, смена форм, очистка кеша/выход, роли, длинное имя и размеры
320/390/768/1280. Снимки регистрации и профиля — `.artifacts/fe-02/`,
диагностика браузера — `.artifacts/frontend/playwright/` (игнорируются Git).
Визуальный проход включает все четыре ширины, выбранный реальный SVG и длинное имя.
