## Результат

- `/events/new`: вход до заполнения; отдельные состояния проверки сессии,
  гостя и ошибки. Ссылка входа/регистрации сохраняет безопасный returnTo.
- Три шага: «О встрече», «Участие», «Проверка». Название, направление из общего
  списка или своё, описание, местное время и IANA-зона, город/место, оба режима
  записи, необязательные условия. Сводка показывает автора и начало со смещением.
- Публикация от текущего человека либо своей APPROVED организации с canPublish.
  `?organization=...` сохраняет выбор; недоступная/чужая организация не заменяется
  личным автором автоматически. До допуска есть объяснение и ссылка в свой кабинет.
  ORG_NOT_APPROVED перечитывает getMe, сохраняя текст и выбранного автора.
- Ошибка/пустота общего справочника не запрещает своё направление. DTO передаёт
  ровно одну ветку activityType (id либо name), не назначает catalogStatus.
  Проверка справочника не объявляется согласованием публикации.
- datetime-local преобразуется в абсолютное startsAt через Intl в выбранной зоне,
  без интерпретации в зоне устройства. Проверяются календарь, зона, будущее начало,
  сезонные пропуски и повторения; неоднозначное время требует другого выбора.
  Окончательная проверка начала и прав остаётся серверной.
- Один POST только после проверки сводки, блокировка повторного нажатия/отправки.
  Переход на ID из ответа — только после 201/PUBLISHED; страница перечитывает
  актуальную встречу. Успешная отправка обновляет кеш публичных списков/справочника.
- 422 связывает JSON pointers с полями, возвращает на нужный шаг и фокусирует ошибку.
  Известный отказ сохраняет заполнение. Сетевой сбой, таймаут, 5xx или неожиданный
  успешный ответ оставляют неизвестный результат и блокируют повтор публикации.
  getMe/совпадение названия не доказывают выполнение потерянного запроса.

## Память, сессия и уход

Форма живёт только в памяти вкладки, без localStorage/sessionStorage, серверных
черновиков или кеширования тела POST в Query/Mutation. На истечении сессии её
содержимое скрывается. Вход в тот же аккаунт возвращает значения и шаг;
другой аккаунт уничтожает прежнее заполнение. Выход/блокировка очищают его.
При потере сессии во время POST неизвестный результат записывается **до** отправки
и сохраняет запрет повторения после входа. Запоздалый ответ старой сессии не
подтверждает успех в новом контексте.

Навигация с заполненной формы требует решения в диалоге с клавиатурой/Escape
и восстановлением фокуса. Подтверждённый уход очищает форму. Перезагрузка
предупреждает о потере; после неё форма пуста. Уход/отмена чтения ответа не
объявляются отменой серверной публикации. Неизвестный результат содержит ссылку
на свои встречи и прямо сообщает, что этот раздел ещё в разработке (FE-08).
До него повторная публикация заблокирована; совпадение названия не выдаётся за квитанцию.

## Проверки

Команды из корня с установленными зависимостями BASE-01:

```bash
pnpm typecheck
pnpm build
pnpm exec vitest run apps/web/src/shared apps/web/src/features --exclude '**/*.spec.ts'
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/google-chrome pnpm exec playwright test --config apps/web/src/app/tests/playwright.config.ts --trace retain-on-failure
python3 scripts/check_repository.py
python3 scripts/check_handoff.py
git diff --check
docker compose -f compose.foundation.yaml build web-check
```

Браузерный сервер — порт 4175, зона устройства America/Los_Angeles; ввод времени
проверяется в Asia/Krasnoyarsk и Europe/Berlin. Фикстуры берутся из общего
`http-cases.json`; варианты границ/сбоев создаются только внутри тестов.
Снимки трёх шагов на 320/390/768/1280 — `.artifacts/fe-05/` (игнорируются Git).

Проверяются: гостевой доступ/сбой сессии, личная публикация/допустимая организация,
готовое/своё направление, оба режима, точный DTO/часовая зона, ожидание 201,
двойная отправка, 422/409/403, таймаут/сеть/5xx, истечение/смена/блокировка аккаунта,
потеря сессии во время POST, сохранение/очистка памяти, уход/перезагрузка,
клавиатура и регрессия FE-01/02/03/04.

При визуальной проверке исправлено сужение текстового поля своего направления:
размер 20×20 теперь относится только к radio. Браузерная проверка дополнительно
контролирует полезную ширину текстового поля. Просмотрены все 12 снимков шагов
на четырёх размерах: горизонтального переполнения/обрезанного текста не обнаружено.

В промежуточных прогонах уточнены тестовые ожидания: существующий ID берётся
из реально возвращённого каталога, фокус шага проверяется до выбора radio,
URL каталога допускает штатный from, уведомление блокировки различается со
статусом загрузки. Один отдельный сбой открытия формы расследован по трассировке:
Chrome не загрузил модуль React (`net::ERR_NETWORK_CHANGED`) до запуска приложения.
Трассировка сохранена в `.artifacts/fe-05/network-changed-trace.zip`; причина
изменения сетевого состояния ОС не установлена. Обходных повторов HTTP/POST в
приложении не добавлено.

встречи. Физические устройства, экранная клавиатура и диктор не проверялись.
