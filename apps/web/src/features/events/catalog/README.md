# FE-03 — главная и каталог встреч

Ниже сохранён отчёт FE-03. По следующему поручению подключена
[страница встречи и публичные профили FE-04](../detail/README.md).
SCR-03 теперь получает данные из getEvent; обратная ссылка сохраняет фильтры
каталога. Общая серверная интеграция остаётся незавершённой.

Продолжение фронтенда по поручениям пользователя «Продолжи реализацию» и
«Продолжи», 20 октября 2026. Основа — коммит
`ab6b1054ddceeed6c4ec16df9e075b5601c454ce` и сохранённые незакоммиченные
FE-01/FE-02 в `codex/fe-01-shell`. Их изменения не откатывались.

**Фронтенд подключён к API 0.13.0 и проверен на HTTP-фикстурах. Реальный
сервер BE-03 и совместная приёмка через OPS-01 ещё не готовы.** Это не
подтверждение серверной фильтрации, хранения или работы бизнес-сценариев.

## Результат

`/` — гостевая главная с объяснением продукта, поиском по интересу/городу,
направлениями из listActivityTypes, ближайшими встречами из listEvents,
объяснением записи и переходом к созданию организации. Город не подставляется
автоматически. Счётчики пользователей/мест, рейтинги и цены не выдумываются.

После входа hero заменяется коротким входом в «Мои встречи».
`HomePage.personalPlans` — место подключения FE-08. Пока показывается только
ссылка на личный список; нет фиктивных CONFIRMED или сообщения, что участий нет.
Личные запросы listMyParticipations на этом этапе не выполняются.

`/events` — каталог с поиском, городом, направлением, режимом записи,
календарными датами, сбросом, применёнными фильтрами и продолжением списка.
Поиск сохраняет остальные выбранные условия. Пустой город не отправляется API.
Корректный activityTypeId из ссылки сохраняется, даже если его нет в общем списке.
Неподтверждённые/отклонённые направления не добавляются в общий select.

Карточка показывает название/направление, начало в зоне встречи с годом/GMT,
город/место, организатора и ссылку на профиль, режим записи и переход к встрече.
Блокировка автора не подменяет публикацию. Аватар/фон выводятся через img;
при сбое изображения используется штатная графика/инициалы. Текст не вставляется
как HTML. Кнопок записи в каталоге нет.

## Фильтры и страницы

- Условия сохраняются в URL. Каталог явно отправляет from; при первом входе
  фиксирует момент в ссылке, чтобы страницы и возврат сохраняли одну область.
  Явные абсолютные from/to поддерживаются вместе с календарными датами.
- Даты UI включительные, API — `[dateFrom, dateTo)`. Один первый день превращается
  в этот день и следующий; диапазон 7–9 ноября — до 10 ноября. Переноса date-only
  через Date/toISOString/зону устройства нет. Переходы месяца/года/високосного
  февраля вычисляются календарно.
- Повторяющиеся/невалидные фильтры, невозможные даты и обратные диапазоны
  останавливают запрос выдачи и предлагают исправление/сброс.
- Cursor из URL не используется: ссылка открывает первую страницу. API выдаёт
  nextCursor, клиент передаёт его без разбора. Смена фильтров отбрасывает цепочку.
  Дубли между страницами удаляются по ID с сохранением серверного порядка;
  повтор ID внутри одной страницы считается ошибочным ответом.
- Загрузка/ошибка/пустота различимы. Сбой следующей страницы сохраняет прежние
  карточки и предлагает явный повтор. INVALID_CURSOR предлагает начать с первой
  страницы. Обновление сохраняет фильтры, включая from/to. Количество показанных
  карточек не выдаётся за total. Серверный порядок локально не пересортировывается.
- Карточка передаёт текущую ссылку каталога в состояние навигации;
  «К найденным встречам» в пока пустом SCR-03 возвращает точные фильтры.
  Восстановление прежнего вертикального положения списка пока не реализовано.

## Проверки

Из корня, с установленными зависимостями BASE-01:

```bash
pnpm typecheck
pnpm build
pnpm exec vitest run apps/web/src/shared apps/web/src/features --exclude '**/*.spec.ts'
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/google-chrome pnpm exec playwright test --config apps/web/src/app/tests/playwright.config.ts
python3 scripts/check_repository.py
python3 scripts/check_handoff.py
git diff --check
docker compose -f compose.foundation.yaml build web-check
```

Браузерные тесты поднимают сервер на 4175, работают в зоне America/Los_Angeles
и подменяют HTTP только в тестовом контексте. Именованные примеры читаются из
общего `http-cases.json`; варианты пагинации/длинных названий используют те же
типы DTO. В приложение фикстуры не включаются. Системный Chrome выбирается
переменной выше; без неё нужен Chromium, установленный для Playwright.

Результаты: 50 модульных и 39 браузерных проверок прошли (включая FE-01/02);
из них 14 браузерных — FE-03. TypeScript, сборка, Docker web-check,
проверки репозитория/пакета передачи/diff успешны. Проверены поиск/сохранение
условий, пустой город, ID вне общего списка, местные даты/абсолютные границы,
пагинация/дубли/сбои/INVALID_CURSOR, состояния данных, возврат и главная после входа.
Визуально просмотрены главная и каталог на 320/390/768/1280; переполнения и
обрезки текста не обнаружено. Снимки — `.artifacts/fe-03/`, диагностика —
`.artifacts/frontend/playwright/` (игнорируются Git).
