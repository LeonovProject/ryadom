## Страницы

- `/events/:eventId`: направление, название, дата/время с зоной встречи,
  город/место, описание, условия или пояснение об их отсутствии, организатор
  со ссылкой, оба режима записи и число подтверждённых участников.
  Собственное участие читается из ответа API, без оптимистических изменений.
- Начавшаяся публикация сохраняется: EVENT_STARTED закрывает запись/решения,
  PENDING не превращается в отказ или подтверждение. Доступ автора к составу
  определяется canManageParticipants, отдельно от canDecideParticipations.
  Ссылки на управление/модерацию ведут пока к экранам следующих карточек.
- UNPUBLISHED: только название, недоступность публикации, сохранённое своё
  участие и причина, если API её вернул. Ветка не читает и не показывает
  адрес/время/описание/организатора/фон, даже если ответ ошибочно содержит лишние
  поля. Новых действий записи/сообщений нет; доступно перечитывание сведений.
- activityTypeReview отображается для авторских возможностей, если API
  вернул проверку. Состояние справочника не подменяет публикацию встречи.
  ADMIN без авторства не получает ссылку управления участниками.
- `/people/:accountId`: публичное имя/аватар, isBlocked и опубликованные
  встречи с organizerAccountId. Email, системная роль, приватные решения,
  чужие участия/заявки не показываются. Для своего профиля — личный кабинет.
- `/organizations/:organizationId`: описание, спортивные интересы, допуск
  к публикации и встречи по organizationId. Публичная страница появляется
  только после успешного getOrganization; 404 не загружает её встречи и не
  раскрывает кабинет. Переход в кабинет есть только у владельца из getMe.
  ownerIsBlocked показывается отдельно от допуска и публикаций.

Списки профилей содержат опубликованные встречи всех дат: from не добавляется
автоматически. Серверный порядок сохранён, используется общая пагинация FE-03,
пустой список не обещает несуществующий рейтинг/опыт/посещение.

## Данные, ошибки и навигация

DTO импортируются из общего клиента, независимых схем нет. Ключи ресурсов
включают ID и версию текущей сессии. Чтение использует same-origin cookie,
отмену запроса при уходе/смене ID и таймаут. Неверный UUID не отправляется API;
ответ с ID другого ресурса отклоняется. Повторы — только явным действием
либо штатным обновлением чтения при возврате во вкладку.

Загрузка, 404, 401/403 и сбой сервера различимы. Ошибка перечитывания ресурса
убирает прежнее содержимое. Переход PUBLISHED → UNPUBLISHED → 404 не оставляет
старых закрытых полей в DOM. ACCOUNT_BLOCKED optional-session запроса проходит
через общую очистку сессии/персонального кеша; затем доступно гостевое чтение.
Поздний ответ предыдущего профиля не подменяет новую страницу.

Дата/время показываются общим форматтером в зоне встречи, а не устройства.
Пользовательский текст остаётся текстом, переносы сохранены. SVG выводится
через img, при ошибке изображения информация остаётся читаемой.
Из встречи можно вернуться к точным фильтрам каталога. Заголовок браузера
обновляется после загрузки; клавиатурный фокус сохраняется при замене
заголовка ожидания реальным заголовком после перехода.

## Воспроизведение проверки

Из корня с установленными зависимостями BASE-01:

```bash
pnpm typecheck
pnpm build
pnpm exec vitest run apps/web/src/shared apps/web/src/features --exclude '**/*.spec.ts'
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/google-chrome pnpm exec playwright test --config apps/web/src/app/tests/playwright.config.ts
python3 scripts/check_repository.py
python3 scripts/check_handoff.py
git diff --check
docker compose -f compose.foundation.yaml build web-check
```

Браузерный сервер использует порт 4175. Тесты подменяют HTTP-ответы только
в тестовом контексте: именованные примеры общего `http-cases.json` плюс
типизированные варианты границ/сбоев. Фикстуры не входят в приложение.
Переменная пути Chrome нужна при использовании системного браузера.

Проверяются варианты публикации/nullable, отсутствие закрытых полей,
временная граница, роли/допуск/участие, неверные ID, возврат во вкладку,
запоздалый ответ, кеш, навигация/фокус и регрессия FE-01/02/03.
Снимки встречи/обоих профилей на 320/390/768/1280 — `.artifacts/fe-04/`,
диагностика — `.artifacts/frontend/playwright/` (игнорируются Git).

Итоги проверки 20 октября 2026:

- typecheck, production build и контейнерная сборка web-check — PASS;
- Vitest — 50 тестов в 6 файлах, PASS;
- полный браузерный прогон — 60/60, включая 21 сценарий FE-04, PASS;
- check_repository.py, check_handoff.py, git diff --check — PASS;
- просмотрены все 12 снимков трёх страниц на 320/390/768/1280 px:
  горизонтального переполнения и обрезанного текста не обнаружено.

В предшествующем общем прогоне два открытия страниц не показали заголовок
за 5 секунд (одна заглушка и организация на 390 px), итог был 58/60.
Отдельный повтор с трассировкой прошёл 5/5, затем полный прогон с
`--trace retain-on-failure` — 60/60 без изменений приложения между прогонами.
Причина этих неповторившихся сбоев не установлена; стабильность браузерной
среды следует наблюдать при последующей интеграции.

## Ограничения и передача

Нужны реальные проверки видимости и прав BE-03/BE-05 через продуктовый proxy,
cookie/две сессии и хранение после пересоздания контейнеров. Сборка web-check
не закрывает эту интеграцию. Получение/показ PRESET в реальном образе по-прежнему
завершает MEDIA-01F. Запись — FE-08, состав/решения — FE-09, обсуждение — FE-10,
модерация — отдельные карточки. Физические устройства, экранная клавиатура
и экранный диктор не проверялись. Коммит, push и развёртывание не выполнялись.
