## Найденные дефекты и выполненные исправления

### QA01-F01 — Swagger открывается на внутреннем порту, P2, CLOSED

**Владелец COORDINATOR**, область `infra/web/routes.conf` и адресные infra-тесты.
До исправления на preview запрос `http://127.0.0.1:4180/api/docs` отвечает
`308 Location: http://127.0.0.1:8080/api/docs/`. Порт контейнера снаружи не
опубликован. Со слешем исходный адрес работает. [Точные ответы](evidence/routes.json).
В `location = /api/docs` относительный `return` Nginx превращается в абсолютный
URL со своим портом. Аналогичный риск в HTTPS-конфигурации с внутренним 8443.

Исправить перенаправление с сохранением внешнего origin, например относительным
Location. Проверить HTTP с внешним нестандартным портом и HTTPS: `/api/docs`
открывает UI, его локальные JS/CSS и `/api/openapi.yaml`, не меняя схему/домен/порт.
Не требуется пересматривать API/авторизацию или сбрасывать данные.

**Исправлено:** `absolute_redirect off` только в точном location `/api/docs`.
[Реальные HTTP](evidence/routes-fixed-http.json) и
[HTTPS](evidence/routes-fixed-https.json) на случайных внешних портах прошли.
`infra/tests/accept.py` теперь проверяет и исходную ссылку без слеша.
Пересобран и обновлён только web общего preview;
[повторное чтение маршрутов](evidence/routes-preview-fixed.json) PASS. API/БД
не пересоздавались, DEMO_MODE не включался, seed/reset не выполнялись.
В настоящем Chrome исходная ссылка открыла UI с 60 операциями без JS-ошибок:
[вывод](evidence/swagger-ui-fixed.txt), [снимок](screenshots/swagger-fixed-1280.png).

### QA01-F02 — «Ты участвуешь» относится к другому человеку, P2, CLOSED

**Владелец FRONTEND**, область `apps/web/src/features/participation/manage/`
и согласованное расширение `StatusBadge` при необходимости. Войти Анной,
открыть состав своей встречи с подтверждённым Алексеем: его строка подписана
«Ты участвуешь». [Снимок](screenshots/after-retained-roster-1280.png).
`ManagePage.tsx` использует личную формулировку общего статуса.

Использовать нейтральную подпись для чужого состава («Участие подтверждено»),
сохранив личную формулировку для своей записи и общие цвета состояний. Общие
файлы бренда меняет COORDINATOR по согласованию, не исполнитель параллельно.
Адресная проверка: личная карточка участника, чужая строка в составе автора,
CONFIRMED/PENDING/REJECTED, включая снятую встречу. Данные статусов не менять.

**Исправлено координатором по уточнению пользователя:** у StatusBadge появился
необязательный контекст `roster` только для participation; CONFIRMED в составе
автора — «Участие подтверждено». По умолчанию личная подпись и остальные
состояния/цвета прежние. Четыре адресных браузерных случая покрывают CONFIRMED
на опубликованной/снятой встрече и PENDING/REJECTED. Существующие тесты личной
записи проверяют «Ты участвуешь». После production-сборки повторены реальные
S1–S6 в новой БД с проверкой обеих подписей;
[снимок исправления](screenshots/fixed-roster-1280.png) просмотрен.

### QA01-N01 — сетевые изменения во время UI-регресса

Первые два полных запуска: по **223 PASS / 2 FAIL** с разными тестами.
Повторы каждой пары по пять раз: **10/10 + 10/10 PASS**; первая пара дополнительно
2/2 PASS. Диагностический полный запуск также дал 223/2. В обоих его trace
зафиксирован `net::ERR_NETWORK_CHANGED` на файлах приложения во время создания
и удаления тестовых сетей Docker: [выдержки](evidence/network-change.json).
Продукт не менялся, retries/таймауты не повышались. Финальный UI-регресс должен
выполняться после завершения всех сетевых контейнерных операций, последовательно.
Причина именно первых четырёх сбоев без trace не доказана задним числом.
После завершения контейнеров полный прогон **225/225 PASS** без retries:
[вывод](evidence/playwright-isolated.txt). После исправления подписи
адресный регресс участия/состава/общих компонентов **19/19 PASS**, включая
4 новых теста: [вывод](evidence/playwright-fixed-focused.txt).

Наблюдение UX: на узком каталоге блок фильтров занимает почти весь первый экран;
карточки доступны прокруткой, переполнения нет. Это улучшение удобства, а не
неработающий S1. Перед сдачей полезно сократить высоту стартового блока.

Неблокирующее замечание к документации для DELIVERY-01A: вводный текст
`info.description` в Swagger сохранил перечень возможностей ранней интеграции
и ссылку на её отчёт. Сама схема актуальна и показывает все 60 операций;
фактический статус ядра определяется этой QA и manifest. При окончательном
обновлении описания OpenAPI нужно штатно обновить встроенную Go-схему и её хеш,
а не менять текст только в Swagger UI. Эта QA не меняла общий контракт.

## Воспроизведение

Образы API/web собирать по `infra/README.md` с тегами `ryadom-qa01-*`;
также нужны `ryadom-qa01-migrate` и `ryadom-qa01-seed`. Инструменты Node/pnpm,
Chrome, Docker Compose и openssl должны быть доступны. Запускать из корня:

```bash
python3 tests/e2e/qa01/backend.py --source "$PWD"
python3 tests/e2e/qa01/accept.py --source "$PWD" --screenshots /tmp/ryadom-qa01-browser
# Только после завершения контейнерного прохода и его cleanup:
pnpm exec vitest run .test.ts
VITE_DEMO_ACCESS=true PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/google-chrome pnpm exec playwright test --config apps/web/src/app/tests/playwright.config.ts --trace retain-on-failure
python3 tests/e2e/qa01/routes.py --source "$PWD" --base http://127.0.0.1:4180
```

Адресная контейнерная проверка redirect без БД:

```bash
python3 tests/e2e/qa01/routes_accept.py --source "$PWD" --output /tmp/qa01-routes
```
