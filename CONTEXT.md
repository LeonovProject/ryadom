# Контекст проекта

Обновлено: 2026-10-19 (Asia/Krasnoyarsk).

Репозиторий проекта «Рядом» содержит брендбук, документацию и локальный дизайн-прототип. Приложения,
сервер и инфраструктура ещё не созданы. Перед работой прочитайте `AGENTS.md`.
Координатор обновляет этот файл по значимым решениям.

## Источники истины

- Первичны два предоставленных PDF: `docs/references/official/assignment.pdf`
  и `evaluation-criteria.pdf`. Это неизменённые копии «Постановка.pdf» и
  «Критерии_оценки.pdf»; SHA-256 и пути находятся в `docs/requirements/sources.json`.
- Полные конверсии — `docs/requirements/assignment.md` и `evaluation-criteria.md`.
  Маркеры A-Pxx/C-Pxx обозначают физические страницы с учётом обложки.
- Рабочая спецификация — `docs/product/scope.md`; проверка — `acceptance.md`;
  уточнения прежних предположений — `source-reconciliation.md` в том же каталоге.
- PDF имеют приоритет над конверсиями, рабочими документами и брендбуком.
  Внешние публикации и сдача требуют соответствующей авторизации пользователя.

## Обязательный продукт

- Кейс Столото: адаптивный веб для компании на спортивные занятия. Разные виды
  спорта и опыт пользователей; готовые направления и свой вариант без правки кода.
- Ровно три роли: пользователь, организация/сообщество, администратор.
  Организатор означает автора события, которым является пользователь или организация.
- Пользователь создаёт и публикует от себя. Организация подаёт заявку на допуск;
  администратор одобряет/отклоняет с видимой причиной отказа. До допуска нет
  публичной страницы/публикаций; после допуска события выходят без повторного согласования.
- Оба режима: свободная запись сразу подтверждена; заявка ожидает принятия/отказа
  автора. Автор видит участников/заявки, пользователь — результат решения.
- Обязательно внутреннее текстовое обсуждение с авторами сообщений. В открытом
  событии вопрос доступен любому пользователю платформы, включая незаписанных.
- Администратор ищет события/организации и переходит к связанным данным,
  удаляет/снимает событие с причиной для автора, скрывает/удаляет одно сообщение.
  Снятое/удалённое событие не принимает новые записи даже по прямой ссылке;
  автор и записанные понимают недоступность публикации.
- Экраны входа/регистрации нужны; авторизацию можно имитировать демоаккаунтами.
  Бизнес-операции действительно меняют данные. Нужны демоданные для всех ролей.
- Сдача: GitVerse, доступный экспертам через сеть прототип, README с запуском,
  доступами, сценариями и ограничениями, презентация. Пока это требования к будущей реализации.
- Максимумы разделов: 10+25+6+6+28+23=98. Шесть сценариев дают до 18 за работу
  и до 18 за UX. Административные требования шире этих шести сценариев.
- Лимиты мест, очередь, карты, уведомления, возврат организации на доработку и
  другие улучшения дополнительны. Нативное приложение не требуется и само по себе
  не даёт баллов; адаптивность веба обязательна.

## Бренд и договорённости команды

- Рабочее название «Рядом», React для веба, красный и белый, немного чёрного и синего.
- Мобильное приложение с возможным React Native и неспортивное расширение — идеи
  команды на будущее. Они не заменяют обязательный спортивный веб-прототип.
- Брендбук 1.2: `brandbook/ryadom-brandbook.docx`, PDF, ZIP и исходник сборки.
  Версия 1.0 сохранена как история оформления. Связь с требованиями —
  `brandbook/requirements-alignment.md`.
- Палитра: красный `#D92D3A`, белый `#FFFFFF`, текст `#17191D`, синий `#2457C5`.
  Заголовки Montserrat, текст Open Sans. Знак — две наклонные параллельные линии.
- Источник оформления — `brandbook/assets/tokens.json`; CSS/TypeScript, состояния,
  словарь текстов и ZIP синхронизируются с ним. Название и знак не проверены как товарный знак.

## Совместная разработка

- Правила — `docs/development/multi-agent-workflow.md`, очередь — `backlog.md`,
  шаблон задачи — `task-template.md`. Одна область файлов на исполнителя;
  общие контракты и интеграция закреплены за координатором.
- `docs/contracts/README.md` задаёт правила общих моделей/API, но не утверждает
  готовую схему или стек. Сервер, хранение, демовход и размещение предложены
  в техническом проекте, но ещё не утверждены.
- Проверки: `python3 scripts/check_repository.py` и `git diff --check`.
  DOCX/PDF после изменений рендерятся и проверяются по всем страницам.
- Очередь — предложение порядка реализации; агенты автоматически не запущены.

## Технические предложения

- Пользователь поручил подробно зафиксировать предложения в файлах. Разработку
  пока не начинать, коммит не создавать. Это поручение выполнено только в документации.
- Точка входа — `docs/architecture/README.md`. Предлагаются React/TypeScript/Vite,
  React Router, TanStack Query, CSS Modules/Radix, NestJS, PostgreSQL/Prisma,
  Zod/OpenAPI, pnpm workspaces и Docker Compose. Версии и инфраструктура не выбраны.
- `docs/architecture/data-model.md` описывает восемь таблиц, ограничения,
  индексы и транзакции; это не SQL-миграции и не созданная база.
- `docs/architecture/access-and-states.md` предлагает демосессии, одного
  ответственного на организацию, одну заявку на допуск, открытые обсуждения,
  снятие публикации и сохранение существующих записей с блокировкой новых действий.
- `docs/contracts/api-proposal.md` описывает маршруты, DTO, ошибки и повторы;
  OpenAPI и генерируемого клиента ещё нет.
- `docs/development/implementation-plan.md` содержит этапы, зоны владения,
  демонабор и проверки по S1–S6/A1–A6. Владельцы, сроки и запуск не назначены.
- Все эти решения имеют статус предложения. Первичные PDF и обязательный
  объём не изменены; код, зависимости, инфраструктура и материалы бренда не менялись.
- По следующему обсуждению добавлены `docs/product/screens.md` и `user-flows.md`:
  18 предлагаемых маршрутов, системные состояния, содержимое страниц, адаптивность
  и покрытие приёмки. Hero — блок главной; профиль человека единый для участия
  и личной организации встреч; публичная организация и закрытый кабинет разделены.
- Уточнён проект API для публичных встреч личного автора, деталей своего профиля
  организации и сводок событий в личных списках. Новых таблиц и кода не создано.
  UX-01 добавлен в очередь для согласования и схем блоков до реализации.

## Дизайн-прототип 0.1

- Пользователь выбрал локальный макет внутри проекта и разрешил начать его создание.
  Предыдущий запрет разработки продукта сохраняется для API/БД/приложений; коммит не создавать.
- `design/prototype/index.html` — старт; инструкция — `design/prototype/README.md`.
  HTML/CSS/JS без сборки и внешних библиотек; шрифты локальные с лицензиями,
  параметры оформления импортируются из брендбука 1.2.
- Основные страницы: главная, каталог, встреча, профиль человека, организация,
  трёхшаговое создание. Дополнительно: демовход/регистрация в диалоге, свой кабинет,
  свои встречи и состав/заявки для автора. Полные кабинеты организаций и модерация не созданы.
- Поиск, фильтры, записи, вопросы, решения и создание — взаимодействия в памяти
  вкладки. Перезагрузка/сброс очищают их. Переключатель состояний — инструмент
  дизайна, а не модерация с изменением всего набора событий.
- Проверены синтаксис JS, локальные ресурсы, отдача HTTP 200 и сценарии в изолированной
  среде с имитацией DOM. Это не браузерные E2E-тесты и не техническая приёмка продукта.
- Встроенный браузер многократно не ответил при подключении и снимке. Визуальная
  проверка 320/390/768/1280 остаётся открытой; не заявлять её успешной.
