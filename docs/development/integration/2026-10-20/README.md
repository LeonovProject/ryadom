## Что пока ограничено

- Каталог встреч, направления и создание встречи ждут BE-03/04. Поэтому главная
  и каталог показывают ошибку загрузки от отсутствующего API. Seed уже содержит
  события, но эти данные пока не выдаются HTTP-модулями. Добавления фиктивного
  успешного ответа или обхода серверных прав при объединении не было.
- FE-03–07 проверены на контрактных HTTP-фикстурах, но соответствующие реальные
  операции встреч/организаций/допуска ещё не приняты. Они остаются IN_PROGRESS.
- Личная главная пока предлагает переход к встречам; выборки ближайших записей,
  участие/заявки, управление составом и обсуждение относятся к следующим карточкам.
- Административные встречи/направления/аватары/аккаунты и остальные семь
  маршрутов пока содержат явные заглушки. Личные загрузки SVG, жалобы,
  блокировка через UI и административный reset ещё впереди.
- Внешнего развёртывания, GitVerse и итоговой приёмки DELIVERY не было.

## Как посмотреть сейчас

Оставлен отдельный локальный Compose-проект **ryadom-integration-preview**:

- [Приложение](http://127.0.0.1:4180/).
- [Регистрация](http://127.0.0.1:4180/register), [профиль](http://127.0.0.1:4180/me).
- [Swagger](http://127.0.0.1:4180/api/docs/).

Для входа доступны обычные подготовленные аккаунты из
[DB-02](../../../../apps/api/db/seed/README.md): например alex@example.test,
пароль `Ryadom-Alex-2026!`. Можно зарегистрировать отдельный тестовый аккаунт,
обязательно выбрав «Спутник». Вход ведёт на / либо безопасный returnTo.

Локальные секреты находятся вне репозитория, в файле с правами 0600:
`/tmp/ryadom-integration-preview/runtime.env`. Значения не включены в коммит.
Для управления этим экземпляром из корня:

```bash
docker compose --env-file /tmp/ryadom-integration-preview/runtime.env -p ryadom-integration-preview ps
docker compose --env-file /tmp/ryadom-integration-preview/runtime.env -p ryadom-integration-preview up -d --wait web
docker compose --env-file /tmp/ryadom-integration-preview/runtime.env -p ryadom-integration-preview down
```

Для новой машины используется [.env.example](../../../../.env.example) и
[инструкция инфраструктуры](../../../../infra/README.md). Этот /tmp-файл не
переносится и может исчезнуть при очистке ОС; работающий том без его пароля/ключа
не перенастраивать новым случайным env. Preview привязан только к loopback.
Seed был запущен явно один раз на новой БД; обычный запуск не сбрасывает данные.

## Откуда продолжать исполнителям

Оба исполнителя начинают от итогового merge-коммита, содержащего этот отчёт,
а не от f4ef6a5/6d1dab9. Координатор передаёт точный SHA итогом задачи. В чистой
рабочей копии своей ветки его можно получить через `git merge --ff-only <SHA>`;
если после исходного коммита уже появилась работа, её сохраняют и согласуют
обычное слияние, без reset/переписывания истории.

- **Бэкенд:** следующий BE-03 — каталог/чтение встреч и справочник, затем BE-04
  для публикации. BE-05 и BE-13 независимы после BE-02 и назначаются отдельно.
  Использовать существующие guard, транзакцию, DTO и единого владельца SQL.
- **Фронтенд:** продолжить FE-03–07 с настоящими endpoint по мере появления:
  загрузка каталога, событие/создание, организации и допуск. Сохранить проверенные
  права/ошибки/защиту от повторов. FE-08 и следующие пути — отдельные карточки
  после проверки зависимостей; они не считаются реализованными этой интеграцией.
- **Координатор:** закрыты DOCS-01 и ранняя MEDIA-01F на объединённом результате;
  финальная QA-01/DELIVERY остаются впереди. Новых функций ради снимков не добавлено.
