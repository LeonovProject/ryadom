## Исправление при интеграции

В `ReportButton.tsx` старый RESOLVED-повтор говорил «контент ограничен», даже
если сообщение уже восстановлено. Теперь: «Эта жалоба уже рассмотрена.
Повтор не открывает её заново». Это подпись квитанции; состояние сообщения
показывается отдельно. API/повторы/права не менялись.

Общая правка Compose из BE-12 добавляет только `DEMO_MODE: ${DEMO_MODE:-false}`
в API. Дополнены `.env.example` и infra/README: переключатель выключен по
умолчанию, не зависит от WEB_DEMO_ACCESS и не запускает seed/reset при старте.
Общий preview остаётся с **DEMO_MODE=false**. Включение на своём сервере требует
пересоздания API; пользователь сам выполняет развёртывание.

## Совместная контейнерная проверка

[accept.py](../../../../../infra/tests/p3/accept.py) создаёт случайный локальный
Compose-проект с отдельными БД/томом, TLS, секретами, портом и DEMO_MODE=true.
[Браузер](../../../../../infra/tests/p3/browser.cjs) использует настоящие формы
и API без моков. Миграции/seed неизменны и переиспользованы; API/web собраны из
общих исходников. SQL/sqlc, TypeScript и production build прошли.
Окончательные образы: API `ryadom-p3-api`
`sha256:12efb62c414bc4089ff461f4407784b3e1915376ddd326e85dab53c9ee3b8d0d`,
web `ryadom-p3-web`
`sha256:aba062e26dfaa2bbe4087e9148395789912c1b88d57a563648ce7abc679437fb`.


Первый полный успешный проход подтвердил:

1. FE-12/BE-10: исправление с одобрением, затем переименование; то же ID и новое
   имя читаются в связанной публичной встрече.
2. FE-13/BE-11: жалобы на встречу и сообщение из публичной формы, без причины
   и автоматического скрытия. ADMIN отдельно отклоняет прямые жалобы, скрывает
   сообщение по revision, восстанавливает; публичный текст исчезает/возвращается.
   Повтор закрытой жалобы не открывает её снова. Новая жалоба другого человека
   разбирается по актуальной версии.
3. FE-11/BE-09: реальная форма снимает встречу с обязательной причиной.
4. FE-15/BE-13: блокировка и разблокировка через подтверждение. Две сессии
   получают 403 ACCOUNT_BLOCKED, затем остаются без доступа; новый login успешен.
   Точный старый JWT после разблокировки/сохранность всех связей дополнительно
   подтверждены адресным серверным отчётом.
5. Первый down/up собственного тома сохраняет имя направления, снятие встречи,
   восстановление сообщения, рассмотренные жалобы и статус аккаунта.
6. FE-14/BE-12: реальная форма со словом СБРОСИТЬ отправляет ровно один POST.
   Старые сессии других пользователей получают 401; после нового входа ADMIN
   localStorage resetId совпадает с lastReset. generation/UUID аккаунтов новые.
7. Второй down/up сохраняет всю квитанцию. Повторный браузер читает её через
   профиль; прежняя тестовая встреча отсутствует, нового reset POST нет.

В исходной версии нового теста ожидался 401 сразу после блокировки; он исправлен
на контрактный 403 ACCOUNT_BLOCKED (ACTIVE с отозванной сессией даёт 401).
Продукт для этого не менялся. После найденной неточности подписи жалобы web
пересобран; повторён только затронутый moderation-проход с восстановлением и
закрытым повтором. Демосброс повторно не выполнялся: его код не менялся.

Ширины отдельных участников 320/390/768/1280, зона устройства Pacific/Honolulu;
нет JS-ошибок, горизонтального переполнения и лишних status/hide/restore/unpublish
запросов. Просмотрены снимки направления, восстановленного обсуждения, аккаунта
и подтверждения сброса. Снимки не заменяют полный клавиатурный/адаптивный QA.
Отказ направления, длинная пагинация, конфликты/таймауты и rollback приняты из
предметных свидетельств; этот проход не объявляет их полным совместным регрессом.
