## Основание приёмки

Подробная предметная проверка выполнена серверным исполнителем:
[BE-03 README](../../../../../apps/api/internal/modules/events/README.md).
Принят его отчёт: полный Go/PostgreSQL/race, SQL-фильтры до LIMIT, календарные
даты каждой зоны, курсоры, роли/ограниченные DTO, неизменность данных, сессии и
курсор после пересоздания, реальный HTTPS и браузер. Эти полные группы повторно
координатором не запускались — по уточнению пользователя.

Координатор проверяет только внесённое подключение: сборку API из объединённых
исходников (включая сравнение sqlc), общий preview с прежними томом/ключом,
четыре HTTP-операции и транспортные границы. Наличие Swagger само по себе не
является проверкой.

Подтверждено на объединённых исходниках:

- Docker-сборка API прошла, sqlc-генерация совпала с сохранёнными файлами;
  стартовые SVG проходят общий валидатор.
- Пересоздан только API в ryadom-integration-preview; readiness здоровая.
  PostgreSQL/том/ключи/web сохранены, seed/reset не запускались.
- Через 4180: каталог 15 опубликованных встреч, 4 одобренных направления,
  опубликованная карточка; после обычного входа Анны — 13 собственных встреч.
  Тестовая сессия завершена, прежние сессии не отзывались.
- q=&city= возвращает тот же каталог; пустой/длинный/повреждённый курсор —
  400 INVALID_CURSOR; повторённые/неизвестные query-параметры — 400 INVALID_REQUEST.
  Гостевой /me/events — 401, а не отсутствие маршрута.
- check_repository.py, check_handoff.py и git diff --check пройдены.

Это узкая проверка подключения поверх принятого предметного отчёта исполнителя;
она не объявляет повторным полный race/браузерный прогон.

## Следующая карточка

BE-03 закрыта после подтверждения подключения. Следующая **BE-04**:
[создание и публикация](../../../tasks/backend.md). Брать SHA итогового коммита
этой интеграции, который координатор передаёт итогом. Из чистого worktree BE-03
его можно получить через `git merge --ff-only <SHA>`; собственную работу сначала
сохранить. Reset/переписывание веток не нужны.

Разрешённые области: запись в modules/events/**, разрешение направления в
modules/activitytypes/**, events.sql/activity_types.sql и относящаяся sqlc-
генерация у единственного DATABASE. Не менять DTO/OpenAPI/миграции/зависимости,
фронтенд или контейнерную конфигурацию попутно. Если понадобится новое общее
подключение, передать координатору минимальный патч.

BE-04 реализует createEvent: атомарно личная/организационная публикация и своё
направление; будущее начало, IANA-зона, текущий владелец APPROVED-организации,
права/Origin/guard и отсутствие автоматического повтора. PENDING/REJECTED
направления используются по DEC-07 без новой заявки/сброса решения. Приёмка:
реальный create → list/get во второй сессии через Compose. Это отдельное
назначение, а не объявление BE-04 выполненной.

FE-03 продолжает свой назначенный scope и получает новый общий SHA после
координации; его параллельные коммиты сохраняются. Организации, участие,
обсуждение, модерация/медиа и полный S1–S6 остаются за следующими карточками.
