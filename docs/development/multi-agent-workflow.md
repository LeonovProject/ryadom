# Параллельная работа над Рядом

Этот порядок применяется при распределении работы между несколькими агентами.
Он описывает координацию в репозитории; автоматический запуск агентов и настройки
инструментов здесь не создаются.

## Порядок работы

1. Координатор читает [первичные требования](../requirements/README.md), выбирает
   задачи из [очереди](backlog.md), проверяет зависимости и назначает одного владельца
   на каждую задачу. Обязательный объём сверяется с [приёмкой](../product/acceptance.md).
2. Для каждой задачи заполняется [карточка](task-template.md): результат,
   разрешённые файлы, общие контракты, проверки и критерии готовности.
3. До параллельной реализации фиксируется минимальный общий контракт.
   Прототипы и моки явно отмечаются как таковые.
4. Исполнитель работает в своей ветке и отдельной рабочей копии от согласованного
   коммита. Имя ветки: `agent/<task-id>-<short-name>`. Worktree создаётся штатными
   средствами используемого приложения либо Git. Рабочие копии не добавляют в Git.
5. Исполнитель меняет только закреплённые файлы, запускает проверки и передаёт
   результат по шаблону ниже. Если коммиты входят в назначенную задачу, передаёт SHA.
6. Координатор проверяет diff и зависимости, интегрирует задачи последовательно
   и выполняет общие проверки на объединённом результате.

Если отдельные worktree недоступны, допускается одна рабочая копия с непересекающимся
владением файлами. В этом случае только координатор выполняет Git-операции записи,
меняет общие зависимости и запускает генераторы, которые перезаписывают несколько файлов.

## Разделение зон

Роли ниже описывают ответственность, а не постоянное количество агентов.
Каталоги приложений являются предложением для будущего решения о структуре.

| Зона | Пример области | Условие начала |
| --- | --- | --- |
| Продукт и контракты | `docs/product/`, `docs/contracts/` | Уточнены цель и исходные критерии |
| Бренд и общие компоненты | `brandbook/`, будущий пакет UI | Назначен единственный владелец генерации |
| Веб | Будущий `apps/web/` | Согласованы структура, зависимости и контракт |
| Сервер | Будущий `services/api/` | Выбраны стек, авторизация и правила данных |
| Проверка сценариев | Сценарии приёмки и будущие тесты | Известны наблюдаемые результаты |
| Мобильное приложение | Будущий `apps/mobile/` | Отдельно определён объём идеи команды |

## Общие файлы

Координатор ведёт `README.md`, `CONTEXT.md`, [очередь](backlog.md), корневые
конфигурации и будущие lock-файлы. Контракты, миграции, общие типы и исходные
параметры оформления имеют одного назначенного владельца на время изменения.

Не редактируйте общий файл «попутно». Передайте координатору конкретную правку
либо согласуйте расширение области задачи. Не заменяйте чужое изменение своей
версией и не разрешайте конфликт выбором всей стороны без чтения содержимого.

В отдельной ветке полезно делать небольшие коммиты по задаче. На общей рабочей
копии нельзя использовать `git add .` для смешанных изменений нескольких авторов.
Интеграция не означает разрешения отправить изменения на удалённый сервер.

## Изменение контракта

Опишите изменение в `docs/contracts/` и передайте зависимым исполнителям:
какие поля или состояния меняются, кто обновляет потребителей, как проверяется
совместимость. Если контракт ещё не согласован, продолжайте независимую работу,
не выдавая собственное предположение за общую договорённость.

## Передача результата

```text
Задача и исходный коммит:
Результат:
Изменённые файлы:
Изменения контракта:
Проверки и результаты:
Ограничения и необходимые решения:
Коммиты или способ передачи diff:
```

Готовая задача имеет понятный результат, остаётся в своей области, не ломает
согласованные контракты и содержит свидетельство проверки. Для интерфейса нужен
проверенный экран, для сценария — прохождение до результата, для брендбука —
рендер и просмотр страниц. Временные заглушки отмечаются явно.

## Основание инструкций

Корневой `AGENTS.md` — точка входа для инструкций Codex. Поведение поиска
инструкций описано в [официальной документации OpenAI](https://learn.chatgpt.com/docs/agent-configuration/agents-md).
После изменения инструкций уже работающим агентам нужно передать изменения;
не следует считать, что они автоматически перечитали файл.
