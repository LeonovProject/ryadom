# Очередь разработки по первичным источникам

Основание: [постановка и критерии](../requirements/README.md).
Реализация не начата; исполнители не назначены. Импорт PDF, спецификация
и [приёмка](../product/acceptance.md) подготовлены.

| ID | Результат | Зависимости | Область |
| --- | --- | --- | --- |
| PLAN-01 | Выбрать оставленные команде правила: демовход, свои направления, доступ к событиям по заявке, судьба старых записей | Первичные PDF | Продукт |
| ARCH-01 | Структура, сервер/хранение, запуск, доступ экспертам через сеть | PLAN-01 | Архитектура и конфигурация |
| CONTRACT-01 | Три роли, допуск/публикация, свой спорт, оба режима, обсуждение/модерация | PLAN-01, ARCH-01 | Общие контракты |
| UI-01 | Компоненты, адаптивность и состояния с поправками постановки | ARCH-01 | Общий UI |
| WEB-01 | Вход/регистрация, каталог/карточка, создание со своим спортом, оба режима, состав и обсуждение | CONTRACT-01, UI-01 | Веб |
| ORG-01 | Профиль/заявка, статус/причина отказа, страница после допуска, публикация | CONTRACT-01, UI-01 | Организация |
| ADMIN-01 | Поиск, допуск/отказ с причиной, модерация события и одного сообщения, запрет новой записи | CONTRACT-01, UI-01 | Административный контур |
| API-01 | Работающие данные, права и операции всех обязательных контуров | CONTRACT-01 | Сервер/хранение |
| DEMO-01 | Вымышленные данные для всех ролей, режимов и веток без подготовки экспертом | CONTRACT-01 | Демо-набор |
| QA-01 | S1–S6/A1–A6, обе ветки решений, прямые ссылки и второй пользователь | WEB-01, ORG-01, ADMIN-01, API-01, DEMO-01 | Приёмка |

| EXTRA-01 | Полезные дополнительные функции с самостоятельной проверкой | Основной путь работает | Согласованный объём |
| MOBILE-01 | Будущее развитие идеи команды вне оцениваемого минимума | Отдельное решение | Развитие |

После контрактов можно разделять веб и сервер. WEB-01, ORG-01 и ADMIN-01 получают
непересекающиеся файлы; общие маршруты, зависимости и UI имеют одного владельца.
Реальная схема каталогов ещё не выбрана.

Шесть сценариев не исчерпывают постановку: обязательны также вход/регистрация,
административный поиск, модерация сообщения и комплект сдачи.
Карта, вместимость, real-time и полная авторизация не должны задерживать базу.
Нативное приложение не требуется и не приносит дополнительных баллов.
