# Очередь разработки по первичным источникам

Основание: [постановка и критерии](../requirements/README.md).
Реализация не начата; исполнители не назначены. Импорт PDF, спецификация
и [приёмка](../product/acceptance.md) подготовлены.

**Исполнителю назначается отдельная карточка из [детальной очереди](tasks/README.md),
а не весь крупный раздел таблицы ниже.** Подготовлена 41 небольшая задача с
зависимостями, границами файлов, наблюдаемым результатом и проверками.
Все задачи запланированы; активных назначений и выполненной реализации нет.

Подробные [технические предложения](../architecture/README.md),
[проект API](../contracts/api-proposal.md) и [план реализации](implementation-plan.md)
зафиксированы; [ADR-001](../architecture/backend-decision.md) утвердил бэкенд Go
и обязательную [контейнеризацию](containerization.md). Это частичное закрытие
выбора технологий ARCH-01, а не завершённая реализация. [Карта экранов](../product/screens.md) и
[пути](../product/user-flows.md) дополняют предложение. По следующему поручению
[API 0.13.0](../contracts/api-v1.md) зафиксировал DTO/права/переходы. CONTRACT-01
подготовлен на уровне спецификации и проверенной генерации; интеграция с API/БД
ещё не выполнена. PLAN-01/UX-01/ARCH-01 остаются подготовкой к выполнению:
повторно согласовывать уже зафиксированные правила DEC/API не нужно. Незавершены
общая сборка, назначения, демонабор и прикладная проверка; это не новые вопросы
о ролях/статусах и не разрешение начать реализацию.

По отдельному поручению создан [дизайн-прототип 0.2](../../design/prototype/README.md)
всех 18 предлагаемых маршрутов. Это частичный результат UX-01;
согласование, состояния операций и расширенные проверки доступности ещё открыты.
Задачи разработки приложения этим макетом не закрываются.

[Повторная проверка экранов](../product/screen-review.md) и [покрытие 0.2](../../design/prototype/coverage.md)
уточняют остаток UX-01. Кабинеты организаций и оба административных списка с
деталями связаны; нужно дополнить контуры отправкой/сетевыми ошибками/неизвестным
результатом и проверить реальные устройства/доступность.
[Первый визуальный проход](../../design/reviews/2026-10-19/README.md) выполнен: 18 экранов
на 390/1280, ключевые страницы на 320/768. Всё это внесено после коммита `2a267ee`.
Правило начавшихся встреч принято: [DEC-01/02](../product/decisions.md).
API 0.13.0 закрывает запись/решения при начале; реализация и граничные проверки
входят в BE-07, FE-04/08/09, QA-01. Открытым этот вопрос больше не считается.

После контрактов можно разделять веб и сервер. WEB-01, ORG-01 и ADMIN-01 получают
непересекающиеся файлы; общие маршруты, зависимости и UI имеют одного владельца.
Go-модуль, миграции и контейнерная среда также имеют одного назначенного владельца.
Будущая схема каталогов предложена в техническом проекте; запуск агентов не выполнен.
INFRA-01 выполняется на первом этапе, а не перед финальной сдачей. S3 исключён.
Личные загрузки/фоны [MEDIA-01](../architecture/media.md) идут после основного
контура, но по DEC-12 готовые SVG/MEDIA-01F обязательны до QA-01: без них
регистрация недоступна. По DEC-22 исходники уже есть
в [стартовом наборе](../../design/assets/README.md); ожидание файлов снято,
остаются проверка MEDIA-00 и интеграция MEDIA-01F.

Шесть сценариев не исчерпывают постановку: обязательны также вход/регистрация,
административный поиск, модерация сообщения и комплект сдачи.
Карта, вместимость, real-time и полная авторизация не должны задерживать базу.
Нативное приложение не требуется и не приносит дополнительных баллов.

Дополнение DEC-20/21: вместо демовыбора принят email/пароль с JWT и серверным
отзывом. AUTH-01 → BE-02 задают общую авторизацию; BE-13/FE-15 — блокировка USER
в SCR-22, оба до QA-01. Подробная очередь содержит 44 карточки, API 0.13.0.
