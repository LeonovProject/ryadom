Идентификаторы при полном сбросе новые, demoKey/email/демопароли стабильны, все три основных доступа ACTIVE. Обычный seed остаётся явным и не затирает данные; разрушительное удаление делает только операция сброса. demo_state/миграции не удаляются сидом.
- DEC-14: у демопользователя есть подтверждённые будущие планы и отдельная начавшаяся сегодня в зоне события встреча. Для проверки порядка нужны ближняя встреча со старой записью и дальняя с новой, одинаковые startsAt, а также PENDING/REJECTED/UNPUBLISHED вне ближайших планов. Временные граничные наборы проверяются с управляемыми часами; штатный сид остаётся относительным к демонстрации. Не заменять этим свободную встречу/заявку, на которые эксперт ещё должен записаться самостоятельно.
- DEC-08: отдельные OPEN на встречу и сообщения, закрытые RESOLVED/DISMISSED, HIDDEN для восстановления и VISIBLE после восстановления с согласованными версиями/датами. Остаются свежие цели для подачи/дублей от демоаккаунта; собственные цели им не заменять.
- DEC-07: готовые направления APPROVED/is_seeded=true; отдельные пользовательские PENDING для обеих веток, REJECTED с причиной и связанные встречи. Эти имитации пользовательского ввода имеют is_seeded=false и создателя, хотя вставляются seed-скриптом.

- Результат: Сервер chi, конфигурация, соединение с PostgreSQL, health/live и health/ready, requestId, единый JSON ошибок, ограничения тела и проверка Origin; место регистрации предметных модулей.
- DEC-13: общий транзакционный барьер demo_state задаётся сейчас: FOR SHARE первым до предметных блокировок, авторитетная проверка сессии/роли после него. Reset использует FOR UPDATE и повторно проверяет ADMIN после ожидания. Обработчики получают единую транзакционную оболочку, не обходят её собственным подключением. Healthcheck/статика исключены; ответственность передаётся всем исполнителям до начала модулей.
- Оболочка различает public / optional-session / session / event-owner / organization-owner / admin из OpenAPI. Public не требует сессии и не использует присланную cookie; optional-session допускает отсутствие cookie, неверная/истёкшая даёт 401, JWT BLOCKED — 403 с очисткой cookie. AUTH-01/BE-02 подключают общий guard ACTIVE/sessions до предметных модулей. Барьер чтения сам по себе не делает публичный маршрут защищённым. Синтаксис JSON/query/пути — 400, ошибки полей/неизвестных свойств тела — 422 по контракту; сгенерированные типы/интерфейсы не заменяют валидацию и единый формат ошибок.
- Приёмка и проверки: Жизнь процесса не зависит от БД; готовность зависит. Ошибки/Origin/лимиты проверены. Пока нет обработчиков бизнес-сценариев. Полную проверку образа завершает OPS-01.
- Операции контракта: liveness, readiness.
