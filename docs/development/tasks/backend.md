# Серверные задачи

BE-02 реализована и проверена: [отчёт](../../../apps/api/internal/modules/auth/README.md).
Остальные серверные карточки этого файла ещё впереди. Один раздел — одна
отдельная задача для исполнителя. Правила назначения и общие ограничения —
[в очереди](README.md). Ниже указаны будущие пути; код приложений пока отсутствует.

Контракт 0.13.0 и [DEC-01](../../product/decisions.md) обязательны: BE-03 вычисляет
canDecideParticipations и EVENT_STARTED в карточке, сохраняя чтение состава;
BE-07 проверяет актуальное время после блокировок. Проверка UI не заменяет серверную.

## BE-02 — Вход, JWT-сессии и аккаунты

- Родительская область: API-01.
- Зависимости: AUTH-01, DB-02, OPS-01.
- Владелец / исходный SHA / ветка: назначает координатор перед запуском.
- Область файлов: apps/api/internal/modules/accounts/** и auth/**, общий читатель готового manifest; db/queries/accounts.sql, account_avatars.sql, sessions.sql — у единого владельца БД. Общая регистрация обработчиков через координатора.
- Результат: Вход/регистрация/выход, текущий и публичный аккаунт работают по контракту. Cookie-сессия 24 часа, хеш токена в БД, роли не назначаются входными данными.
- DEC-20/21: email/пароль, Argon2id/JWT из AUTH-01, UNIQUE email, приватный email в Me, isBlocked публично. Вся общая авторизация проверяет ACTIVE/sessions под accounts FOR SHARE после барьера, до предметных замков. Ошибки/лимиты/claims — authentication.md. Прежние demo-маршруты не регистрируются; блокировка ADMIN реализуется отдельно в BE-13.
- Приёмка и проверки: Два независимых контекста; истечение/выход/смена профиля, запрет повышения роли, Origin. Cookie проходит через Compose proxy. В API полного публичного профиля нет systemRole.
- DEC-11: register требует непустой presetId. Одним commit создаются USER/аватар/сессия: только с допустимым ID PRESET/APPROVED/1; пропуск/null отклоняются. Неизвестный ID/неверное имя не создают ничего и не заменяют прежнюю сессию; Cookie после commit. Регистрироваться с личным SVG/ролью/URL нельзя. Публичный avatarUrl выбранного PRESET доступен сразу. listAvatarPresets и разрешение ID/URL из общего manifest реализуются здесь, без зависимости от поздней MEDIA-01A.
- Проверка DEC-11: имя+готовый, запрет пропуска/null, блокировка при пустом manifest, ошибочный/исключённый ID, атомарность/сохранение данных, согласованный ответ Me с картинкой. При таймауте нет автоматического повторного создания; getMe показывает текущую сессию, не доказывает выполнение именно потерянного запроса.
- DEC-13: auth/login/register/logout и чтения аккаунта/сессии используют общий барьер BE-01, затем проверяют свежую сессию. Во время сброса не создают новый профиль/сессию поверх удаления; старый токен после сброса SESSION_EXPIRED. Барьер нужен уже в этом этапе, а не добавляется попутно разными модулями.
- Операции контракта: login, register, logout, getMe, getAccount, listAvatarPresets.
- Вне задачи: другие карточки, независимые изменения OpenAPI, зависимости/миграции вне владения и публикация без поручения.

## BE-03 — Каталог и чтение встреч

- Родительская область: API-01.
- Зависимости: BE-02.
- Владелец / исходный SHA / ветка: назначает координатор перед запуском.
- Область файлов: apps/api/internal/modules/events/** (чтение); db/queries/events.sql, activity_types.sql через владельца БД.
- Результат: Направления, каталог, карточка и собственный список событий. Фильтры и курсоры, публичный и ограниченный DTO. Запросы не создают события.
- Приёмка и проверки: Фильтры до пагинации, пустая выдача, неверный курсор, чужой личный ресурс. Снятое событие не раскрывает закрытые поля; проверка на настоящей PostgreSQL через Compose.
- DEC-21: OrganizationOrganizer.ownerIsBlocked читается из текущего ответственного без изменения допуска/публикации; PersonalOrganizer.account.isBlocked задаёт недоступность личного автора.
- Операции контракта: listActivityTypes, listEvents, getEvent, listMyEvents.
- DEC-19: listEvents.dateFrom/dateTo сравнивают календарную дату startsAt в timezone каждой встречи, нижняя граница включительна/верхняя исключительна. from/to — независимые моменты, все условия AND до LIMIT и входят в курсор. Проверить разные зоны при одинаковом UTC-моменте, местную полночь, реальную валидность дат/диапазона, сочетание с from и смену фильтра со старым курсором. Копия локальной даты в БД не создаётся.
- DEC-07: listActivityTypes только APPROVED; поиск/фильтр событий без ограничения catalogStatus. activityTypeReview — автору опубликованной встречи, остальным null. Чтение направлений выделяется в modules/activitytypes/** с единым владельцем SQL.
- Вне задачи: другие карточки, независимые изменения OpenAPI, зависимости/миграции вне владения и публикация без поручения.

## BE-07 — Запись и решения по участию

- Родительская область: API-01.
- Зависимости: BE-04.
- Владелец / исходный SHA / ветка: назначает координатор перед запуском.
- Область файлов: apps/api/internal/modules/participation/**; queries/participations.sql через владельца БД.
- Результат: OPEN сразу подтверждает, APPROVAL ожидает; свои записи, список автора, принятие/отказ. Повтор не создаёт дубль и не сбрасывает REJECTED.
- Приёмка и проверки: S3/S4, два клиента, обе ветки; чужой автор и ADMIN без авторства не решают заявки. Проверены повтор и конкурентная запись с UNIQUE на PostgreSQL.
- Операции контракта: joinEvent, listMyParticipations, listEventParticipations, decideParticipation.
- DEC-14: listMyParticipations получает eventWindow/referenceTime по контракту. JOIN с events, только PUBLISHED в окнах UPCOMING/STARTED_TODAY, startsAt/event.id ASC до LIMIT; общий момент двух блоков и всех страниц. Без окна — прежний полный список/ограниченные UNPUBLISHED. Проверить ближайшую запись за первой страницей старого порядка, равные startsAt, границу начала/полуночи в разных зонах и INVALID_CURSOR при смене окна/опорного времени. Нельзя использовать referenceTime вместо актуального now для записи/решений.
- DEC-15: третье окно STARTED — все startsAt <= referenceTime, только PUBLISHED, startsAt/event.id DESC до LIMIT. Точное равенство включено, при одинаковом старте ID тоже DESC. Курсор сохраняет направление; не применять ASC из двух окон главной. Прежняя выдача без окна нужна режиму «Все записи» с ограниченными UNPUBLISHED, а не является экранным default «Участвую».
- Уточнение DEC-01 / API 0.13.0: после блокировок актуальное now >= startsAt даёт EVENT_STARTED до повтора, для обоих режимов и обеих веток решения. Проверить -1 мс/равенство/+1 мс и ожидание блокировки через начало; БД не меняется при отказе. PENDING сохраняется, чтение состава остаётся доступным. BE-03 формирует canDecideParticipations и приоритет joinBlockedReason=EVENT_STARTED.
- Вне задачи: другие карточки, независимые изменения OpenAPI, зависимости/миграции вне владения и публикация без поручения.

## BE-08 — Обсуждение и скрытие одного сообщения

- Родительская область: API-01 / ADMIN-01.
- Зависимости: BE-04.
- Владелец / исходный SHA / ветка: назначает координатор перед запуском.
- Область файлов: apps/api/internal/modules/discussion/**, moderation/messages/**; queries/messages.sql через владельца БД.
- Результат: Вопрос/ответ без обязательной записи. Публичное HIDDEN без body, административное чтение с оригиналом; скрытие сохраняет событие и остальное обсуждение.
- Приёмка и проверки: S5/A3, различимое авторство, вопрос незаписанного человека, отсутствие утечки body даже автору/ADMIN на публичном маршруте; повтор скрытия безопасен.
- Контракт DEC-08 обязателен уже здесь: hide принимает expectedRevision, AdminMessage содержит счётчики/версии и nullable restoredAt/By. Скрытие закрывает OPEN-жалобы сообщения в той же транзакции (таблица из DB-01); BE-11 добавляет подачу/разбор/восстановление. Нельзя временно реализовать прежний bodyless hide.
- adminListMessages.hasOpenReports и реальные счётчики/версии реализуются здесь, до BE-11: DB-02 уже содержит жалобы. Фильтр до LIMIT и входит в курсор; статические нули вместо данных недопустимы. SQL закрытия/подсчёта предоставляет единый владелец БД, BE-11 переиспользует его. Проверить скрытие сообщения с OPEN-жалобами из штатного сида.
- Операции контракта: listMessages, createMessage, adminListMessages, adminHideMessage.
- DEC-18: listMessages.order=NEWEST_FIRST — createdAt/id DESC и курсор к ранним; API default OLDEST_FIRST остаётся ASC. Порядок связан с курсором, при равном времени ключ id следует тому же направлению. adminListMessages остаётся ASC. Проверить обсуждение больше одной страницы, HIDDEN без body и новые сообщения между страницами; не возвращать две версии одного ID в одной странице.
- Вне задачи: другие карточки, независимые изменения OpenAPI, зависимости/миграции вне владения и публикация без поручения.

## BE-09 — Поиск и снятие событий

- Родительская область: API-01 / ADMIN-01.
- Зависимости: BE-07, BE-08, BE-06.
- Владелец / исходный SHA / ветка: назначает координатор перед запуском.
- Область файлов: apps/api/internal/modules/moderation/events/**; снятие использует общую операцию events; общие SQL-изменения у владельца БД.
- Результат: Административный поиск/карточка, снятие с причиной и ограниченная видимость. Запись, вопрос, решение и смена фона блокируются состоянием на сервере.
- Приёмка и проверки: S6/A2, прямая ссылка, причина нужному автору, сохранность старых записей. Гонка снятия/записи допускает оба законных порядка; проверены повторы причин.
- DEC-08: AdminEvent содержит реальные счётчики и eventReportsRevision; hasOpenReports реализуется здесь до пагинации, учитывает прямые жалобы и жалобы сообщений. Снятие атомарно закрывает только прямые OPEN-жалобы как RESOLVED, сообщения не затрагивает. BE-11 добавляет подачу/разбор/восстановление и переиспользует готовые фильтры/закрытие, не создаёт вторую версию снятия. Проверить OPEN из DB-02 до готовности BE-11; причины снятия остаются обязательными.
- Операции контракта: adminListEvents, adminGetEvent, adminUnpublishEvent.
- DEC-07: adminListEvents принимает activityTypeId и возвращает связанные события всех состояний публикации по фильтрам. Параметр входит в область курсора; это связанный список для SCR-20.
- Вне задачи: другие карточки, независимые изменения OpenAPI, зависимости/миграции вне владения и публикация без поручения.
