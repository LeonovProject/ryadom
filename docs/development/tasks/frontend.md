# Задачи интерфейса

Все карточки — **запланированы, не назначены и не начаты**. Один раздел — одна
отдельная задача для исполнителя. Правила назначения и общие ограничения —
[в очереди](README.md). Ниже указаны будущие пути; код приложений пока отсутствует.

Для FE-03/04/05 и кабинетных списков применяется [DEC-02](../../product/decisions.md):
общее форматирование начала в зоне встречи с явным GMT/UTC-смещением на её дату.
FE-04/08/09 используют API 0.13.0 и раздельные права чтения состава/решений.
По DEC-07 FE-03 показывает только одобренный общий список, сохраняя фильтр
по известному ID любого состояния. FE-04 показывает activityTypeReview только
автору опубликованной встречи; FE-05 позволяет свой спорт без ожидания проверки.
SCR-20 и административные действия выполняются отдельно в FE-12.

## FE-02 — Вход и состояние текущего аккаунта

- Родительская область: WEB-01.
- Зависимости: FE-01, OPS-01.
- Владелец / исходный SHA / ветка: назначает координатор перед запуском.
- Область файлов: apps/web/src/features/auth/**, accounts/private/** для базового SCR-08; подключение общих провайдеров выполняет координатор. Последующие блоки MEDIA-01D/FE-14 подключаются через координатора, базовая страница не переписывается параллельно.
- Результат: Отдельные экраны входа/регистрации и базовый личный кабинет SCR-08: имя/аватар, публичный профиль, прямые ссылки на свои встречи/организации/создание и модерацию по роли. Выход, getMe, смена профиля и очистка персонального кеша. Проверяемые email/пароль и JWT-cookie по DEC-20, состояния 401/403 ACCOUNT_BLOCKED/429, очистка кеша; загрузка своего SVG/демосброс здесь ещё не реализуются.
- Приёмка и проверки: По фикстурам — успех/401/ошибка; после BE-02 — cookie через proxy и независимые контексты. Вопрос/запись после входа не выполняются автоматически.
- DEC-11: SCR-07 — одна страница с именем/email/паролем/клиентским подтверждением, обязательным готовым аватаром/предпросмотром, без автовыбора/пропуска. Выбор локален до одного register; без второго запроса selectPresetAvatar. Пустой/ошибочный каталог блокирует создание профиля, вход существующим аккаунтом доступен, недоступный выбранный ID не сбрасывается молча, имя сохраняется. Свой SVG только позже в SCR-08. После 201 — безопасный returnTo либо / (DEC-16); getMe после таймаута не выдаётся за доказанное создание. Клавиатура/диктор/телефон, отправка/ошибка/пустота и запрет автоповтора POST проверяются.
- DEC-20/21: повторный вход в созданный аккаунт, менеджер паролей, EMAIL_TAKEN, Retry-After, без localStorage/поля токена/автовыдачи роли. После неопределённой регистрации доступен явный login. BLOCKED защищённого/optional-session запроса очищает личный кеш, оставляя объяснение; отказ нового login не заменяет прежнюю сессию; публичное чтение гостем доступно.
- Операции контракта: login, register, logout, getMe, listAvatarPresets.
- DEC-16: после подтверждённого входа/регистрации допустимый returnTo имеет приоритет, иначе `/` — персональная главная. Прежние default `/events` и `/me` заменены. Истёкшая/ошибочная сессия не вызывает успешный переход; автоматической записи/вопроса/жалобы нет. Сам личный блок подключается в FE-08.
- Вне задачи: другие карточки, независимые изменения OpenAPI, зависимости/миграции вне владения и публикация без поручения.

## FE-03 — Главная и каталог

- Родительская область: WEB-01.
- Зависимости: FE-02.
- Владелец / исходный SHA / ветка: назначает координатор перед запуском.
- Область файлов: apps/web/src/features/events/catalog/**, apps/web/src/home/**; общие маршруты подключает координатор.
- Результат: Гостевая главная, каталог, поиск, фильтры, URL-параметры и карточки. Направления из API, загрузка/ошибка/пустота/продолжение списка. Для персональной главной готовится место подключения блока, который реализуется отдельно в FE-08; отсутствие этого блока не выдаётся за пустой результат личного API.
- Приёмка и проверки: 390/1280 и граничные 320 px; поиск сохраняет фильтры, пустой город не ограничивает выдачу. После BE-03 — работа на реальном API.
- Операции контракта: listEvents, listActivityTypes.
- DEC-19: фильтр явной календарной даты/диапазона отправляет dateFrom/dateTo, с подписью «По местной дате встречи». Одиночный день — [день, следующий день), включительная верхняя дата UI переводится в следующий календарный день. Не преобразовывать date-only через зону устройства/Date.toISOString. В каталоге будущих from остаётся отдельным условием AND; смена дат сбрасывает курсор. Пресет «Сегодня» с новой семантикой не вводится без отдельного правила.
- DEC-14/15: личный блок и его выборки принадлежат FE-08, чтобы FE-03 не имела второго незакрытого этапа после BE-07. Общая оболочка/навигация и место подключения согласуются с координатором. Гостевой hero сохраняется; mock личного блока не является приёмкой этой функции.
- Вне задачи: другие карточки, независимые изменения OpenAPI, зависимости/миграции вне владения и публикация без поручения.

## FE-05 — Создание встречи

- Родительская область: WEB-01.
- Зависимости: FE-04.
- Владелец / исходный SHA / ветка: назначает координатор перед запуском.
- Область файлов: apps/web/src/features/events/create/**.
- Результат: Шаги формы, свой вид спорта, выбор допустимого автора, проверка, ошибки и предупреждение о потере введённого. Успех только после ответа API.
- Приёмка и проверки: Полный S1 после BE-04; вторая сессия находит результат. При неопределённом ответе POST автоматически не повторяется. Проверены телефон и сохранение формы при ошибке.
- Операции контракта: getMe, listActivityTypes, createEvent.
- DEC-02: datetime-local интерпретируется в выбранной IANA-зоне встречи, затем превращается в абсолютный startsAt. new Date(value) для ввода без смещения использует зону устройства и не заменяет это преобразование. Сводка показывает полученные дату/время/смещение перед публикацией. Невозможное или неоднозначное сезонное локальное время не исправляется молча: форма просит выбрать однозначное время. Проверить создание из браузера с другой зоной, не только форматирование полученного UTC.
- Вне задачи: другие карточки, независимые изменения OpenAPI, зависимости/миграции вне владения и публикация без поручения.

## FE-08 — Запись и мои активности

- Родительская область: WEB-01.
- Зависимости: FE-05.
- Владелец / исходный SHA / ветка: назначает координатор перед запуском.
- Область файлов: apps/web/src/features/participation/user/**, participation/home/**, events/mine/**. Подключение личного блока к завершённой оболочке home FE-03 выполняет координатор; общие файлы не редактируются параллельно.
- Результат: Свободная запись/заявка, собственный статус, вкладки моих участий/заявок/созданных и личный блок главной. Снятая встреча отличается от отклонённого участия.
- Приёмка и проверки: После BE-07 — S3 и пользовательская сторона S4. Двойное нажатие, 409/401, повторное чтение и переходы с сохранением каталога; без оптимистического подтверждения.
- Операции контракта: joinEvent, listMyParticipations, listMyEvents, getEvent.
- DEC-14: на главной до трёх будущих CONFIRMED/PUBLISHED, затем компактно начавшиеся сегодня. UPCOMING/STARTED_TODAY используют один referenceTime и серверный порядок до LIMIT; nextCursor не означает total. Загрузка/ошибка/пустота раздельны, на телефоне ближайшая карточка видна без длинного hero. При смене аккаунта/сбросе очищаются оба окна и полный список, после своей записи перечитываются. Общие ключи кеша/API-клиент — через координатора.
- Граница времени DEC-01 применяется и к личным выборкам: при ближайшем startsAt и смене дня в зоне показанных сегодняшних встреч читать оба блока заново с новым referenceTime и без старых курсоров; также при возврате во вкладку и явном обновлении. Не переносить строки только локальной сортировкой старых страниц и не оставлять начавшуюся встречу в «Предстоящих» до перезагрузки браузера. Таймер — удобство, сервер задаёт опорное время и права; realtime/постоянный polling не добавляются.
- DEC-15: tab=confirmed, view=upcoming по умолчанию — CONFIRMED/UPCOMING ASC; view=started — CONFIRMED/STARTED DESC; видимая ссылка «Все записи» (view=all) без окна — все даты и createdAt/participation.id DESC, включая ограниченные UNPUBLISHED. Смена вида сбрасывает курсор. PENDING/REJECTED отдельно, «Начавшиеся» не означает завершение/посещение. Фикстуры и затем реальный API BE-07; фронтенд не пересортировывает одну страницу для поиска ближайших.
- Уточнение DEC-01/02: в начавшуюся встречу запись закрыта, 409 EVENT_STARTED обновляет карточку/своё участие. PENDING с пояснением о нерассмотренной до начала заявке, без автоматического отказа; время в зоне встречи с подписью. Проверить смену состояния открытой страницы на границе.
- Вне задачи: другие карточки, независимые изменения OpenAPI, зависимости/миграции вне владения и публикация без поручения.

- DEC-21: перед APPROVAL-заявкой на встречу недоступного организатора — пояснение, что автор временно не может ответить; сама запись остаётся доступна по прежним правилам, свободный режим подтверждается обычно.

## FE-10 — Вопросы и ответы в карточке
