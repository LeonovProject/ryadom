# Восстановление штатного демонабора из аккаунта ADMIN

Карточки **запланированы, не назначены и не начаты**. Основание —
[DEC-13](../../product/demo-reset.md), API 0.13.0. Здесь нет команды сбросить БД
или начать разработку. Каждая карточка назначается отдельно.

## BE-12 — Состояние демобазы и атомарный сброс

- Родительская область: DEMO-RESET-01.
- Зависимости: BE-09, BE-10, BE-11.
- Владелец / исходный SHA / ветка: назначает координатор перед запуском.
- Область файлов: apps/api/internal/modules/admin/demoreset/**; вызов единого seed/репозиториев, SQL только через владельца БД. Общий барьер уже задан BE-01/02; его применение в модулях проверяет координатор.
- Результат: adminGetDemoState/adminResetDemoData только ADMIN+DEMO_MODE, проверка Origin/слова/generation/seedVersion/resetId, фиксированное транзакционное удаление/seed, новая generation и квитанция. Все сессии завершаются, cookie очищается после commit. Новые UUID, стабильные demoKey, даты сида по Красноярску. Нет shell/DROP/TRUNCATE или клиентского SQL.
- Приёмка и проверки: полный чек-лист demo-reset.md на PostgreSQL/Compose: права/режим/ввод, потеря ответа/повтор, два администратора, ожидание общего барьера и конкурентный бизнес-запрос/вход по email/паролю, ошибка seed с полным rollback. Все десять предметных таблиц возвращаются к сиду, demo_state сохраняется; квитанция после повторного входа и перезапуска, старые ID/сессии не работают. Результат операции не имитируется.
- Операции контракта: adminGetDemoState, adminResetDemoData; затронуты общий seed/авторизация/транзакции.
- Вне задачи: UI, резервные копии, выбор чужого дампа/даты/SQL, частичный reset, удаление тома, переписывание миграций и сброс общей среды без отдельного поручения на проверку.

## FE-14 — Сброс в личном кабинете администратора

- Родительская область: DEMO-RESET-01.
- Зависимости: FE-11.
- Владелец / исходный SHA / ветка: назначает координатор перед запуском.
- Область файлов: apps/web/src/features/admin/demoreset/**; интеграция блока SCR-08/диалога/очистки кеша через координатора. Нового URL нет.
- Результат: блок «Демоданные» только ADMIN при доступном adminGetDemoState, версия/дата/последствия, ввод СБРОСИТЬ, один POST со свежими версиями/resetId. После подтверждения — очистка кеша/форм, вход заново.
- Приёмка и проверки: фикстуры 0.13.0, затем BE-12 через Compose. USER/выключенный режим без кнопки, телефон/клавиатура/фокус. Нет автоматического retry или подстановки свежей generation в старую команду. Потерянный ответ восстанавливается по сохранённому resetId после входа ADMIN по email/паролю, stale/busy/rollback не показывают успех. Другие вкладки получают 401 при следующем обращении; старые формы не выполняются от нового аккаунта.
- Операции контракта: adminGetDemoState, adminResetDemoData; login/getMe после сброса.
- Вне задачи: собственный seed, новая страница администратора, журнал/экспорт/отмена сброса, изменение контракта и сброс общей среды без отдельного поручения на проверку.
