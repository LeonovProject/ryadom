# Передача: первая встреча и печатное приглашение

Порядок назначения/подключения уточнён [пакетным процессом](../handoff/work-packets.md):
карточки можно выполнять последовательно в одном назначенном пакете; обычные
подключения API/экранов выполняет единственный владелец стороны. Прежнее
требование передавать каждую регистрацию координатору заменено; общие
контракты/зависимости/бренд остаются у COORDINATOR.

Подготовлено 20 октября 2026 по поручению пользователя, DEC-25. Это четыре
отдельные карточки **PLANNED**, исполнители не запущены. Спецификации:
[помощник](../../product/first-meeting-helper.md) и
[приглашение](../../product/printable-invitation.md). API 0.13.0/БД прежние.

Координатор назначает ограниченный пакет карточек либо отдельную карточку
с фактическим SHA, отдельной веткой/
worktree и проверкой git status. Спецификации включены в
[общую точку продолжения](../handoff/continuation-2026-10-20.md) вместе с DEC-24/26.
Брать точный SHA её коммита, переданный координатором; прежний HEAD без
пакета этих материалов не содержит. Реализация по-прежнему назначается отдельно.

Статус SPECIFIED не означает реализацию или включение в финальный показ.
Это отдельные подготовленные улучшения, не молчаливое расширение старой QA-01
и не сокращение уже согласованного объёма DEC-17. Для заявления об их готовности
нужна QA-02; решение о назначении принимает пользователь/координатор.

## QR-01 — Локальная генерация QR для приглашения

- Родительская область: подготовленные улучшения DEC-25 / общая основа.
- Зависимости: BASE-01, FE-01.
- Владелец роли: COORDINATOR. Исходный SHA / ветку назначает координатор.
- Область файлов: package.json, pnpm-lock.yaml, apps/web/package.json при необходимости; новый apps/web/src/shared/qr/**. Общие конфигурации менять только если без этого не собирается результат.
- Результат: локальная закреплённая библиотека с подходящей лицензией и createInvitationQr(url: string): Promise<string> → PNG data URL. QR: M, свободное поле 4 модуля, 512×512, чёрный/белый. Без сетевого сервиса/CDN. Версию/лицензию и способ подключения записать в README модуля.
- Приёмка и проверки: проверка типов/сборка и воспроизводимое независимое декодирование результата в исходную ссылку. Проверить длинный origin, пустой/ошибочный ввод и отказ генератора. Результат доступен в веб-образе без загрузки внешнего JS.
- Контракт передачи FE-17: передать путь импорта, закреплённую версию и способ обработки ошибки до интеграции. Модуль не читает URL вкладки и не выбирает встречу.
- Вне задачи: страницы/печать, сканер QR, сокращение URL, OpenAPI, БД и изменения старого макета.

## FE-16 — Помощник условий первой встречи

- Родительская область: подготовленные улучшения DEC-25 / продолжение FE-05.
- Зависимости: FE-05.
- Владелец роли: FRONTEND. Исходный SHA / ветку назначает координатор.
- Область файлов: apps/web/src/features/events/create/**. Не менять detail/**, app/**, общие зависимости, API/SQL и токены брендбука.
- Результат: сворачиваемые необязательные вопросы, предпросмотр и явное добавление в conditions по спецификации; обратная совместимость клиентского EventDraft.
- Приёмка и проверки: все пункты спецификации помощника; содержательные unit-тесты сборки/лимитов, браузерная проверка применения/переходов/черновика/ошибок. Обязательные поля и ограничения pending/uncertain не обходятся. Нет нового HTTP-поля и лишнего POST.
- Операции контракта: существующие createEvent/getEvent; реальное сохранение и второй читатель — в QA-02 после BE-04.
- Передача: показать изменённый shape клиентского EventDraft, пример окончательного conditions, проверки и ограничения. FE-17 использует обычную строку и не зависит от готовности FE-16.
- Вне задачи: новая страница, подсказки через AI, автоматические обещания подготовки, парсинг условий, обязательный возраст/здоровье, редактирование опубликованной встречи.

## FE-17 — Предпросмотр и печать приглашения

- Родительская область: подготовленные улучшения DEC-25 / продолжение FE-04.
- Зависимости: FE-04, QR-01.
- Владелец роли: FRONTEND. Исходный SHA / ветку назначает координатор.
- Область файлов: новый apps/web/src/features/events/invitation/** и точечное подключение в apps/web/src/features/events/detail/EventPage.tsx. shared/qr/** только читать; app/**, общие CSS, API/SQL/lock не менять.
- Результат: вторичное действие карточки, доступный предпросмотр со свежим getEvent, локальный QR и печать только приглашения; без нового маршрута и POST.
- Приёмка и проверки: вся спецификация приглашения. Unit-тесты канонического URL/выбора публичных полей/обрезания description; браузерные проверки OPEN/APPROVAL, прав, ошибок, начала/снятия, фокуса и печатного CSS. Сохранить PDF короткого/предельного случаев, просмотреть все страницы и независимо считать QR.
- Операции контракта: getEvent, чтение и привычный переход в карточку. Приглашение не использует canJoin как право печати и не превращает просмотр/печать в запись.
- Передача: снимки предпросмотра и печати, точный URL из декодированного QR, примеры режимов/ошибок, ограничение устаревающей бумаги. Контейнерная приёмка с реальным API — QA-02.
- Вне задачи: изменение формы создания, сервер PDF/загрузок, внешняя рассылка/публикация, сбор получателей, новые фоны или самостоятельное развёртывание.

## QA-02 — Проверка первого знакомства и печатного приглашения

- Родительская область: подготовленные улучшения DEC-25 / дополнительная приёмка.
- Зависимости: FE-16, FE-17, BE-04, BE-09.
- Владелец роли: QA. Исходный SHA / ветку назначает координатор.
- Область файлов: tests/e2e/first-meeting/**, docs/development/validation/first-meeting/**. Исправления приложения возвращать владельцам; зависимости/инфраструктуру ведёт координатор.
- Результат: реальные createEvent/getEvent/снятие в Compose, два независимых контекста и листок с проверенным QR; факты отделены от фикстур и сетевых проверок после развёртывания.
- Приёмка и проверки: человек/допущенная организация, оба режима, ручные условия/помощник/пустые условия, другая зона браузера, 4000 символов и многостраничная печать, повтор/ошибка/старый предпросмотр, сохранение данных с прежним томом. QR читается в точную ссылку; открытие/печать не создают участия. После снятия сохранённая ссылка не разрешает новую запись. Смена аккаунта не переносит черновик или приватные поля.
- Граница отчёта: локальная ссылка 127.0.0.1 не считается проверенной с телефона. После пользовательского развёртывания сетевую часть повторяет DELIVERY-01B. Не утверждать, что человек посетил встречу или бумага напечатана, по факту открытия диалога.
- Вне задачи: новый балльный критерий, сброс общей БД, произвольная публикация, подмена реальных операций моками.

## Порядок и пересечения

QR-01 и FE-16 имеют непересекающиеся файлы; после QR-01 FE-17 может идти
параллельно FE-16. У FE-17 пересечение с FE-04/FE-10/FE-13/другими владельцами
EventPage.tsx: подключение назначить одному исполнителю, остальные передают
конкретный патч координатору. Не менять файл одновременно. Форма помощника
и печатный модуль связаны только стандартным conditions API 0.13.0.

После готовности обоих — QA-02. До запуска каждой карточки повторно сверить
фактические изменения и владельцев, а не ориентироваться на один старый SHA.
