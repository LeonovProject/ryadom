## AUTH-01 — JWT, хеширование пароля и ограничения попыток

- Родительская область: API-01 / ARCH-01.
- Зависимости: BE-01, DB-01.
- Владелец / исходный SHA / ветка: назначает координатор перед запуском.
- Область файлов: apps/api/internal/platform/authn/**. Версии библиотек, конфигурацию/окружение и общие зависимости подключает координатор; SQL/migrations не меняются этой карточкой.
- Результат: Argon2id PHC с параметрами/случайной солью, проверка пароля, выпуск/валидация JWT с фиксированным алгоритмом/typ/claims и управляемыми часами; SHA-256 токена. Общие ограничители login/register и трактовка доверенного IP; секрет только в API, не по умолчанию. Нет HTTP-эндпоинтов/назначения роли/самостоятельной копии схем DTO.
- Приёмка и проверки: Правильный/неверный пароль, разные соли одного пароля, Unicode/пробелы без trim, повреждённый PHC; неподходящий alg/typ/iss/aud/sub/jti/exp/iat, подделка и граница exp. Проверка конфигурации ключа; воспроизводимые проверки ограничений окон/TTL/Retry-After с управляемыми часами без реального ожидания, недоверенный forwarding-IP. Пароли/токены/секреты не логируются. Проверка sessions/ACTIVE и транзакционный guard принадлежат следующей BE-02, криптография сама не даёт доступа.
- Передача: Координатор подключает настройки AUTH_JWT_SECRET и библиотек; BE-02 использует единый интерфейс этих средств. Приёмка не объявляет готовность реального входа до BE-02/FE-02 и Compose-проверки.
- Операции контракта: —; общие средства для login/register и всех защищённых маршрутов.
- Вне задачи: предметные операции, административная блокировка, независимые изменения OpenAPI, публикация и запуск следующей карточки без назначения.
