# Жалобы на встречи и сообщения

Карточки **запланированы, не назначены и не начаты**. Основание —
[DEC-08](../../product/reports-and-moderation.md), API 0.13.0. Каждая назначается
отдельно по [правилам очереди](README.md), после обязательного контура модерации.

## BE-11 — Жалобы, ручной разбор и восстановление сообщения

- Родительская область: REPORTS-01.
- Зависимости: BE-09.
- Владелец / исходный SHA / ветка: назначает координатор перед запуском.
- Область файлов: apps/api/internal/modules/reports/** и согласованные обработчики модерации messages/events. reports.sql, изменения messages/events.sql и миграции — только через назначенного владельца БД; общая регистрация — через координатора.
- Результат: reportEvent/reportMessage, adminGetMessage, adminRestoreMessage, отклонение жалоб и интеграция с уже готовыми фильтрами/счётчиками/атомарным закрытием BE-08/09. Начальная схема и данные reports подготовлены DB-01/02. Не переопределять скрытие/снятие и не вводить временные нулевые счётчики. Без автоматического скрытия и поля причины жалобы.
- Приёмка и проверки: полный чек-лист DEC-08 на PostgreSQL через Compose. Дубль одного аккаунта/цели, обе цели и закрытые повторы, запрет своих целей/гостя/снятой встречи/новой жалобы HIDDEN; без обязательного участия. Параллельные подачи, скрытие/восстановление/разбор с новыми жалобами, старые версии и таймаут. Прямые и сообщения не закрываются вместе. ADMIN-only исходный HIDDEN; события/организации/участия не смешиваются. Перезапуск сохраняет записи/версии/решения.
- Операции контракта: reportEvent, reportMessage, adminGetMessage, adminRestoreMessage, adminDismissEventReports, adminDismissMessageReports; интеграция adminHideMessage/adminUnpublishEvent/adminListEvents/adminGetEvent/adminListMessages.
- Вне задачи: интерфейс, публикация снятой встречи, редактирование сообщений, уведомления, причины/вложения жалоб, блокировки, универсальный аудит, независимая смена OpenAPI и публикация без поручения.

## FE-13 — Жалобы в карточке и разбор в модерации

- Родительская область: REPORTS-01.
- Зависимости: FE-11.
- Владелец / исходный SHA / ветка: назначает координатор перед запуском.
- Область файлов: apps/web/src/features/reports/** и согласованные точки интеграции карточки встречи/обсуждения/административной модерации. Общие маршруты, компоненты и тексты — через координатора; новых URL не требуется.
- Результат: SCR-03 — «Пожаловаться» на встречу/сообщение, вход для гостя, подтверждение только по ответу сервера; SCR-17 — фильтр и два счётчика; SCR-18 — фильтр сообщений, отклонение жалоб и восстановление HIDDEN без причины.
- Приёмка и проверки: фикстуры 0.13.0, затем BE-11 через Compose. Дубль/закрытая квитанция, ошибки/неизвестный результат без ложного успеха, очистка персонального кеша при смене аккаунта. MESSAGE_CHANGED/REPORTS_CHANGED вызывают перечитывание, без автоматического повтора с новой версией. Исчезнувшая из фильтра строка восстанавливается чтением по id. Публичный HIDDEN без body; после восстановления прежний текст на прежнем месте. Телефон/клавиатура/загрузка/пустота, отсутствие причины жалобы и сохранение обязательной причины снятия.
- Операции контракта: reportEvent/reportMessage, adminGetMessage, adminRestoreMessage, adminDismissEventReports/adminDismissMessageReports; затронутые операции модерации/списков и повторное listMessages.
- Вне задачи: отдельная история жалоб, новый административный маршрут, автоматическое скрытие/блокировки, изменение общего контракта и публикация без поручения.

BE-11 и BE-10, FE-13 и FE-12 не имеют предметной зависимости друг от друга.
Это не разрешение нескольким исполнителям одновременно менять общую модерацию,
миграции или маршруты: по умолчанию соответствующий владелец ведёт их последовательно.
