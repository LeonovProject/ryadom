# Модерация аккаунтов

Порядок назначения/подключения уточнён [пакетным процессом](../handoff/work-packets.md):
карточки можно выполнять последовательно в одном назначенном пакете; обычные
подключения API/экранов выполняет единственный владелец стороны. Прежнее
требование передавать каждую регистрацию координатору заменено; общие
контракты/зависимости/бренд остаются у COORDINATOR.

Обе карточки запланированы, не назначены и не начаты. Основание —
[DEC-21](../../product/account-blocking.md), [вход](../../architecture/authentication.md)
и API 0.13.0. Все пути будущие; общие навигация/SQL/DTO принадлежат координатору.

## BE-13 — Поиск, блокировка и разблокировка USER

- Родительская область: ADMIN-01 / API-01.
- Зависимости: BE-02.
- Владелец / исходный SHA / ветка: назначает координатор перед запуском.
- Область файлов: apps/api/internal/modules/accounts/moderation/**. Запросы accounts.sql/sessions.sql добавляет единый владелец БД после завершения BE-02; auth/общий guard не переписывается вторым исполнителем.
- Результат: adminListAccounts/adminGetAccount/adminSetAccountStatus, фильтры/поиск/курсоры, приватный AdminAccount и expectedRevision. Цель только USER; ADMIN защищён. BLOCKED/status/revision/данные ADMIN и удаление всех sessions одним commit; ACTIVE очищает blocked-поля без восстановления токенов.
- Приёмка и проверки: Две сессии, прямой запрос после блокировки, неверный/правильный пароль BLOCKED, новый вход после разблокировки и отказ старых JWT; ADMIN/USER/гость, защищённая цель, stale revision/повтор/таймаут. Проверить гонку с login и предметной операцией по общему порядку замков, отсутствие изменения контента/участия/допуска и сохранение после рестарта в Compose. Никакого обхода через прежние demo-маршруты.
- Публичные признаки: BE-02 отдаёт PublicAccount.isBlocked; BE-03/05 — ownerIsBlocked организатора-организации/публичной организации. Координатор обеспечивает передачу правил этим владельцам; BE-13 не меняет их файлы параллельно.
- Операции контракта: adminListAccounts, adminGetAccount, adminSetAccountStatus.
- Вне задачи: блокировка ADMIN, жалобы на аккаунт, причина/таймер, роли, перенос владения или автоматическое снятие публикаций.

## FE-15 — Аккаунты ADMIN, SCR-22

- Родительская область: ADMIN-01 / WEB-01.
- Зависимости: FE-11.
- Владелец / исходный SHA / ветка: назначает координатор перед запуском.
- Область файлов: apps/web/src/features/admin/accounts/**. Общий маршрут /admin/accounts, навигацию и кеш подключает координатор. Файлы auth принадлежат завершённой FE-02, публичных карточек — FE-04.
- Результат: Поиск/фильтр/пагинация, панель выбранного аккаунта в одном URL, просмотр email/роли/статуса, подтверждение блокировки/разблокировки USER без поля причины. ADMIN без действия блокировки. Загрузка/ошибка/пустота/утрата прав, клавиатура/телефон по брендбуку.
- Приёмка и проверки: Сначала HTTP-фикстуры, затем реальный BE-13/Compose: успех только по ответу, двойное нажатие заблокировано, 409/таймаут перечитывает adminGetAccount без автоматического PATCH retry. Не выдавать свежее состояние за доказательство авторства потерянного запроса. Проверить отзыв другой сессии в отдельном контексте и очистку личного кеша общим обработчиком FE-02.
- Интеграция контента: FE-04 показывает isBlocked/ownerIsBlocked и недоступного организатора; FE-08 предупреждает перед APPROVAL-заявкой, сохраняя доступность записи по правилам. Эти изменения передаются владельцам, не делаются вторым исполнителем в их файлах.
- Операции контракта: adminListAccounts, adminGetAccount, adminSetAccountStatus.
- Вне задачи: самостоятельная смена API/общих типов, модерация контента вместо аккаунта, параллельные правки общей навигации или публикация.
