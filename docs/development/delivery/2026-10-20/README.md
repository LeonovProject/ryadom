# Финальная локальная поставка — 20 октября

Подготовлена по поручению пользователя объединить продукт и отправить в оба
remote, с минимальными проверками из-за оставшихся примерно 10 минут.
Развёртывание на машине пользователя выполняет пользователь, по
[Ubuntu-инструкции](../../../deployment/ubuntu-24.04.md). Основной адрес — HTTP
по IP на 80 с явным деморежимом DEC-27. Это вымышленные данные/публичные пароли;
для настоящих данных требуется HTTPS.

## Состав

- Прежнее ядро QA-01 из a65d1c9: S1–S6, организации, участие, обсуждение,
  жалобы, блокировка, сброс и Swagger. Полный QA-01 ранее прошёл.
- HTTP-поставка e1eb5c3: подготовка Ubuntu и opt-in HTTP. Полный Go/race/vet
  и реальный HTTP-вход проверены ранее, отчёт docs/deployment/verification.md.
- BACKEND 4a399f1 / MEDIA-01A 9cc4287 и MEDIA-01B: свой SVG-аватар,
  revision-bound модерация и загрузка/сброс фона. 14 хешей из verified-source.json
  совпали с общей копией. Приняты адресные PostgreSQL/race/TLS/rollback/конкуренция
  исполнителя без полного повторного прогона.
- FRONTEND 6c5f143, FE-16 9d772cf: помощник условий первой встречи,
  семь готовых SVG и случайный первоначальный выбор по последующему поручению
  пользователя фронтендеру. Явный presetId по-прежнему обязателен в register.
  Приняты его типы/браузер/настоящий Compose и проверки SVG по отчётам FE-16/AVATARS.
- Незакоммиченные приглашение/QR из той же frontend-копии включены координатором
  по поручению финализации: локальная qrcode 1.5.4 MIT, свежая публичная карточка,
  проверка перед печатью, безопасная ссылка без query/JWT, A4 и полные условия.
  Исходная копия исполнителя не сброшена и не закоммичена координатором.
- Координатор подключил формы MEDIA-01C/D/E: свой SVG/PRESET/сброс в профиле,
  фон на странице своей встречи, очередь ADMIN с чтением текущей версии,
  preview до решения, одобрение/скрытие/восстановление. Неизвестный результат
  блокирует повтор до явного чтения; пользовательский SVG только как img URL.

Новый коммит Кирилла не обрабатывался. Канонический OpenAPI 0.13.0 и DTO,
схема БД/миграции не менялись. Общие зависимости изменены только для QR.
Новые серверные SQL/sqlc из backend-пакета проверены production-сборкой.

## Поставка и ограничения

Запуск — Docker Compose из корня, четыре образа api/migrate/seed/web; только
явный seed новой БД, постоянный .env/ключ/том. Web demo access требует сборки.
На внешнем IP после развёртывания проверить login, второй браузер, SVG, печать,
Swagger и файл демодоступов. DELIVERY-01B остаётся открытой до такого просмотра.

Swagger показывает общий контракт: вводное описание info.description содержит
исторический перечень ранней интеграции; актуальный статус реализации — этот
отчёт. Это не меняет маршруты/схемы. Мобильный native-клиент не разрабатывался.

Переданный SHA — коммит, содержащий этот отчёт. Общая история не переписывается,
ветки исполнителей не сбрасываются. Коммит и push main выполняются в origin
(GitHub) и gitverse по прямому запросу пользователя. Презентацию и финальную
внешнюю демонстрацию пользователь готовит самостоятельно.
