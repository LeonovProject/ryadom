# Главная и быстрый доступ к своим встречам

Статус: **правила личного блока приняты по DEC-14–16, реализация отсутствует**. Основание — просьба
пользователя видеть свои записи с минимумом шагов и добавить «Мои встречи»
рядом с «Встречами» сверху. Пользователь выбрал будущие встречи первыми,
начавшиеся сегодня — отдельным компактным блоком. Выборки закреплены в API
0.13.0. Работу над макетом пользователь остановил; макет 0.2 не изменён.
Остальные детали оформления ниже остаются проектируемым интерфейсом.

## Постоянная навигация

На компьютере: логотип → **Встречи → Мои встречи**, справа «Создать встречу»
и профиль/вход. «Мои встречи» — обычный видимый пункт, не спрятанный в профиле.
Он ведёт сразу на `/me/events`, по умолчанию вкладка «Участвую». Остальные
контексты — организации/модерация — доступны из профиля и своих кабинетов.

На телефоне «Мои встречи» сохраняется в нижней навигации. Если добавляем туда
«Главная», порядок: Главная / Встречи / Мои встречи / Профиль. Не прячем личный
список в бургер и не требуем сначала открыть профиль. Гость при выборе личного
пункта проходит вход с returnTo=/me/events, без автоматических бизнес-действий.
Активный раздел обозначен явно; числового бейджа без подтверждённого счётчика нет.

## Главная после входа

Первый содержательный блок после шапки — **«Мои встречи»**, без большого
рекламного hero перед ним. В нём до трёх ближайших записей и ссылка «Все мои
встречи». Следом — компактный блок «Начались сегодня», отдельно от трёх будущих
планов; утренняя встреча не вытесняет будущую вечернюю. Минимум одна компактная карточка должна помещаться в первом экране
телефона; точная вместимость проверяется на 320/390 px и с длинными названиями.

Карточка содержит название, дату/время с зоной встречи, понятное место и
«Ты участвуешь». Открытие карточки ведёт в событие одним нажатием. Можно добавить
вторую ссылку «Обсуждение» к соответствующему блоку той же страницы, без нового
самостоятельного экрана. Большая обложка не должна вытеснять время и адрес.

Только CONFIRMED показывается как участие. Для PENDING — отдельная строка/ссылка
«Мои заявки», не «Ты участвуешь». REJECTED остаётся в личном списке с понятным
результатом, а не занимает место ближайшего подтверждённого плана. Личное авторство
и встречи своей организации доступны через вкладку «Организую» и её кабинет;
организатор не записывается на собственную встречу автоматически.

После личного блока — компактный поиск, направления и «Найти новую встречу»
с карточками опубликованных событий. Ссылка «Создать встречу» доступна, но не
отвлекает от уже запланированного. Если своих записей нет, небольшой блок
«Пока нет встреч» / «Найти встречу», затем сразу каталог; пустота не занимает экран.

## Главная гостя

Короткий hero с объяснением пользы, поиск и опубликованные встречи остаются.
До чтения каталога/карточки вход не требуется. Гость не видит вымышленные личные
записи или персональные счётчики. Пока сессия ещё проверяется, не показываем
полный гостевой hero на миг с последующим скачком к личному блоку.

## Время, статусы и ошибки

- Не убираем сегодняшнюю запись сразу при startsAt: человек может опоздать
  и открыть адрес/обсуждение. Для начавшейся — «Началась в …», не «Сейчас идёт»
  или «Завершена»: времени окончания в модели нет. Более ранние дни остаются
  в полном личном списке, не называются автоматически историей посещений.
- Будущие: startsAt > referenceTime. «Начались сегодня»: startsAt <= referenceTime
  и календарная дата начала равна дате referenceTime в зоне самой встречи.
  В обоих блоках только CONFIRMED/PUBLISHED, порядок startsAt/event.id ASC.
  При равенстве времени начала встреча уже относится ко второму блоку.
  Вчерашняя в него не попадает. Нельзя вычислять «сегодня» по зоне устройства.
  referenceTime — общий опорный момент чтения, не время решения по заявке.
- UNPUBLISHED не предлагается как предстоящая доступная встреча. В полном личном
  списке запись сохраняется в ограниченном виде: только разрешённые
  название/статус и ссылка, без закрытых адреса/даты/фона.
- Загрузка личных данных — компактный skeleton. Ошибка — «Не удалось загрузить
  мои встречи» / «Повторить», не «Встреч нет». Поиск новых событий работает
  независимо. 401 завершает персональный показ и предлагает вход заново.
- Смена аккаунта/успешный демосброс очищают персональный кеш. Нет уведомлений,
  непрочитанных сообщений или количественных бейджей без соответствующей модели.

## Сколько действий

| Цель | Предлагаемый путь |
| --- | --- |
| Увидеть ближайшие записи на главной после входа | Без переходов, первый личный блок |
| Открыть одну из показанных встреч | Одно нажатие на её карточку |
| Увидеть полный личный список с любого экрана | Одно нажатие «Мои встречи» |
| Прочитать обсуждение показанной встречи | Одно нажатие, если согласована прямая ссылка на блок |
| Гость открывает личный список | Вход с возвратом сразу в список |

## Выборки API 0.13.0

Расширяется существующая listMyParticipations, новый маршрут не нужен:

1. `GET /api/v1/me/participations?status=CONFIRMED&eventWindow=UPCOMING&limit=3`
   получает ближайшие будущие и referenceTime сервера.
2. Для компактного второго блока — та же операция с
   `status=CONFIRMED&eventWindow=STARTED_TODAY&referenceTime=<момент из первого ответа>&limit=3`.
   При nextCursor показывается переход к остальным, без вымышленного общего числа.

Фильтры и сортировка применяются на сервере **до пагинации**. Пересортировка
первой страницы на фронтенде не находит ближайшие записи за её пределами.
Курсор сохраняет опорное время, фильтры и последний ключ сортировки. Два блока
используют одно referenceTime, поэтому их временные окна не пересекаются.
Это не снимок БД: новые записи и модерация могут изменить выдачу; для обновления
обоих блоков получают новый опорный момент и сбрасывают прежние курсоры.

Без eventWindow полный личный список сохраняет прежнюю семантику:
createdAt/participation.id DESC, все даты и доступная ограниченная сводка UNPUBLISHED.
По DEC-15 полный раздел «Участвую» по умолчанию использует UPCOMING;
«Начавшиеся» — STARTED со startsAt/event.id DESC, «Все записи» — без окна
с доступными ограниченными UNPUBLISHED. Фильтры view=upcoming/started/all
при tab=confirmed описаны в [SCR-09](screens.md#scr-09-мои-встречи).
Статусы участия не меняются из-за времени начала. Точные правила параметров —
[в контракте](../contracts/api-v1.md#личные-временные-выборки-dec-14).

Навигация сама по себе использует уже предусмотренный `/me/events` и не требует
нового маршрута API. BE-07/FE-03/FE-08 и приёмка уточнены по DEC-14;
новых карточек работ не добавлено. Для макета потребуется отдельная проверка
вида/переходов после возобновления работы над ним.

По DEC-16 после входа или регистрации без допустимого returnTo открывается
персональная главная `/`; сохранённая безопасная цель имеет приоритет. Запись,
вопрос или жалоба после входа не выполняются автоматически. Это заменяет
прежний переход входа в каталог и регистрации в `/me`; профиль доступен из шапки.
