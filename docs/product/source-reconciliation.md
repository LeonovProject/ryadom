# Уточнения после получения первичных PDF

Действуют [постановка и критерии](../requirements/README.md).
Таблица уточняет предварительные продуктовые предположения по полным документам.

| Прежняя трактовка | Действующее требование | Постановка |
| --- | --- | --- |
| Роли предположены | Три роли заданы: пользователь, организация/сообщество, администратор; организатор не четвёртая роль | A-P02, A-P04, A-P05 |
| Универсальность доказывается спортом и неспортивной активностью | Нужны разные спортивные направления; неспортивное расширение — идея команды | A-P02, A-P08 |
| Публикация обычным пользователем ещё не определена | Пользователь создаёт и публикует от себя; событие открывает другой пользователь | A-P03, A-P08 |
| Достаточно конечного списка категорий | Обязателен свой вид спорта без изменения кода | A-P03, A-P04, A-P08 |
| Вопросы можно заменить внешним чатом | Нужно обсуждение внутри события; комментариев достаточно, внешний чат лишь дополняет | A-P05, A-P08 |
| Обсуждение только для записанных | Для открытого события информация/обсуждение доступны не только участникам, вопрос задаёт любой пользователь платформы | A-P05 |
| Допуск и публикация ещё требуют выбора механики | Решает администратор; до допуска страница не публична, публикации недоступны; после допуска нет обязательной повторной модерации событий | A-P05–A-P07 |
| Причины решений и модерация сообщения — возможные улучшения | Причины отказа организации и модерации события, а также скрытие/удаление одного сообщения обязательны | A-P06, A-P07 |
| Снятие публикации в основном сценарии делает автор | Его делает администратор; дополнительные полномочия автора — отдельное решение | A-P07, A-P08 |
| Удаление исключено | Допустимо удаление или снятие. Обе операции не объявлены обязательными | A-P07, A-P08 |
| Поведение прямой ссылки полностью выбирает команда | Новая запись запрещена; организатор и записанные понимают недоступность | A-P07 |
| Вместимость — обязательное поле | Лимит мест, очередь, отмены, переносы и уведомления — дополнительные возможности | A-P04 |
| Нативное приложение может само дать баллы | Не требуется и не даёт дополнительных баллов; адаптивный веб обязателен | A-P08, A-P09 |
| Достаточно переключения экранов | Имитировать можно вход; допуск, публикация и участие меняют данные | A-P05 |
| Достаточно локального запуска и текущего Git-репозитория | Сдача требует GitVerse и доступного экспертам через сеть прототипа | A-P09 |

Брендбук 1.2 согласован с [правилами реализации](../../brandbook/requirements-alignment.md).
Технологии, конкретные поля сверх минимума, обработка названий спорта, ограничения
информации событий по заявке, судьба старых записей после модерации, демовход,
развёртывание и выбранные улучшения остаются решениями команды.
