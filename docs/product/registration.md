# Регистрация и повторный вход — DEC-11/12/20

Статус: **принято для MVP; не реализовано**. DEC-20 заменяет регистрацию
демопрофиля по одному имени обычным аккаунтом email/пароль. Обязательный выбор
готового аватара DEC-12 сохраняется; свой SVG загружается позже в профиле.
Формы данных — [API 0.13.0](../contracts/api-v1.md), технические правила —
[аутентификация](../architecture/authentication.md).

## Вход в процесс

/register доступен из навигации, /login и при попытке защищённого действия.
Каталог и опубликованные встречи можно читать гостем. Безопасный внутренний
returnTo сохраняется между входом и регистрацией; внешний URL не принимается.
Если сессия есть, предложить продолжить от текущего аккаунта либо явно выйти.
Автоматически создавать ещё один аккаунт или менять действующее лицо нельзя.

## Одна страница SCR-07

Заголовок «Создать профиль». Все поля находятся на одной странице:

| Блок | Содержимое и поведение |
| --- | --- |
| Имя | displayName после trim, 1..120 Unicode code points; публично, одинаковые имена разрешены |
| Email | Обязательный адрес для повторного входа, 3..254 ASCII без пробелов, lowercase на сервере; приватный. Подпись «Подтверждение почты в этой версии не требуется» |
| Пароль | Обязательный, 15..128 code points без trim/обрезания, показ/скрытие, разрешены вставка и менеджер паролей, autocomplete=new-password |
| Подтверждение пароля | Клиентское сравнение, в API не передаётся; при несовпадении форма не отправляется |
| Предпросмотр | Введённое имя и выбранная картинка либо стандартная заглушка до выбора |
| Готовый аватар | Обязательная сетка из listAvatarPresets, подпись «Свой SVG можно загрузить позже в профиле». Первый вариант не выбирается автоматически; пропуска нет |
| Основное действие | «Создать профиль», доступно при валидных полях/совпавших паролях/выбранном доступном presetId. Нажатие на картинку только меняет выбор |
| Переход | «Уже есть профиль? Войти», сохраняет returnTo |

Сетка — группа с одним выбранным вариантом; название каждого SVG доступно
диктору, выделение рамкой/отметкой, клавиатура и фокус, без горизонтальной прокрутки
на телефоне. Ошибка картинки показана, выбранный ID не заменяется молча.
По DEC-22 в каталоге есть реальный аватар «Спутник» (`ryadom-companion`);
ожидание изображений снято. Даже один вариант выбирается явно, без автовыбора.
Пустота/ошибка каталога по-прежнему блокирует только новую регистрацию;
вход уже созданными аккаунтами остаётся доступен.

Нет выбора роли, организации, интересов, геолокации или загрузки своего SVG
на этом экране. Регистрация создаёт только USER/ACTIVE; организацию создают
отдельно. Подготовленные аккаунты могут иметь NONE, существующий пользователь
может сбросить картинку в профиле — это не разрешает пропуск при регистрации.

## Запрос и состояния

POST /auth/register (register): displayName, email, password, presetId.
Один commit создаёт accounts, account_avatars PRESET/APPROVED/1 и sessions.
201 Me содержит приватный email и выбранный avatarUrl; JWT выдаётся cookie
после commit. Новая регистрация заменяет текущую сессию только при успехе.
Нельзя создавать аккаунт, а потом отдельным запросом назначать начальный аватар.

| Состояние | Интерфейс |
| --- | --- |
| Загрузка каталога | Сетка загружается, создание недоступно, остальные поля можно заполнять |
| Пустой каталог | «Регистрация пока недоступна: нет готовых аватарок», переход ко входу и повтор чтения |
| Ошибка каталога | Сообщение и явный повтор, без регистрации с заглушкой |
| Отправка | «Создаём профиль…», поля/кнопка защищены от повторной отправки, успех ещё не показан |
| 422 | Ошибки рядом с полями, фокус на первой. Исчезнувший presetId требует явного нового выбора; имя/email сохраняются |
| 409 EMAIL_TAKEN | Предложить вход либо другой адрес; не выдавать это за успешную регистрацию и не входить автоматически |
| 429 RATE_LIMITED | Показать срок Retry-After; повтор только действием пользователя после ожидания |
| Успех | Очистить старый персональный кеш, перейти к безопасному returnTo либо на персональную главную / |
| Таймаут/неопределённый ответ | Не повторять POST автоматически. getMe проверяет текущий вход; сам по себе не доказывает создание именно этим запросом |

Если cookie не пришла после commit, человек может открыть /login и войти
с введённой парой email/пароль. Успешный login подтверждает вход в аккаунт,
не авторство потерянного запроса регистрации. Если getMe относится к прежнему
другому email, не выдавать его за новый профиль. Пароль живёт только в памяти
формы, не попадает в URL, localStorage, кеш запросов или логи и очищается при уходе.
На ошибки формы не отвечать обещанием отсутствия созданного аккаунта, если
результат неизвестен. После входа участие/вопрос/жалоба не отправляются сами.

## SCR-06 — повторный вход

Email и пароль (autocomplete=username/current-password), кнопка «Войти»,
переход к регистрации. Ранее зарегистрированный пользователь может вернуться
после выхода/истечения 24 часов. 401 INVALID_CREDENTIALS имеет общий текст;
403 ACCOUNT_BLOCKED показывает блокировку, 429 — ожидание. Нет кнопки
восстановления, которая никуда не ведёт, SMS или подтверждения почты.
Демоаккаунты трёх контекстов используют обычный login; доступы документируются
в инструкции демонстрации, выбора ADMIN одним demoKey больше нет.

## Владельцы и приёмка

AUTH-01 — криптография/ограничения; BE-02 — вход/регистрация, общая проверка
ACTIVE/сессии, listAvatarPresets и читатель manifest; FE-02 — обе формы и SCR-08.
MEDIA-01F подключает реальные готовые SVG до QA-01; MEDIA-01A/D позднее дают
замену/свою загрузку. У регистрации нет зависимости от поздней модерации SVG.

- Имя/email/пароль/обязательный аватар сохраняются атомарно, профиль и картинка
  доступны другому пользователю без утечки email/хеша/токена.
- Повторный вход после выхода и пересоздания контейнеров работает; email
  сравнивается без регистра, параллельные регистрации не дублируют адрес.
- Пустой каталог/неверный ID/неверные поля/занятый адрес не создают частичных
  данных и не заменяют прежнюю сессию. Пропуск/null и клиентская роль запрещены.
- Проверены неизвестный результат, последующий явный login, безопасный returnTo,
  отсутствие автоповторов, обе ошибки входа и ограничения попыток.
- Телефон, клавиатура/диктор, фокус, менеджер паролей и все состояния формы
  проверяются на приложении после реализации; статические примеры этого не доказывают.
