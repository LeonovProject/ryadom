# Готовые и пользовательские SVG-аватары — DEC-09/10

Статус: **принято; реализация отсутствует**. DEC-09 добавил личный SVG с
модерацией. DEC-10 по последующему запросу пользователя дополняет его выбором
из заранее подготовленных SVG. По DEC-22 стартовый аватар «Спутник» уже
[подготовлен в репозитории](../../design/assets/README.md); ожидание файлов снято.
Это улучшения команды, не требования официальных PDF. API —
[0.13.0](../contracts/api-v1.md), безопасность — [media.md](../architecture/media.md).

У аккаунта одна текущая аватарка. source=NONE/PRESET/CUSTOM отделяет происхождение
от состояния проверки. Готовая доступна сразу; личная загрузка требует одобрения.
Выбор готовой заменяет текущий личный файл, а загрузка своего SVG заменяет готовую
аватарку и снова идёт на проверку. Предыдущий выбор автоматически не возвращается.

## Состояния и показ

| Состояние | Владелец в личном кабинете | Остальные пользователи |
| --- | --- | --- |
| NONE / EMPTY | Выбрать готовую или загрузить SVG | Стандартная заглушка |
| PRESET / APPROVED | Выбранный вариант каталога, заменить/сбросить | Готовая аватарка, без новой модерации |
| CUSTOM / PENDING | «На проверке», приватный предпросмотр, заменить/сбросить | Заглушка |
| CUSTOM / APPROVED | «Одобрено», заменить/сбросить | Одобренная аватарка |
| CUSTOM / HIDDEN | «Аватар скрыт», приватный предпросмотр, заменить/сбросить | Заглушка |

Новая загрузка всегда PENDING, включая замену ранее одобренной. Прежний файл
не остаётся публичным, пока проверяется новый. Неверный/слишком большой файл
вообще не принимается: прежний SVG, статус и версия сохраняются. Пользовательская загрузка не получает автоматического одобрения. Готовый вариант
уже проверен до включения в каталог и доступен сразу.

Лимит такой же, как у фона: **128 КиБ = 131072 UTF-8 байта включительно**
до/после нормализации, JSON-тело максимум 1 МиБ. Сжатые SVGZ не принимаются.
SVG проходит общий серверный XML allowlist, отображается только изображением.
Сырой текст не включается в аккаунты, сообщения, списки или DTO очереди.

В PublicAccount используется avatarUrl: статический URL PRESET или API URL
одобренного CUSTOM. До одобрения/после скрытия/сброса это null. Клиент показывает статическую заглушку и заменяет изображение на неё
также при ошибке загрузки, без бесконечного цикла повторов.

## Каталог готовых аватаров — DEC-10/12

По [DEC-11/12](registration.md) этот же каталог доступен сразу на регистрации:
обязательный выбор сохраняется вместе с именем в одном register с email/password/displayName/presetId. Пользователь
не обязан сначала создать аккаунт, а затем отдельным запросом выбирать картинку.
Свой SVG загружается позднее в профиле, без обязательного шага после регистрации.

Общий [avatar-presets.json](../../packages/contracts/avatar-presets.json) содержит
items с id, label, imageUrl. В нём семь готовых SVG: прежний `ryadom-companion` и шесть рисунков пользователя. Размещение
исходников и подключение — [инструкция](../../packages/contracts/avatar-presets/README.md).
GET /avatar-presets возвращает полный список в порядке manifest. При пустом
каталоге в существующем профиле показывается пояснение и доступна своя загрузка;
на регистрации продолжение блокируется. По уточнению пользователя 20 октября один вариант на регистрации предвыбирается случайно; ручной выбор сохраняется.

PUT /me/avatar/preset принимает presetId и expectedRevision. Неизвестный ID даёт
422 VALIDATION_ERROR /presetId без изменения выбора. Если тот же PRESET уже выбран,
200 без изменения версии/дат. Иначе версия должна совпасть, или AVATAR_CHANGED.
Выбор даёт source=PRESET/status=APPROVED, presetId=ID и revision+1; прежние SVG,
uploadedAt/reviewedAt/By очищаются. Это замена текущего файла, а не отдельная
проверяемая заявка. Старые формы модератора после выбора готовой дают 404.

Один manifest используется API и вебом в сборке, статические SVG входят в веб-образ.
Нельзя выбирать произвольный URL. ID неизменяем, при другом содержимом нужен новый
ID; imageUrl соответствует /assets/avatars/presets/<id>.svg. SVG проверяется тем же
allowlist и лимитом 128 КиБ перед включением в каталог. Готовые ресурсы могут
кешироваться как статические изображения: их просмотр не зависит от выбора аккаунта.
Проверка и обновление коллекции выполняются при подготовке сборки, без отдельного
интерфейса управления каталогом. Административная очередь содержит только CUSTOM.

Если сохранённый presetId исключён из новой сборки, он остаётся в БД и личном
состоянии, но previewUrl и публичный avatarUrl становятся null. Показываются
заглушка и «Выбранный вариант недоступен», предлагаются другой выбор/загрузка/сброс.
Смена manifest не увеличивает revision аккаунта автоматически. Выбрать отсутствующий
ID заново нельзя. Результат замены/загрузки подтверждает только ответ сервера.

## Модерация

Отдельная очередь SCR-21 `/admin/avatars`: имя пользователя, приватное изображение,
статус/дата, фильтры имени и состояния. Интерфейс начинает с PENDING, но можно найти
APPROVED для скрытия и HIDDEN для восстановления. EMPTY в очереди не показывается.
Одна строка на аккаунт, только текущая CUSTOM-загрузка; PRESET/NONE не входят
в очередь и недоступны по прямым административным маршрутам (404).

- APPROVE: PENDING/HIDDEN → APPROVED. Одобрение HIDDEN восстанавливает аватарку.
- HIDE: PENDING/APPROVED → HIDDEN. Файл остаётся владельцу/ADMIN для просмотра.
- Оба действия без поля причины. Права ADMIN не дают менять личный файл за владельца.
- Жалобы на аватарки пока не добавляются: DEC-08 остаётся о встречах и сообщениях.
- Статусы аватара не меняют роль человека, допуск организации, встречи или участия.

Владелец может заменить или сбросить файл в любом состоянии. Сброс очищает
текущий SVG и модерацию, возвращает EMPTY. История файлов, отдельные заявки/
уведомления, блокировки и логотипы организаций вне этого решения.

## Версия и одновременная работа

У каждого аккаунта есть одна строка account_avatars с source=NONE, status=EMPTY
и revision=0 при создании.
Строка сохраняется после сброса; новый файл не получает прежнюю версию. Любой
реальный выбор готовой/загрузка/модерация/сброс увеличивает revision на один. У повторов без
изменений остаются прежние даты, версия и решение.

PUT /me/avatar передаёт svg и expectedRevision из getMyAvatar. При смене PRESET
источник становится CUSTOM, presetId очищается. Если текущий
PENDING содержит тот же нормализованный SVG, это повтор 200 без изменений.
Иначе версия должна совпасть; новая загрузка сохраняется как PENDING с revision+1,
reviewedAt/By очищаются. Старый повтор после одобрения/скрытия даёт AVATAR_CHANGED
и не отправляет уже рассмотренный файл на проверку заново. Осознанная повторная
загрузка с актуальной версией разрешена и снова требует одобрения.

DELETE /me/avatar принимает expectedRevision: уже EMPTY — 200 без изменений;
иначе старая версия даёт 409 AVATAR_CHANGED. После сброса сохраняется увеличенная
версия, source=NONE, presetId/SVG/uploadedAt/reviewedAt/By очищаются.

Для административного перехода версия формы обязана совпадать с текущей.
Если нужный статус уже установлен, 200 без изменений допустим только при
expectedRevision=current или current-1 (повтор ровно последнего перехода).
Более старая форма даёт 409 AVATAR_CHANGED даже при совпадении статуса.
NONE/PRESET/нет аккаунта на административных маршрутах — 404.

Пример: upload(0) → PENDING/1, approve(1) → APPROVED/2, новая загрузка(2) →
PENDING/3. Старая форма approve(1) не может одобрить новый файл. Hide(2) → HIDDEN/3,
approve(3) → APPROVED/4; повтор старого hide(2) не скрывает восстановленный SVG.

После конфликта/таймаута клиент перечитывает getMyAvatar либо adminGetAvatar
и предлагает решение заново. Автоматически подставлять свежую версию в старую
команду нельзя. Пока ответ не подтверждён, интерфейс не объявляет успех.

## Доступ к изображению

Публичный API URL личного SVG содержит accountId и revision, выдаёт только
текущий CUSTOM/APPROVED. PRESET использует статический URL из каталога; на API
маршруте личного изображения он недоступен (404).
У PENDING/HIDDEN/EMPTY, другой версии и неизвестного аккаунта одинаковый 404,
включая владельца/ADMIN на публичном маршруте. Старый URL после замены или
модерации не выдаёт новый файл. Приватные previewUrl владельца и ADMIN имеют
те же проверки revision и отдельную проверку сессии/роли при каждом запросе.

У API-изображений и отказов private/no-store; SVG с CSP sandbox/nosniff.
Proxy не кеширует личные SVG. Для доверенного PRESET применяются правила статики.
Гость может видеть одобренные аватары. Разметка SVG не вставляется в DOM.
Модератор принимает решение по revision просмотренного DTO/изображения;
замена между чтениями даёт 404 изображения или конфликт решения.

Клиент после своей мутации обновляет профиль/getMe, личное состояние и затронутые
списки/обсуждения; при смене аккаунта очищает персональный кеш. Другой пользователь
видит изменения после повторного чтения; push не предусмотрен. Уже показанную
или скачанную копию изображения отозвать нельзя.

## Приёмка после реализации

Загрузка → заглушка у второго пользователя → одобрение → видимая аватарка →
скрытие → заглушка → повторное одобрение. Замена APPROVED требует новой проверки;
сброс сохраняет версию. Проверяются опасный XML, 128 КиБ/131073 байта, UTF-8,
ошибки/таймаут, старые URL, приватный предпросмотр, права и гонки решения/загрузки/
сброса. PostgreSQL после пересоздания контейнеров сохраняет SVG/состояния/версии.
Дополнительно: пустой/заполненный каталог, выбор готовой без ожидания, повтор,
неизвестный/исключённый ID, CUSTOM → PRESET и PRESET → CUSTOM, сброс обоих видов,
старая форма решения после выбора готовой. Проверяются заполненный каталог
с `ryadom-companion` и отдельная фикстура пустого; интеграция ресурсов — MEDIA-01F.
Примеры OpenAPI проверяют только форматы; эти действия пока не исполнялись.
