# «Что важно знать перед встречей» — спецификация для реализации

Дата: 20 октября 2026. DEC-25: пользователь поручил описать идею для передачи
агентам. **Спецификация подготовлена; реализация не начата этим поручением.**
Это улучшение команды сверх PDF, поддерживающее A-P03–A-P05 и R2.4/R6.7.
[Карточка FE-16](../development/tasks/first-meeting.md) назначается отдельно.

## Проблема и результат

Гипотеза: найденная встреча может оставаться непонятной новичку — какой темп,
что взять, к кому подойти, объяснят ли правила. Организатор не всегда вспоминает
указать эти сведения. Помощник предлагает вопросы и превращает **ответы автора**
в обычный текст условий, который сохраняется вместе со встречей.

Наблюдаемый результат: другой человек читает ответы в карточке и в
[печатном приглашении](printable-invitation.md). Уровень подготовки не
определяется по возрасту; медицинских обещаний и знака «проверено» нет.

## Место в интерфейсе

В существующей трёхшаговой форме SCR-10 (`/events/new`), на шаге «Участие»,
рядом с существующим полем «Условия участия» разместить сворачиваемый блок
**«Что важно знать перед встречей»**, исходно закрытый.

Вводный текст: «Помоги тем, кто придёт впервые: расскажи о подготовке,
инвентаре и знакомстве. Ответь на нужные вопросы и добавь текст в условия».

| Вопрос | Клиентский ключ | Подсказка-пример, не начальное значение | Лимит Unicode code points |
| --- | --- | --- | ---: |
| Какая подготовка нужна и какой будет темп? | preparation | Например: «Начальный уровень, спокойный темп» | 600 |
| Что взять с собой? | equipment | Например: «Вода и удобная обувь; коврик предоставим» | 600 |
| Как узнать организатора на месте? | recognition | Например: «Анна с красной лентой на рюкзаке» | 400 |
| Что будет в начале встречи? | welcome | Например: «Познакомимся и объясним упражнения» | 600 |

Все четыре ответа необязательны. Указанный пример не заполняет поле и не
попадает в запрос. Автор может обойти помощник и написать условия вручную.
Закрытие блока сохраняет введённое. Поле места на шаге «О встрече» получает
подсказку: «Укажи адрес, точку сбора и ориентир». Описание встречи сохраняет
своё назначение; помощник не переписывает его или адрес.

## Составление текста

Показывать предпросмотр добавляемого блока и кнопку **«Добавить в условия»**.
Порядок строк фиксирован, пустые ответы пропускаются:

```text
Подготовка и темп: <preparation>
Что взять с собой: <equipment>
Как узнать организатора: <recognition>
В начале встречи: <welcome>
```

Перед сборкой обрезать только внешние пробелы ответа; переносы и внутренний
текст сохранять. Между непустым прежним conditions и блоком — два переноса.
При пустом прежнем тексте вставляется только блок. Текст — обычная строка:
никакой HTML/Markdown-интерпретации или последующего разбора этих заголовков.

**Только явное нажатие** меняет conditions. Оно не публикует встречу и не
выполняет сетевого запроса. Прежний текст не заменяется. После успешного
добавления очистить ответы помощника, показать «Текст добавлен в условия»
и перевести фокус к conditions. Повторное/двойное нажатие не добавляет тот же
блок дважды. Итоговые условия доступны для свободного редактирования.

Если нет непустых ответов, кнопку отключить. Если отдельный ответ превышает
свой лимит, показать связанную с полем ошибку. Если **весь итоговый conditions**
превышает 4000 code points, не менять ни его, ни ответы; показать
«В условиях получится N символов из 4000. Сократи текст перед добавлением».
Автоматического обрезания и частичной вставки нет.

Если автор нажал «Проверить встречу» с неприменёнными ответами, вместо
перехода показать: «Ответы помощника ещё не добавлены в условия» и действия
«Добавить в условия» / «Удалить ответы и продолжить». Первое применяет обычные
лимиты, второе явно очищает только ответы помощника и выполняет обычную
валидацию шага. Никакой неявной вставки или потери текста при переходе.

## Данные и совместимость

| Область | Решение |
| --- | --- |
| API | createEvent/getEvent 0.13.0 без изменений. Передаётся существующий conditions, максимум 4000; locationText максимум 1000, description максимум 10000 |
| БД | Прежние строковые поля события. Новых колонок, миграций, статусов и индексов нет |
| Черновик | Необязательное firstMeeting с четырьмя строками в клиентском EventDraft, рядом с values; отсутствующее поле старого черновика даёт пустые ответы |
| Сохранение | Только память вкладки по нынешним правилам ownerId. Ответы переживают переходы шагов, ошибки и возврат к форме; после перезагрузки исчезают вместе с черновиком |
| API DTO | firstMeeting не входит в EventValues/eventInput и не отправляется как дополнительное поле CreateEventInput |
| Публикация | На шаге проверки виден окончательный conditions. После успешного createEvent весь черновик очищается; при неопределённом результате прежний запрет повтора сохраняется |
| Сессия | Помощник соблюдает существующую очистку при выходе/смене пользователя; истечение сессии сохраняет черновик для того же владельца по DEC-20 |

При pending/uncertain помощник заблокирован вместе с остальной формой. Смена
вида спорта или автора не дописывает никаких условий автоматически. Старые
встречи и ручные conditions показываются как прежде: синтаксического распознавания
«первой встречи», фильтров по подготовке и новых значков не вводить.

## Пример

Автор указал «Без опыта, спокойный темп», «Воду; инвентарь дадим»,
«Анна с красной лентой у входа», «Знакомство и объяснение упражнений».
После добавления и публикации именно эти ответы видны другим читателям.
Надпись «без опыта» — заявление автора, а не проверенное платформой свойство.

## Критерии приёмки

- [ ] Форма работает с закрытым/пустым помощником; прежние обязательные поля и два режима записи сохранены.
- [ ] Полные/частичные ответы составляются в заданном порядке; пустые строки пропущены, примеры не вставляются, ручной текст сохраняется.
- [ ] Двойное нажатие не дублирует блок; результат можно отредактировать, вернуться назад и увидеть тот же conditions.
- [ ] Лимиты отдельных ответов и всего conditions проверены на 3999/4000/4001, emoji и переносах; превышение не обрезает и не теряет текст.
- [ ] Неприменённые ответы при переходе требуют явного выбора; закрытие блока, 422/сетевая ошибка не теряют ответы.
- [ ] Черновик не попадает в storage или другой аккаунт, старый черновик без firstMeeting открывается; pending/uncertain сохраняют ограничения FE-05.
- [ ] Единственный createEvent содержит только контрактные поля. Второй браузер читает фактические conditions из API после перезагрузки/пересоздания контейнеров с тем же томом.
- [ ] Клавиатура, фокус, связанные подписи/ошибки и 320/390/768/1280 px проверены; текст с HTML-подобными символами отображается буквально.

Приёмка на фикстурах допустима для FE-16, но техническая готовность улучшения
подтверждается QA-02 на реальных createEvent/getEvent. Старый HTML-макет не меняется.
