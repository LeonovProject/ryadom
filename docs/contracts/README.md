# Общие контракты

Основание — [первичные источники](../requirements/README.md),
[границы](../product/scope.md) и [приёмка](../product/acceptance.md).
Реализованного API нет. По поручению пользователя зафиксирован
**[интеграционный контракт 0.13.0](api-v1.md)** для параллельной работы веба и сервера.
[OpenAPI](../../packages/contracts/openapi.yaml) — единственный источник маршрутов
и DTO; [примеры и проверка](../../packages/contracts/README.md) готовы.
[ADR-001](../architecture/backend-decision.md) определяет Go и генерацию Go/TypeScript.

[Ранний проект API](api-proposal.md) заменён текущим контрактом. Транспортные поля,
права и переходы 0.13.0 теперь зафиксированы; [физическая модель БД](../architecture/data-model.md)
остаётся проектом, а не миграцией. Владелец спецификации/примеров — координатор;
имена исполнителей модулей ещё не назначены. Подготовка контракта не запускает реализацию.

## Границы модели

- Три роли: пользователь, организация/сообщество, администратор. Автор события —
  пользователь либо организация, а не четвёртая роль.
- Организация, заявка на допуск, событие, участие/заявка участника и сообщение —
  связанные, но разные предметные понятия.
- Членство, подписки и несколько управляющих организации не обязательны.
- Жалоба DEC-08 — отдельная сущность OPEN/RESOLVED/DISMISSED, на встречу либо
  сообщение. Одна запись аккаунта/цели, без причины/автоматического скрытия.
  Скрытие/снятие закрывают разные группы; восстановление текста не возвращает
  публикацию. Версии не дают старой команде отменить новое решение. Правила —
  [спецификация модерации](../product/reports-and-moderation.md).
- Направление имеет отдельное состояние включения в справочник (DEC-07):
  APPROVED перечисляется в общем выборе, PENDING/REJECTED разрешено использовать
  во встречах. Модерация не задерживает личную публикацию и не меняет участие.
- Допуск, публикация и участие не объединяются в одно поле состояния.
- Свой вид спорта добавляется без изменения кода.
- Событие связано с автором/обсуждением; организация — со своими событиями.
- Сообщение связано с автором/событием; его модерация сохраняет остальные сообщения и событие.

## Обязательные инварианты

1. До допуска организация видит заявку, но не публикует страницу и события от своего имени.
2. Администратор одобряет/отклоняет допуск; причина отказа видна организации.
3. События допущенной организации публикуются без обязательной повторной модерации.
4. Свободная запись сразу подтверждает участие; заявка не подтверждена до принятия автором.
5. Принятие и отказ обновляют обе стороны; администратор не подменяет автора.
6. Открытое обсуждение доступно не только записанным; вопрос задаёт любой пользователь
   платформы. Ограничения для встреч по заявке описываются отдельно.
7. Администратор удаляет событие или снимает с публикации с причиной для автора;
   новая запись запрещена, в том числе по прямой ссылке.
8. Автор и уже записанные понимают недоступность; судьба старых записей — решение команды.
9. Допустима имитация входа, но операции меняют данные и доступные действия.

## Согласование операций

Для каждой операции фиксируются владелец, вход/выход, права, состояния,
ошибки/повторные запросы и последствия для ролей. Согласуйте конкурирующие запросы
и неопределённый результат так, чтобы не создавать дубли участия.
Это правило качества реализации, а не новый балльный критерий.

[states.json](../../brandbook/assets/states.json) и
[copy.ru.json](../../brandbook/assets/copy.ru.json) — материалы дизайна,
не готовая схема API. Например, возврат заявки на доработку — дополнительный процесс.

Общий контракт 0.13.0 выпущен; связи с S1–S6 и серверными обязательными проверками
есть в x-requirements операций. A5 (адаптивность/доступность) проверяется на вебе,
а не отдельным API-маршрутом.
Не поддерживайте независимые несовместимые копии API. После изменений повторяйте
валидацию схем/примеров и генерацию для обоих языков; повышайте версию и обновляйте
зависимые задачи до интеграции.

## Готовый и личный SVG-аватар — DEC-09/10

PublicAccount/NullablePublicAccount используют avatarUrl/null вместо avatarId.
Готовый каталог дополняет загрузку: listAvatarPresets/selectPresetAvatar,
source/presetId в AvatarState; текущий выбор один. PRESET доступен сразу,
CUSTOM требует одобрения; очередь ADMIN только CUSTOM. По DEC-22 общий manifest
содержит реальный `ryadom-companion.svg`. Загрузка и модерация используют DTO
AvatarState/AdminAvatar и expectedRevision. Статус/сырой SVG/приватный preview
не попадают в публичный аккаунт. Личное изображение — только CUSTOM/APPROVED
с текущей revision; готовое — статический URL существующего presetId.
Preview личного SVG владельца/ADMIN проверяет права. Правила —
[аватары](../product/avatars.md), общий лимит SVG 128 КиБ/JSON 1 МиБ.

## Начальный аватар при регистрации — DEC-11

По DEC-12 RegisterInput требует presetId, null/пропуск запрещены. Имя/начальный
PRESET/сессия создаются одним commit, ответ Me уже содержит avatarUrl.
Невалидный ID даёт 422 без частичного создания. Свой SVG не входит в регистрацию,
загружается позже в профиле. Пустой каталог блокирует новую регистрацию до получения реальных SVG.
Права роли/аватара этим DEC-12 не менялись; способ входа позже заменён DEC-20. Процесс — [регистрация](../product/registration.md).

## Сброс сида — DEC-13

adminGetDemoState/adminResetDemoData доступны только ADMIN в DEMO_MODE. Точное
подтверждение, generation/seedVersion и resetId защищают от старой формы/повтора;
десять предметных таблиц возвращаются к сиду одним commit. demo_state сохраняет
новое поколение и квитанцию, все сессии удаляются. Общий барьер транзакций
вводится BE-01/02 до предметных модулей. Правила — [сброс](../product/demo-reset.md).

DEC-20/21, API 0.13.0: [настоящий вход email/пароль и JWT](../architecture/authentication.md)
заменяет демовыбор. [Блокировка USER](../product/account-blocking.md) отзывает все
сессии с сохранением контента. Новые поля Me/PublicAccount/организации и
AdminAccount, три admin-операции; согласованные DTO/примеры в OpenAPI.
