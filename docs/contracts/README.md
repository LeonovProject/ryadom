# Общие контракты

Основание — [первичные источники](../requirements/README.md),
[границы](../product/scope.md) и [приёмка](../product/acceptance.md).
Реализованного API нет; поля и формат схем определяются после выбора стека.

## Границы модели

- Три роли: пользователь, организация/сообщество, администратор. Автор события —
  пользователь либо организация, а не четвёртая роль.
- Организация, заявка на допуск, событие, участие/заявка участника и сообщение —
  связанные, но разные предметные понятия.
- Членство, подписки и несколько управляющих организации не обязательны.
- Допуск, публикация и участие не объединяются в одно поле состояния.
- Свой вид спорта добавляется без изменения кода.
- Событие связано с автором/обсуждением; организация — со своими событиями.
- Сообщение связано с автором/событием; его модерация сохраняет остальные сообщения и событие.

## Обязательные инварианты

1. До допуска организация видит заявку, но не публикует страницу и события от своего имени.
2. Администратор одобряет/отклоняет допуск; причина отказа видна организации.
3. События допущенной организации публикуются без обязательной повторной модерации.
4. Свободная запись сразу подтверждает участие; заявка не подтверждена до принятия автором.
5. Принятие и отказ обновляют обе стороны; администратор не подменяет автора.
6. Открытое обсуждение доступно не только записанным; вопрос задаёт любой пользователь
   платформы. Ограничения для встреч по заявке описываются отдельно.
7. Администратор удаляет событие или снимает с публикации с причиной для автора;
   новая запись запрещена, в том числе по прямой ссылке.
8. Автор и уже записанные понимают недоступность; судьба старых записей — решение команды.
9. Допустима имитация входа, но операции меняют данные и доступные действия.

## Согласование операций

Для каждой операции фиксируются владелец, вход/выход, права, состояния,
ошибки/повторные запросы и последствия для ролей. Согласуйте конкурирующие запросы
и неопределённый результат так, чтобы не создавать дубли участия.
Это правило качества реализации, а не новый балльный критерий.

[states.json](../../brandbook/assets/states.json) и
[copy.ru.json](../../brandbook/assets/copy.ru.json) — материалы дизайна,
не готовая схема API. Например, возврат заявки на доработку — дополнительный процесс.

До разделения веба и сервера выпустите общий контракт со ссылками REQ-* и S1–S6/A1–A6.
Не поддерживайте независимые несовместимые копии одного API в разных приложениях.
