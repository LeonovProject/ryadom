# Аватары и SVG-фоны без файлового хранилища

Дата: 2026-10-19. Пользователь выбрал отказ от S3 и оба способа аватара:
личный SVG с модерацией (DEC-09) и готовый набор (DEC-10). Фон встречи тоже
загружается как SVG. Личные изображения хранятся строками в PostgreSQL; функции пока
не реализованы. DTO и операции закреплены в [API 0.13.0](../contracts/api-v1.md).
Максимальный размер SVG **утверждён по поручению пользователя: 128 КиБ
(131 072 байт), включительно**. Остальные детали реализации сохраняют статус предложения.

## Размер после уточнения охвата

Первичный охват — примерно один город ([DEC-05](../product/decisions.md)).
Пользователь уточнил выбранный предел: **128 КиБ
(131 072 байт), включительно** — [DEC-06](../product/decisions.md).
Это заменяет прежний предел; ограничение обновлено в API 0.13.0 и правилах ниже.
Охват не задаёт число одновременных пользователей; ограничения сложности SVG
проверяются отдельно от размера файла.

Для каталога предлагается отложенная загрузка фонов вне первого экрана и
зарезервированные размеры изображений. Основное изображение первого экрана
загружается сразу. Для img подходит loading=lazy; CSS-фон требует отдельного
управления загрузкой. Основание — [рекомендации web.dev](https://web.dev/articles/browser-level-image-lazy-loading).
Действующее private/no-store сохраняется: сокращение трафика не должно обходить
проверку доступа после снятия публикации.

## Аватары — DEC-09/10

Правила — [личные SVG-аватары](../product/avatars.md). Пользователь загружает
SVG в личном кабинете или выбирает готовый. Одна текущая строка account_avatars
на аккаунт с source=NONE/PRESET/CUSTOM, без архива старых файлов. В accounts
avatar_id нет; готовый ID хранится в account_avatars.preset_id.
По [DEC-11/12](../product/registration.md) готовый вариант обязательно выбирается
сразу при регистрации и сохраняется вместе с аккаунтом/сессией. Пустой каталог
блокирует регистрацию, пропуск запрещён; своя загрузка доступна позднее в профиле.

- EMPTY — заглушка; PENDING — на проверке; APPROVED — публичный SVG;
  HIDDEN — заглушка после решения ADMIN. Новая загрузка всегда PENDING,
  прежний APPROVED до нового одобрения не показывается. При ошибке старый сохранён.
- PRESET — готовый доверенный вариант, сразу APPROVED без новой модерации.
  По DEC-22 общий manifest `packages/contracts/avatar-presets.json` содержит
  `ryadom-companion`; исходник доступен. Он войдёт в веб-образ после
  проверки XML и 128 КиБ. API и веб используют один каталог, ID не переиспользуются.
  Выбор заменяет текущую личную загрузку, сброс очищает любой источник.
- Общие лимиты: 128 КиБ SVG до/после нормализации, 1 МиБ JSON, тот же XML allowlist,
  CSP/nosniff и показ через img. Ошибка 413 не меняет прежний аватар или статус.
- Владелец и ADMIN имеют отдельный приватный предпросмотр. Публичный маршрут
  выдаёт только текущий CUSTOM/APPROVED; готовый вариант — статический URL
  manifest. В PublicAccount только avatarUrl/null, без состояния и сырого SVG.
  Если presetId исключён, avatarUrl=null, в личном кабинете предложен новый выбор.
- ADMIN в SCR-21 одобряет или скрывает без причины, может одобрить HIDDEN заново.
  Владелец заменяет/сбрасывает файл; revision не обнуляется после сброса.
  expectedRevision защищает от решения по уже заменённому изображению.
- URL личных изображений имеют revision. Старая версия, скрытый или неодобренный
  публичный файл дают 404. Это относится к личному SVG: успех/отказ private/no-store,
  proxy не кеширует. Готовый SVG использует неизменяемый статический URL своего ID
  и может кешироваться как ресурс веба; его доступность не зависит от выбора аккаунта.
  Уже показанную/скачанную копию отозвать нельзя; другие клиенты обновляются чтением.

Это аватар человека, в том числе представителя организации. Логотипы организаций,
жалобы на аватары, библиотека файлов и блокировки аккаунта не добавляются.

## Фон встречи

- В `events.cover_svg` (`TEXT`, NULL) хранится проверенная и нормализованная
  UTF-8 строка SVG. Base64, бинарные файлы и отдельная таблица медиа не нужны.
- Максимум — **131 072 байт UTF-8**: исходный `.svg` и строка после декодирования
  JSON проверяются до XML-разбора; нормализованный SVG повторно проверяется перед
  сохранением. Это размер в байтах, не число символов и не длина JSON-обёртки.
  Размер проверяется клиентом, сервером и ограничением `octet_length` в БД.
- Транспортный предел JSON-тела для смены фона — **1 МиБ (1 048 576 байта)**
  на proxy и Go API: он учитывает увеличение строки при JSON-экранировании.
  Это не увеличивает лимит самого SVG. Сжатые загрузки и SVGZ не принимаются.
  Для 131 072 байт даже шестикратное JSON-экранирование строки с обёрткой
  помещается в 1 МиБ; размер самого файла по-прежнему проверяется отдельно.
- Превышение лимита даёт 413 и не меняет прежний фон; файл автоматически не
  обрезается. В форме: «Максимальный размер SVG — 128 КиБ». Дополнительно
  ограничиваются глубина XML, количество элементов и сложность графики;
  эти отдельные пределы ещё определяются до реализации.
- В первой версии фон меняется после создания встречи, из управления ею.
  Создание и запись работают без пользовательского фона; используется штатное
  оформление. При неудачной загрузке сохраняется прежний фон.
- Для загрузки пользователь выбирает `.svg`, клиент читает его как текст;
  сервер повторно проверяет содержимое. Имени файла и клиентскому MIME не доверяют.
- В каталог и карточку API возвращает `coverUrl` либо NULL, а не полный SVG.
  Проверенная строка выдаётся отдельным ответом `image/svg+xml` и используется
  как `<img>` или CSS `background-image`.
- Выдача фона и ответы с отказом имеют `Cache-Control: private, no-store`;
  proxy не кеширует этот маршрут. При каждом запросе проверяется текущий доступ
  к событию. После смены фона клиент повторно загружает изображение, после сброса
  показывает штатный вариант. Уже загруженную пользователем копию отозвать нельзя.
- Пользовательский SVG не вставляется через `innerHTML`/`dangerouslySetInnerHTML`
  и не встраивается через `object`, `embed` или `iframe`. SVG-ответ получает
  `nosniff` и ограничивающую CSP с sandbox; отдельно проверяется прямое открытие URL.

## Проверка SVG

Строковое хранение не делает произвольный SVG доверенным. До сохранения нужен
XML-разбор с разрешённым набором SVG-элементов/атрибутов и повторной сериализацией.
DOCTYPE/сущности, скрипты, обработчики событий, `foreignObject`, анимации,
внешние ссылки/шрифты/изображения и встроенные `data:`-ресурсы не принимаются.
Внутренние ссылки вида `#id` для разрешённых градиентов обрабатываются отдельно;
произвольные CSS/URL не допускаются. Проверка регулярным выражением недостаточна.
Неподдерживаемый файл отклоняется с понятной причиной, без частичного сохранения.

До включения загрузки должны пройти проверки опасных/сложных SVG, прямого
открытия, ошибок и сохранения прежнего фона. Конкретная библиотека проверки ещё
не выбрана. Первоначальное предложение растрировать SVG не принято в этот план:
постоянное хранение и показ используют проверенный SVG, без конвертера изображений.

## Доступ и контейнеры

Фон меняет только автор опубликованного события или ответственный за его
организацию. Администратор без авторства не получает права редактировать фон.
Чтение наследует доступ к событию, включая снятую публикацию; знание URL не
обходит ограничения. Снятие и смена фона согласуются транзакцией над событием.

SVG сохраняется в том же PostgreSQL и переживает перезапуск вместе с событием.
Для этого решения не нужны S3, SDK объектного хранилища, дополнительный том
или файловый сервис. Личные SVG-аватары тоже сохраняются в PostgreSQL; с веб-образом
поставляются заглушка и проверенный готовый каталог (исходник «Спутник» уже есть). Новые поля, модерация и приватность
добавляются в контейнерную приёмку после реализации.

## Порядок реализации и проверка

MEDIA-01 разбита на [отдельные карточки](../development/tasks/media-delivery.md):
MEDIA-00 — общий XML-валидатор до каталога; MEDIA-01A — сервер аватаров и модерация; MEDIA-01D — личный
кабинет; MEDIA-01E — очередь ADMIN. MEDIA-01B повторно использует общий валидатор
для фона, MEDIA-01C добавляет его интерфейс. Схема готовится DB-01, а не отдельной
несогласованной миграцией. После интеграции — повторная приёмка через Compose.
По DEC-22 [стартовые SVG](../../design/assets/README.md) уже доступны: аватар
в manifest и пример фона для загрузки/демонабора. MEDIA-01F проверяет аватар
общим валидатором и подключает его к сборке; выполняется до QA-01,
MEDIA-00 вынесена раньше, вход подготовленными email/паролями и независимая разработка продолжаются.

| Проверка | Ожидаемый результат |
| --- | --- |
| Загрузить аватар, открыть профиль вторым пользователем | До одобрения заглушка; после решения ADMIN виден SVG |
| Скрыть/восстановить аватар; заменить одобренный файл | Скрытый не публичен; восстановленный виден; замена снова PENDING |
| Старый preview URL/старая форма решения после замены | 404 картинки / 409 AVATAR_CHANGED, новое изображение не одобрено старой формой |
| Сбросить аватар, загрузить снова; перезапустить контейнеры | Версия не обнуляется; SVG, решение и текущая версия сохранены |
| Автор загружает допустимый SVG, открывает каталог и карточку | Новый фон виден; строка SVG не включена в списки событий |
| Допустимый SVG ровно 131 072 байт; отдельный пример с многобайтными символами | Ограничение размера пройдено; считаются UTF-8 байты, не символы |
| SVG 131 073 байт или результат нормализации больше 131 072 байт | Ошибка 413, прежний фон сохранён |
| Допустимый по размеру SVG передан с JSON-экранированием, тело не больше 1 МиБ | JSON-обёртка не засчитывается в 128 КиБ SVG |
| JSON-тело больше 1 048 576 байт | Ошибка 413 до обработки SVG |
| Некорректный XML, активное содержимое, внешняя ссылка, превышение лимита | Ошибка без изменения старого фона; неподдерживаемые элементы объяснены пользователю |
| Другой пользователь или администратор без авторства меняет фон | Доступ запрещён; данные не изменены |
| Встреча снята, посторонний открывает сохранённый URL фона | Применяется ограничение доступа встречи, кеш proxy его не обходит |
| Автор сбрасывает фон, затем повторяет сброс | Штатное оформление, без ошибки повторного сброса опубликованной встречи |

Эти проверки ещё не выполнялись: приложения и контейнерной среды нет.

Это улучшения команды, а не обязательные функции официальной постановки.
Обязательные сценарии не должны зависеть от выбора аватара или SVG-фона.
Дизайн-прототип 0.2 пока их не показывает.

Основание технических ограничений: [SVG как изображение, MDN](https://developer.mozilla.org/en-US/docs/Web/SVG/Guides/SVG_as_an_image)
и [проверка загрузок, OWASP](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html).
