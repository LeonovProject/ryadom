# ADR-001: бэкенд на Go и обязательная контейнеризация

Дата: 2026-10-19. Статус: **утверждено по поручению пользователя**.
Пользователь поручил выбрать и утвердить бэкенд, добавить контейнеризацию в
процесс, затем выбрал Go. Это решение заменяет прежнее предложение NestJS/Prisma.
Оно фиксирует технологии и условия готовности; реализация приложения ещё не начата.

## Контекст

Срок сдачи — 20 октября 2026 года в 23:00 по Красноярску (GMT+7), подтверждён
пользователем. Сервер есть; пользователь сам развернёт готовые контейнеры.
Уточнения — [DEC-03/04](../product/decisions.md). Нужны один согласованный API, постоянное хранение и ранняя
интеграция. Состав обязательных сценариев определяется
[первичными документами](../requirements/README.md) и [приёмкой](../product/acceptance.md).

## Принятое решение

| Область | Выбор |
| --- | --- |
| Язык | Go 1.27.2, закреплён и проверен в подготовке BASE-01 / ADR-002 |
| HTTP | Стандартный `net/http`, маршрутизатор chi v5 |
| Архитектура | Одно приложение с предметными модулями: аккаунты, организации, события, участие, обсуждение, модерация |
| База | PostgreSQL 17 с постоянным томом |
| Доступ к данным | pgx v5 и генерируемые sqlc типы/запросы; SQL хранится в репозитории |
| Миграции | Версионируемые SQL-миграции goose, один владелец схемы |
| API | REST/JSON, префикс `/api/v1`, единая спецификация OpenAPI 3.0.3 |
| Генерация контрактов | oapi-codegen для Go; openapi-typescript и openapi-fetch для веб-клиента |
| Проверки сервера | Стандартные `testing`/`httptest`, интеграционные проверки с PostgreSQL |
| Логи | Стандартный `log/slog`, идентификатор запроса |
| Контейнеры | Docker и Docker Compose v2 с первого этапа реализации |
| Веб-вход | Nginx: статическая сборка React и proxy к API на одном origin |

Контракт OpenAPI является единственным источником транспортных типов для Go и
TypeScript. Предметные правила и права проверяет сервер. Сгенерированные типы
не заменяют проверку входных данных и не определяют права пользователя.
По следующему поручению DTO/права/переходы зафиксированы в
[API 0.13.0](../contracts/api-v1.md). [Физическая модель данных](data-model.md)
остаётся проектом SQL-схемы, миграций ещё нет.

Go 1.27 — поддерживаемая ветка на дату решения; PostgreSQL 17 также поддерживается.
Точные версии библиотек, генераторов и образов закреплены координатором
в BASE-01 по [ADR-002](foundation-decision.md): есть `go.mod`/`go.sum`,
lock-файл веба и базовые образы с digest. Проверочный Compose ещё не является
продуктовой средой: HTTP-контур/миграции/постоянный том готовятся в OPS-01.

## Почему этот вариант

Go соответствует прямому выбору пользователя. chi сохраняет стандартную модель
HTTP-обработчиков; pgx/sqlc оставляют ограничения и транзакции в явном SQL.
Разделение по предметным модулям позволяет назначить владельцев без разнесения
обязательных сценариев по отдельным сервисам. OpenAPI связывает Go и React,
поэтому общий TypeScript-серверный пакет больше не требуется.

Цена решения — генерация типов на двух языках и явные SQL-запросы. До распределения
предметных бизнес-модулей нужно проверить один маршрут целиком: OpenAPI → Go → PostgreSQL → веб-клиент.
Это условие первого этапа, а не подтверждённая работоспособность связки.
Спецификация, примеры и Go/TypeScript-генерация уже проверены отдельно —
[отчёт](../contracts/validation.md). Это не проверка контейнерного маршрута с БД.

## Аватары и фоны без S3

По последующим DEC-09/10 **S3 исключён**. Аватар выбирается из готового набора
либо загружается пользователем с модерацией. Текущий выбор хранится в отдельной
account_avatars: source/preset_id для готового или TEXT SVG для личного;
accounts.avatar_id не используется. Готовые файлы входят в сборку, личные — в БД.
SVG-фон встречи сохраняется строкой `TEXT` в PostgreSQL после серверной проверки.
Утверждён максимум **128 КиБ (131 072 байт)** для исходного и нормализованного SVG.
Отдельный файловый том, SDK объектного хранилища и конвертер изображений не нужны.
Подробности, ограничения и предлагаемые поля — [медиа без S3](media.md).
По DEC-12 готовый аватар обязателен при регистрации: хотя бы один предоставленный
SVG и MEDIA-01F нужны до её приёмки. Личная загрузка/модерация и фон выполняются
после проверки основного контура; регистрация не зависит от их готовности.

## Границы и процесс

- [Контейнеризация](../development/containerization.md) обязательна для разработки
  и сдачи по решению команды; это не дополнительное требование официального PDF.
- Локальная интеграция и итоговая приёмка проходят в Compose; отдельно запускать
  веб/API для отладки можно, если поддерживается контейнерный путь.
- Бизнес-правила, интерфейсы и дополнительные функции не утверждаются этим ADR
  автоматически. Утверждение технологий не запускает разработку продукта.
- Развёртывание, создание внешних ресурсов, коммит и push в это поручение не входят.
