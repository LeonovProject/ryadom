# Покрытие дизайн-прототипа 0.2

Актуальное уточнение DEC-20/21: карта приложения содержит 21 URL, включая
SCR-22 /admin/accounts. Вход email/паролем и блокировка описаны в спецификациях;
локальный макет 0.2 сохраняет старый демовыбор и 18 маршрутов, не показывает
JWT/реальную регистрацию/блокировку. Код макета не изменён.

Дата: 2026-10-19. Основание — [карта экранов](../../docs/product/screens.md),
[пути](../../docs/product/user-flows.md) и [приёмка](../../docs/product/acceptance.md).
Ниже отмечено наличие экранов и локальных взаимодействий, а не готовность
приложения. Все изменения происходят в памяти одной вкладки и исчезают при перезагрузке.

Последующее [решение по SVG-аватарам и фонам](../../docs/architecture/media.md)
ещё не отражено в макете 0.2. Загрузка, проверка и модерация аватара/фона здесь
не выполняются; SCR-21 существует только в проекте приложения.
Готовый выбор DEC-10 и его пустой каталог тоже описаны только в документации;
реальные SVG пользователь предоставит позже.
Выбор готовой аватарки непосредственно при регистрации по DEC-11 описан в
спецификации приложения; SCR-07 макета 0.2 по-прежнему не реализует этот выбор.

## Данные для просмотра

| Демопрофиль | Возможности |
| --- | --- |
| Алексей Миронов | Найти встречу, присоединиться/подать заявку, задать вопрос, создать личную встречу или свою организацию |
| Анна Лебедева | Автор исходных встреч, ответственный всех исходных организаций; рассмотреть заявки участников |
| Марина Соколова | Администратор: поиск, допуск организаций, снятие встреч и скрытие сообщений |

У Анны есть «Темп» с допуском, две ожидающие организации «Ход» и «Пульс»,
«Дворовые встречи» без поданной заявки и «Высота» с отказом и причиной.
Можно независимо показать обе ветки решения без возврата уже рассмотренной заявки.

## Связные пути для обсуждения

1. **Организация с нуля:** Анна → мои организации → создать профиль → сохранить →
   отправить на проверку. Переключиться на Марину → найти организацию →
   предоставить допуск. Переключиться на Анну → тот же кабинет → создать встречу
   от организации → опубликовать. Алексей видит публичный профиль и встречу.
2. **Отказ:** Марина → «Пульс» → отклонить с причиной. Анна открывает «Пульс»:
   причина видна, публичной страницы и публикации нет. Повторная подача не обещается.
3. **Участие:** Алексей подаёт заявку на теннис. Анна рассматривает её через
   «Участники и заявки». Алексей видит результат во встрече и своих заявках.
   Для свободной записи подходит пробежка; отдельное решение не требуется.
4. **Одно сообщение:** Марина → модерация тенниса → скрыть сообщение Елены.
   В диалоге видны автор и фрагмент текста. Алексей видит заглушку и оставшийся
   ответ Анны; сама встреча остаётся доступной. В модерации оригинал можно раскрыть.
5. **Снятие:** предварительно записать Алексея на теннис; Марина снимает встречу
   с причиной. Анна видит причину; Алексей — недоступность публикации и прежнюю
   запись без новых действий. Гость по прямой ссылке получает «Страница не найдена».
   Каталог и публичная организация больше не предлагают эту встречу.
6. **Приватность:** Алексей не открывает чужой кабинет или административный раздел.
   Марина не получает право решать заявки участников чужой встречи.

Для смены человека используйте «Профиль → Сменить демопрофиль», сохраняя набор
данных вкладки. «Сбросить» возвращает весь набор к исходному состоянию;
перезагрузка делает то же самое. Это не работа между независимыми сессиями.

## Что ещё не покрыто

- Реальные запросы, хранение, серверные права, независимые пользователи и техническая
  приёмка S1–S6/A1–A6. Имитация DOM не подтверждает эти свойства.
- Состояния отправки, сетевого сбоя и неизвестного результата для всех форм;
  истечение сессии, конкурентное изменение данных и восстановление после сбоя.
  Проверка обязательной причины и устаревшего решения в локальном диалоге есть.
- Загрузка/ошибка каталога и кабинетных списков, дальнейшая загрузка и пагинация.
- Восстановление позиции прокрутки каталога. Параметры выдачи сохраняются в памяти
  вкладки; при перезагрузке контекст прежней выдачи не обещается.
- Предупреждение при навигации кнопками истории браузера. Внутренние ссылки,
  переключатель экранов и перезагрузка предупреждают о заполненной форме;
  при переходах истории заполнение пока остаётся в памяти до явного сброса/смены профиля.
- Новый экран SCR-20 модерации направлений и правила DEC-07: в API 0.9.0 они
  описаны, макет 0.2 их пока не реализует. Его 18 маршрутов — исходное покрытие.
- Жалобы на встречи/сообщения, их разбор и восстановление скрытого текста по
  [DEC-08](../../docs/product/reports-and-moderation.md) описаны для приложения,
  но в макет 0.2 не добавлены. Будут использовать существующие SCR-03/17/18.
- Редактирование профилей/встреч, отмена записи, повторная подача организации,
  восстановление публикации, внешние уведомления и календарь. Это расширения.
- Реализация принятого [правила DEC-01/02](../../docs/product/decisions.md):
  начало закрывает запись/решения, время показывается в зоне встречи с подписью.
  Решение принято для приложения/API 0.2.0; макет пока не вводит запрет по времени.
- Масштаб текста, экранная клавиатура, физические устройства, другие браузеры
  и полный аудит доступности/клавиатуры. Встроенный браузер в последующей
  попытке заработал: [визуальный проход](../reviews/2026-10-19/README.md)
  проверил все 18 экранов на 1280/390 px и ключевые страницы на 320/768 px.
  Это не означает проверки всех состояний на каждой ширине.

## Локальная проверка переходов

При наличии Node.js:

```bash
node scripts/check_prototype.cjs
```

Запускать из корня репозитория. Используются только встроенные модули Node;
зависимости устанавливать не нужно. Скрипт проверяет отрисовку маршрутов и
последовательности действий с имитацией DOM: фильтры, вход/регистрацию, создание,
заявки, допуск/отказ, поиск администратора, скрытие сообщения, снятие и доступы.
Это проверка локального макета; движок браузера, CSS и сеть в ней не участвуют.

DEC-12/13 описаны для будущего приложения: готовый аватар обязателен при
регистрации, в аккаунте ADMIN есть атомарный сброс к сиду. Макет 0.2 этого
не реализует и не сбрасывает настоящую БД. Каталог пока пуст — нужны файлы
пользователя, обязательность регистрации не обходится вымышленными ресурсами.


DEC-14–16 относятся к будущему приложению/API 0.11.0: личная главная, предстоящие
по умолчанию и начавшиеся отдельно, переход после входа/регистрации в / без returnTo.
Макет 0.2 эти изменения ещё не показывает; пользователь остановил его обновление.
Его прежние переходы/порядок не являются источником актуального поведения приложения.

DEC-18/19 (API 0.12.0) — последние сообщения с загрузкой ранних и календарный
фильтр в зоне каждой встречи — описаны для приложения. Текущий макет не является
их реализацией; примерные пресеты/пагинация макета не заменяют новый контракт.
