внешних файлов. Это исходные SVG для продукта, отдельно от брендбука и
остановленного HTML-макета. Приложения и контейнерной сборки ещё нет.

| Аватар «Спутник» | [ryadom-companion.svg](../../packages/contracts/avatar-presets/ryadom-companion.svg) | 256 × 256 | Первый готовый выбор при регистрации и в профиле |
| Фон «Точка встречи» | [ryadom-meeting-point.svg](event-covers/ryadom-meeting-point.svg) | 1600 × 900, 16:9 | Пример загрузки фона встречи и материал демонабора |

Оба рисунка созданы для проекта, не требуют внешних ресурсов, шрифтов или
подписок. Цвета взяты из [tokens.json](../../brandbook/assets/tokens.json):
красный, белый, светлый красный и почти чёрный; у фона небольшой синий акцент.
Используются только svg/rect/circle/path и простые атрибуты оформления,
без скриптов, CSS, ссылок, анимации и встроенных растровых изображений.
Каждый файл меньше 2 КиБ при разрешённых 128 КиБ.

## Как подключать при реализации

- **Аватар:** уже включён в общий [manifest](../../packages/contracts/avatar-presets.json)
  как `ryadom-companion`, label «Спутник». Целевой URL —
  `/assets/avatars/presets/ryadom-companion.svg`. API/веб используют один manifest,
  веб-образ включает исходник как статику. Порядок — [README каталога](../../packages/contracts/avatar-presets/README.md).
  Даже при одном варианте пользователь явно выбирает его: автоматического
  заполнения обязательного `presetId` при регистрации нет.
- **Фон:** в MEDIA-01B/C этот файл можно выбрать для обычной загрузки: содержимое
  передаётся строкой `CoverInput.svg` и сохраняется в `events.cover_svg` после
  серверной проверки. Имя файла и путь не сохраняются вместо SVG. Для демонстрации
  MEDIA-01B согласует с владельцем DB-02 включение проверенной строки в штатный
  seed. Пока валидатор не готов, базовый seed вправе оставлять `cover_svg=NULL`.
  Нового каталога фонов, эндпоинта или обязательного поля создания встречи нет.

Показывать через `img`, не вставлять SVG-разметку в страницу. Аватар подходит
для квадратного или круглого контейнера. Фон декоративный: `object-fit: cover`,
для карточек рекомендуется `object-position: 65% 50%`; на узком экране допустимо
кадрирование. Название, дата, адрес и кнопки находятся в отдельных читаемых
блоках, а не зависят от цвета картинки. Декоративному фону — `alt=""`, аватару
в сетке выбора — доступное имя «Спутник», отдельно от названия аккаунта.

## Проверка и границы готовности

Проверены UTF-8, размер, разбор XML, простой набор элементов/атрибутов,
соответствие цветов токенам и визуальный рендер. Аватар просмотрен в 32/48/96/256 px,
фон — целиком и в кадрировании карточки. Проверка manifest:

```bash
python3 scripts/check_api_contract.py
```

Команда запускается из корня в окружении с `scripts/requirements-contracts.txt`.
Статическая проверка этих двух исходников не заменяет будущий общий XML-валидатор
MEDIA-00 для произвольных загрузок. MEDIA-01F остаётся задачей интеграции:
проверка общим валидатором, публикация из веб-образа и реальная регистрация
ещё предстоят. Зависимость от получения стартовых изображений уже снята.
