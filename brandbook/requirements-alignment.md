# Связь брендбука 1.2 с требованиями

Первичные источники — [постановка и критерии](../docs/requirements/README.md).
В версии 1.2 продуктовые тексты и макеты обновлены по этим документам.
Брендбук задаёт оформление; примеры интерфейсов не подтверждают наличие реализации.

| Раздел брендбука | Правило реализации по первичным источникам |
| --- | --- |
| Универсальность | Обязательны разные спортивные направления и разный опыт. Неспортивные примеры — развитие команды |
| Роли | Три роли: пользователь, организация/сообщество, администратор. Организатор — автор, не отдельная роль |
| Категории | Нужен свой вид спорта без изменения кода, кроме готового списка |
| Создание и допуск | Пользователь публикует от себя. До допуска страница организации не публична и события от её имени не публикуются; после допуска нет обязательного повторного согласования |
| Решения | Причина отказа организации обязательна. Возврат на доработку — дополнительная функция |
| Участие | Оба режима обязательны; ожидание не является подтверждением; решение принимает автор, обе стороны видят результат |
| Карточка | Обязательны организатор со ссылкой, время, место, условия, режим. Вместимость — дополнительная возможность |
| Обсуждение | Внутри события обязательно; внешний чат не заменяет. Для открытого события вопрос доступен любому пользователю платформы |
| Модерация события | Основной сценарий выполняет администратор с причиной для автора. Достаточно одной из двух операций: удаление или снятие с публикации |
| Недоступная публикация | Запись запрещена и по прямой ссылке; организатор и записанные понимают недоступность. Судьба старых записей — решение команды |
| Административный контур | Обязательны поиск, связанные переходы и модерация одного сообщения с сохранением остального обсуждения |
| Мобильное приложение | Идея команды; нативное приложение не приносит дополнительных баллов, оценивается адаптивный веб |
| Демонстрация | Показать вход/регистрацию обязательно; авторизацию можно имитировать. Бизнес-операции должны менять данные |

Актуальные [границы](../docs/product/scope.md) и [приёмка](../docs/product/acceptance.md)
определяют состав реализации. Поля вместимости и стоимости в примерах, черновики,
возврат организации на доработку и уведомления — дополнительные решения.
Сохранённая версия 1.0 — исторический материал оформления, а не спецификация.
