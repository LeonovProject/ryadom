# Брендбук Рядом

Версия **1.2**, 17 страниц. Включает визуальную и вербальную систему, три роли,
статусы, шесть сценариев и мобильное приложение как идею команды.
Продуктовые формулировки и макеты согласованы с [первичными PDF](../docs/requirements/README.md).
[Связь с требованиями](requirements-alignment.md) отделяет обязательный минимум от примеров развития.

## Воспроизведение сборки

Нужны Python 3.10+, зависимости из `source/requirements.txt` и статические
начертания Open Sans Regular/Bold и Montserrat Regular/Bold с кириллицей.
Шрифты не включены в репозиторий; ссылки на официальные источники и лицензии
находятся в `assets/README.md`.

В обычной среде установите зависимости в отдельное виртуальное окружение:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r brandbook/source/requirements.txt
.venv/bin/python brandbook/source/build_brandbook.py --output-dir .artifacts/brandbook
```

На Linux установленные шрифты находятся через Fontconfig. На других системах
или без Fontconfig укажите каталог файлов:

```bash
python3 brandbook/source/build_brandbook.py --fonts-dir /path/to/fonts --output-dir .artifacts/brandbook
```

Ожидаются файлы `OpenSans-Regular`, `OpenSans-Bold`, `Montserrat-Regular` и
`Montserrat-Bold` с расширением `.ttf` либо `.otf`. Флаг `--work-dir` позволяет
назначить каталог промежуточных изображений; по умолчанию используется отдельный
временный каталог. Без `--output-dir` сборка обновляет `brandbook/`.

В среде Codex для документов используйте предоставленный runtime и навык
документов; не подменяйте их системной установкой. Пути runtime не хранятся
в исходнике проекта.

## Экспорт и проверка

Сборщик создаёт DOCX, материалы в `assets/` и ZIP. PDF экспортируется отдельно
из полученного DOCX средствами Word, LibreOffice либо рендера навыка документов.
Для точного рендера шрифты должны быть доступны и редактору/конвертеру;
`--fonts-dir` сам по себе их в систему не устанавливает.

1. Сначала соберите в `.artifacts/brandbook`, чтобы не перезаписать рабочие материалы.
2. Экспортируйте PDF, отрендерите страницы и просмотрите каждую.
3. Проверьте переносы, таблицы, шрифты и соответствие макетов тексту.
4. Перенесите согласованные документы и данные в `brandbook/` одним изменением.
5. Запустите `python3 scripts/check_repository.py` и `git diff --check`.

Не объединяйте параллельные правки DOCX/PDF. Исходник и финальные материалы
обновляет один назначенный исполнитель. Прямые правки Word нужно перенести
в исходник до следующей генерации, иначе сборка их перезапишет.

с `tokens.json`, CSS, TypeScript и ZIP.
