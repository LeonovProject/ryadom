# Общий API-контракт

Владелец этой области — координатор интеграции. При работе над отдельным веб-
или серверным модулем не меняйте спецификацию попутно; передайте необходимую
правку координатору до интеграции.

- Источник транспортных данных — `openapi.yaml`, текущая версия 0.13.0.
  Семантика — `../../docs/contracts/api-v1.md`; первичные PDF сохраняют приоритет.
- Согласованно меняйте required/nullable, ответы, статусы, права, повторы,
  `x-error-codes`, примеры и версию. Обновляйте зависимые задачи.
- Общий JSON/SQL-тип нельзя независимо переопределять на фронтенде и бэкенде.
  Типы pgx/sqlc не являются публичными DTO.
- DEC-09: avatarUrl вместо avatarId; listAvatars/setAvatar исключены. Свой SVG
  сначала PENDING, публично только APPROVED, до проверки/после HIDDEN заглушка.
  revision не обнуляется после сброса; старое решение/URL не применяются к новому
  файлу. Preview владельца/ADMIN приватный. Для аватара и фона SVG <=131072 UTF-8
  байт, JSON <=1048576; общий XML allowlist. Правила — `../../docs/product/avatars.md`.
- DEC-10 дополняет загрузку готовым выбором: listAvatarPresets/selectPresetAvatar,
  source/presetId в AvatarState. PRESET сразу доступен, очередь ADMIN только CUSTOM.
  DEC-22: в avatar-presets.json есть реальный ryadom-companion.svg. Проверяйте
  manifest, файлы и включение в одну сборку; произвольные URL не принимаются.
  Смена на PRESET очищает личный SVG; следующая загрузка опять PENDING. Удалённый
  из manifest ID остаётся в БД, но публично заглушка. ID не переиспользуются.
- DEC-11: RegisterInput.presetId обязательный, не nullable. Один commit создаёт
  USER/аватар/сессию, Cookie после него; 201 Me уже содержит avatarUrl. Отсутствие/
  null отклоняются, допустимый ID — PRESET/APPROVED/1. Неверный ID даёт 422
  без частичного создания. Свой SVG/URL/роль не принимаются регистрацией. BE-02
  владеет listAvatarPresets и общим читателем manifest; MEDIA-01A использует их повторно.
- DEC-13: adminGetDemoState/adminResetDemoData только ADMIN+DEMO_MODE. Сид и
  квитанция/demo_state обновляются атомарно; при ошибке откат, после commit
  все сессии удалены и cookie очищена. Старая generation/resetId не повторяют
  удаление. Все предметные/сессионные транзакции используют общий барьер прежде
  других блокировок и проверяют актуальные права после ожидания. Правила —
  `../../docs/product/demo-reset.md`. Примеры не запускать против общей среды.
- DEC-07: listActivityTypes только APPROVED, но имя/ID PENDING и REJECTED разрешены
  во встречах. Не создавайте повторную проверку при совпадении имени. ADMIN-only
  решение/исправление, expectedName и коллизии задаются контрактом. Метаинформация
  activityTypeReview — только автору опубликованной встречи, другим null. Слияния нет.
- DEC-14: listMyParticipations с eventWindow — PUBLISHED, окна UPCOMING/STARTED_TODAY
  и startsAt/event.id ASC до LIMIT; referenceTime обязателен в странице, null без
  окна. Один момент для обоих блоков и курсоров, сегодня в зоне встречи. Без окна
  прежний полный список/UNPUBLISHED/createdAt DESC. Опорный момент чтения не
  подменяет актуальный now при мутациях. Новых таблиц/маршрутов нет.
- DEC-15: STARTED — третье окно listMyParticipations: PUBLISHED, startsAt <=
  referenceTime, все дни, event.startsAt/id DESC. UPCOMING/STARTED_TODAY остаются
  ASC. Клиентский default «Участвую» — UPCOMING, недоступные записи — в режиме
  без окна; сортировку/фильтры нельзя выполнять после LIMIT. DEC-16 меняет только
  навигацию после входа на / при отсутствии returnTo, ответы auth прежние.
- DEC-18: listMessages.order=NEWEST_FIRST — DESC и курсор к ранним; default
  OLDEST_FIRST остаётся ASC, adminListMessages не получает новый параметр.
  DEC-19: listEvents.dateFrom/dateTo — date в зоне каждого события, границы
  включительно/исключительно; AND с from/to до LIMIT, все фильтры в курсоре.
  Не добавлять копию локальной даты в таблицу и не сортировать первую старую
  страницу, выдавая её за свежие сообщения. У примеров уникальны ID строк,
  одноимённые OpenAPI/JSON-примеры совпадают; это проверяет общий скрипт.
- При now >= startsAt запись и решения дают EVENT_STARTED после проверок доступа
  и публикации, до повтора. canManageParticipants означает чтение состава;
  отдельный canDecideParticipations — право решать до начала. Правила и границы —
  `../../docs/product/decisions.md`. Не меняйте статусы участия из-за начала.
- Скрытое сообщение не содержит body на публичном маршруте. Ограниченные
  карточки/сводки не содержат закрытых полей. ADMIN не заменяет автора встречи.
- DEC-08: жалобы на встречи/сообщения без причины и автоматического скрытия.
  hide/restore — expectedRevision; разбор жалоб — expectedReportsRevision.
  Старый запрос не отменяет новое решение. Прямые жалобы и сообщения независимы;
  восстановление текста не восстанавливает публикацию. Следуйте спецификации
  `../../docs/product/reports-and-moderation.md`; обязательная причина снятия остаётся.
- Запускайте проверку спецификации/примеров через `scripts/check_api_contract.py`
  из корня в окружении с `scripts/requirements-contracts.txt`; порядок в README.
- Для изменения схем проверяйте генерацию для Go и TypeScript, не редактируйте
  производные вручную. Инструменты закреплены в `tooling.json`.
- Примеры — статические фикстуры, не seed и не работающий сервер. Их валидация
  не подтверждает реальные права, XML-безопасность, транзакции или приёмку продукта.

- DEC-20/21: login/register с email/паролем заменяют demo-маршруты. JWT-cookie
  требует актуальной sessions/ACTIVE в БД, блокировка отзывает все сессии.
  AdminAccount/AccountStatusInput и три admin-операции используют expectedRevision.
  PublicAccount.isBlocked и ownerIsBlocked у организации не меняют публикацию.
  Email только Me/ADMIN, пароль/хеш/токен не в ответах. AUTH-01/BE-02/BE-13/FE-15
  должны следовать спецификации входа, включая транзакционный порядок замков.
