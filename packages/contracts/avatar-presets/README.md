# Исходники готовых SVG-аватаров

По поручению пользователя (DEC-22) подготовлен один реальный аватар:
[ryadom-companion.svg](ryadom-companion.svg), label **«Спутник»**, холст 256 × 256.
Он уже включён в [общий manifest](../avatar-presets.json) с ID `ryadom-companion`
и целевым URL `/assets/avatars/presets/ryadom-companion.svg`.
[Фон и правила использования стартового набора](../../../design/assets/README.md).
Ожидание изображений от пользователя снято. Даже один вариант выбирается явно
при регистрации; автоматического выбора обязательного `presetId` нет.

## Оставшаяся интеграция MEDIA-01F

1. Проверить SVG общим XML-валидатором MEDIA-00: максимум 128 КиБ UTF-8
   до и после нормализации. Статическая проверка исходника уже выполнена,
   но не заменяет будущий серверный валидатор произвольных загрузок.
2. Проверить manifest, наличие файлов, UTF-8 и размер через
   `python3 scripts/check_api_contract.py` из корня в окружении зависимостей контракта.
3. Включить один manifest в API и веб; веб-образ публикует перечисленные SVG
   по точным `imageUrl` как изображения, без вставки XML в DOM.
4. Проверить реальную регистрацию с явным выбором, показ во второй сессии,
   пустой каталог и неизвестный ID. Наличие файла ещё не закрывает эту приёмку.
   Замена своего SVG и повторы проверяются в MEDIA-01A/D.

Новые файлы добавляются с неизменяемым ID: маленькие латинские буквы, цифры
и дефисы, максимум 64 символа. Имя `<id>.svg`, URL
`/assets/avatars/presets/<id>.svg`; порядок items задаёт порядок выбора.
ID не переиспользуется для другого изображения, включая замену стартового.
Позднее можно добавить другие предоставленные пользователем рисунки с новыми ID.

DEC-12 сохраняется: пустой каталог блокирует новую регистрацию. Файл и запись
manifest уже есть, но обработчики, контейнерная сборка и XML-валидатор ещё
не реализованы. MEDIA-01F остаётся зависимостью QA-01.
